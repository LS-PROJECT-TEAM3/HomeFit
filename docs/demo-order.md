# 시연 순서

- 상태: **초안 v0.1** (팀 확인 전) [확인 필요: 안내서가 파일 이름을 정하는지, 안내서는 저장소에 없음. 이름이 다르면 README에서 연결한다]
- 날짜: 2026-11-18, 조각 C2, 평가 항목 P3-34(서비스 배포·시연), P3-06, P3-08
- 근거: `docs/journeys/critical/CUJ-04-관리자-시연.md`, `docs/specs/005-관리자-시연-기록찾기/spec.md`·`qa.md`, 화면 코드(`app/(main)/admin/`), `watch/sim-fixtures.ts`·`weather-fixtures.ts`·`rent-fixtures.ts`
- 이 문서에 적은 화면 이름과 묶음 이름은 코드에서 확인했다. **운영 배포에서 처음부터 끝까지 돌려 본 기록은 없다**(5절).

## 1. 한눈에

한 줄: 관리자가 가짜 자료를 넣으면 수집 → 사건 → 알림이 생기고, 사용자가 승인해야 일정에 들어가며, 흐름 화면과 채점이 그것을 숫자와 그림으로 보여 준다.

| 장면 | 화면 | 청중이 보는 것 | 평가 항목 |
|---|---|---|---|
| 1 | 관리자 > 수집 현황·오류 | 정기 수집이 쌓이는 모습, 연속 실패 수 | P3-17 |
| 2 | 관리자 > 시뮬레이터 | 가짜 공고를 넣고 한 번에 돌림 | P3-06 |
| 3 | 관리자 > 흐름 화면 | 방금 돈 실행이 상자·화살표로 그려짐 | P3-08 |
| 4 | 사용자 화면 (가상 계정) | 알림 → 승인 → 내 일정. 관리자는 대신 승인 못 함 | P3-04 |
| 5 | 관리자 > 시뮬레이터 (실패 묶음) | 읽기 실패는 "변화 없음"이 아니라 수집 오류 | P3-02, P3-08 |
| 6 | 관리자 > 시뮬레이터 (예보·시세) | 사건 종류가 둘 이상 | P3-03 |
| 7 | 관리자 > 채점 결과 | 맞힌·놓친·잘못 울린 수 | P3-06 |
| 8 | 기록 찾기 | 끝난 알림을 찾고, 출처와 함께 답함 | P3-05 |

시연 길이는 리허설로 정한다 [확인 필요]. 시간이 모자라면 장면 6과 8을 줄이고, 2·3·4·5·7은 지킨다(CUJ-04의 핵심 순간이 2·3이다).

## 2. 시연 전 준비 (리허설 때 꼭 확인)

1. **접속**: 서비스 주소 https://homefit-lac.vercel.app (로그인해야 화면이 보인다). 관리자 계정과 가상(시험) 계정으로 각각 로그인한 창 둘을 미리 열어 둔다. 로그인 정보는 팀 비공개 채널에만 두고 이 문서와 슬라이드에는 쓰지 않는다.
2. **운영에 `SIMULATION_USER_IDS`가 들어 있는지 확인한다.** 없으면 시뮬레이터가 "대상 0곳"으로 돈다(qa 008 실패와 조치 3). qa에는 2026-11-18 조치 후 통과로 적혀 있지만 발표 직전에 다시 확인한다 [확인 필요].
3. **같은 묶음은 알림을 두 번 만들지 않는다**(spec 005 E3). 가상 계정에 이미 같은 알림이 있으면 "새 알림 0건"으로 나와 아무 일도 안 일어난 것처럼 보인다. 시연 전에 가상 계정의 열린 알림을 확인하고, 이미 있으면 다른 묶음(예: `changed` 대신 `correction`)을 쓴다. 알림을 지워서 비우는 방법은 데이터를 지우는 일이라 팀이 정한다 [확인 필요].
4. **AI 요약**: 운영의 `AI_PROVIDER`와 키가 설정돼 있어야 요약이 나온다. 없어도 기본 체크리스트와 승인·거절 버튼은 나온다(qa 001 C-032). 어느 쪽으로 보여 줄지 정한다 [확인 필요].
5. **끝난 알림이 있는 계정**: 장면 8(기록 찾기)은 승인·거절로 끝난 알림이 있어야 보인다. 장면 4에서 만든 것을 쓴다.
6. **슬랙 DM**(선택): 보여 주려면 가상 계정에서 알림을 미리 켜 둔다(qa 001 H-005에서 실제 DM 확인).

## 3. 순서

### 장면 1. 수집 현황 — 정기 수집이 쌓이고 있다
- 화면: 관리자 메뉴 > **수집 현황·오류** (`/admin/watch`)
- 한다: 출처별 마지막 실행과 **연속 실패 횟수**를 보여 준다. 기상청 같은 출처의 **"지금 한 번 실행"**을 눌러 기록이 한 줄 늘어나는 것을 보여 준다.
- 말한다: "정해진 시각에 저절로 수집하고, 실패하면 여기서 연속 실패가 보입니다."
- 근거: spec 005 FR-001, qa 005 C-501. 정기 실행 시각은 `vercel.json`(UTC 설정을 한국 시각으로 바꾸면 09:00·09:10·05:30·17:30, 매월 2일 10:00).

### 장면 2. 시뮬레이터 — 가짜 공고를 넣는다
- 화면: **시뮬레이터** (`/admin/sim`) > "마이홈 가짜 공고"
- 한다: 묶음 **`changed`**를 고르고 실행한다. 결과 요약(성공, 읽은 공고 수, 새 알림 수)과 **흐름 화면 링크**를 보여 준다.
- 말한다: "실제 공고를 기다리지 않고, 정답이 붙은 가짜 묶음으로 같은 경로를 돌립니다. 알림은 가상 계정에게만 생기고 실제 계정에는 생기지 않습니다."
- 주의 1: 준비 3번(같은 묶음 두 번 → 새 알림 0건).
- 주의 2: `changed`가 무엇을 바꾸는지 화면과 코드가 다르게 적혀 있다. 시뮬레이터 화면 문구는 "마감일·월세가 바뀜 → 알림"(`app/(main)/admin/sim/page.tsx`)인데, 코드 주석(`watch/sim-fixtures.ts`)은 "sample과 같은데 마감일이 하루 늦음"만 적혀 있다. 월세도 바뀌는지 [확인 필요]. 리허설에서 알림 상세의 "무엇이 바뀌었나"를 보고, 확인되기 전에는 발표에서 "마감일이 바뀝니다"까지만 말한다.
- 근거: CUJ-04 1단계, spec 005 FR-002, qa 005 C-502.

### 장면 3. 흐름 화면 — 실제로 돈 기록이다
- 화면: **흐름 화면** (`/admin/flow`)
- 한다: 방금 실행을 고른다. 시작 상자 3종(마이홈 공고, 기상청 예보, 실거래가), 단계 상자와 화살표, 상태 글자(성공·실패·승인 대기·건너뜀), 들어온·나간 건수를 보여 준다. **상자 하나를 열어** 입력·출력 건수와 상세를 보여 준다. 기록이 없는 출처는 "아직 안 켜짐"(회색)이다.
- 말한다: "미리 그린 그림이 아니라 실행 기록(runs, run_steps)에서 그립니다. 상세에는 비밀 키가 가려져 있습니다."
- 근거: CUJ-04 2·3단계(핵심 순간), spec 005 FR-003, qa 005 C-504.

### 장면 4. 사용자 쪽 — 승인해야 일정에 들어간다
- 화면: 가상 계정으로 로그인한 창 > 홈, **사건 상세**, **내 일정**
- 한다: 새 알림 > 상세의 "무엇이 바뀌었나", 요약과 계획 초안(체크리스트) > **승인** > 내 일정에 체크리스트와 마감일이 들어간다. 같은 시점에 관리자 쪽 **사건 현황**(`/admin/incidents`)과 **회원**(`/admin/users`)에는 **승인 버튼이 없는 것**을 보여 준다.
- 말한다: "사람이 승인하기 전에는 아무것도 바뀌지 않고, 관리자도 대신 승인하지 못합니다."
- 근거: CUJ-04 4단계, spec 005 FR-005, qa 001 H-007.

### 장면 5. 실패 장면 — 읽기 실패는 수집 오류다
- 화면: **시뮬레이터** > 묶음 **`failure`**(API 실패) 또는 **`malformed`**(모양이 깨진 응답) 실행 > **흐름 화면** > **수집 현황·오류**
- 한다: 실행 요약이 실패로 나오고, 흐름 화면에서 실패 상자가 보이며 그 뒤 단계에는 도달하지 못한 것을 보여 준다. 수집 현황의 연속 실패 수가 늘어난다. 상세의 오류 문구에서 키 값이 가려져 있는 것도 보여 준다.
- 말한다: "읽기에 실패하면 '변화 없음'으로 두지 않고 수집 오류로 기록합니다."
- 근거: CUJ-04 2단계 인사이트("실패 장면도 시연에 넣는다"), qa 001 C-017. 실패 처리 설명은 `docs/data-sources.md` 4절(조각 C1, PR #5가 합쳐진 뒤 링크를 잇는다).

### 장면 6. 사건 종류를 늘린다 — 습도·결로, 시세
- 화면: **시뮬레이터** > "기상청 가짜 예보" **`cold`**("추운 밤 + 높은 습도 → 결로 위험"), "실거래가(시세) 가짜 거래" **`rise`**("같은 조건 거래 6건, 월세·보증금이 기준보다 20% 높음 → 알림")
- 한다: 각각 실행하고 흐름 화면에서 시작 상자가 바뀌는 것을 보여 준다. 가상 계정의 알림에서 습도 사건 상세, 시세 비교표를 한 번씩 연다.
- 선택: 시세 묶음 **`live`**는 국토부 실제 거래를 가상 계정의 집·관심 지역에만 비교한다(실제 API 연결 시연). 호출 한도를 확인하지 못했으니 [확인 필요] 리허설에서만 쓴다.
- 말한다: "공고, 습도·결로, 시세. 사건 종류가 세 가지이고 같은 구조로 돕니다."
- 근거: CUJ-04 검증("가짜 묶음 3종과 실패 1종을 한 번씩 돌린다"), spec 003, spec 008.

### 장면 7. 채점 — 숫자로 증명한다
- 화면: **채점 결과** (`/admin/eval`)
- 한다: 정답이 붙은 가짜 묶음 18건의 결과 **맞힘 7, 놓침 0, 잘못 울림 0, 조용히 맞음 11**(공고 10, 습도 8)을 보여 주고 사례 줄을 연다.
- 말한다: "알려야 할 것을 알리고, 알리지 않아야 할 것은 조용히 있었는지를 정답과 비교합니다."
- 주의: 이 숫자는 2026-11-17 생성 파일(`eval/results.json`) 기준이다. **시세 묶음은 아직 채점에 없다**(조각 B 예정). 발표 직전에 `npm run eval`을 다시 돌려 화면과 파일 숫자가 같은지 확인한다 [확인 필요].
- 근거: CUJ-04 5단계, spec 005 FR-004, qa 005 C-505.

### 장면 8. 기록 찾기 — 지난 처리에서 근거를 꺼낸다
- 화면: **기록 찾기** (`/knowledge`)
- 한다: 승인·거절로 끝난 알림을 낱말로 찾고, 결과의 알림 링크·처리 결과·날짜를 연다. 질문으로 물으면 찾은 기록만 근거로 답하고 출처 링크가 붙는다. 근거가 없으면 "기록에서 찾지 못했습니다"가 나온다.
- 말한다: "새 사건이 생겼을 때 비슷한 지난 처리를 근거로 보여 줍니다."
- 주의: qa 005 C-507은 "부분 통과"다(끝난 알림이 없는 계정이라 찾은 기록이 있는 화면과 AI 답은 못 봄). 장면 4에서 끝낸 알림으로 리허설한다.

### 장면 9. 위키 챗봇 — 아직 시연할 수 없다
- 관리자 메뉴의 **위키 챗봇**(`/admin/chat`)은 지금 **자리만 있고 질문 입력이 막혀 있다**(PRD FR-26, 조각 A·gaangstar). 조각 A가 합쳐지면 이 장면을 더하고, 그때까지 시연 순서에서 뺀다.

## 4. 발표 중 문제가 생기면

| 일 | 이유 | 하는 일 |
|---|---|---|
| 새 알림 0건 | 같은 묶음은 알림을 두 번 만들지 않는다(E3) | "같은 변화는 한 번만 알립니다"라고 보여 주고 다른 묶음으로 간다 |
| "대상 0곳" | 운영에 `SIMULATION_USER_IDS`가 없음 | 준비 2번. 발표 중에는 로컬 `npm run dev` 화면으로 넘어간다 |
| AI 요약이 안 나옴 | AI 설정 없음·실패 | 기본 체크리스트와 승인·거절 버튼이 나오는 것을 보여 준다(정상 동작) |
| 배포 직후 옛 규칙 같음 | 배포 직후 수집이 옛 배포로 간 적이 있음(qa 001 실패와 조치 20) | `npm run deploy`는 새 배포를 확인한 뒤에만 수집한다. 발표 직전 배포는 피한다 |
| 운영 화면이 안 열림 | 네트워크·배포 문제 | 로컬 `npm run dev`로 같은 순서를 돌린다. 가짜 묶음 주소(`?fixture=`)는 개발에서만 된다 |

## 5. 확인하지 못한 것 / 정할 것

- 운영 주소에서 위 순서를 **처음부터 끝까지 돌려 본 기록이 없다.** 리허설을 하고 결과를 `docs/specs/005-관리자-시연-기록찾기/qa.md`의 사람 QA 항목 H-501에 팀이 적는다(H-501·H-502 결과 칸은 비어 있고, AI가 대신 통과로 적지 않는다).
- spec 005의 상태가 **"초안 v0.1 (승인 전)"**이다. 시연의 중심 기능이 승인 전이니 팀이 승인할지 정해야 한다.
- `changed` 묶음이 월세도 바꾸는지(장면 2 주의 2)를 리허설에서 확인한다.
- 시연 길이, 맡을 사람(누가 화면을 누르고 누가 말하는지)은 정하지 않았다.
- 가상 계정으로 로그인하는 방법과 정보는 이 문서에 쓰지 않았다(비밀). 팀 비공개 채널에서 받는다.
- 운영의 `AI_PROVIDER`, `SIMULATION_USER_IDS` 값은 이 문서를 쓸 때 확인하지 못했다(Vercel 연결 안 됨).
- 슬라이드의 "시연(실패 장면 포함)"과 "채점" 장은 이 순서의 장면 5, 7과 맞춘다. 슬랙 알림 DM을 넣을지, 위키 챗봇을 넣을지는 조각 A·B 진행에 따라 정한다.
