# 여정 명세: 공고·정책 사건 → 신청 준비 계획 승인

## 개요
| 항목 | 내용 |
|---|---|
| 우선순위 | Critical |
| CUJ 연결 | [CUJ 1](CUJ-01-공고정책-신청준비.md) |
| 사용자 유형 | 신규(첫 설정부터), 재방문(새 사건부터) |
| 빈도 | 공고·정책이 올라올 때마다 (하루 1번 수집) |
| 성공 지표 | 올라온 날부터 알게 된 날까지 걸린 날 수, 상세 → 승인·거절 비율, 단계별 이탈 |

## 사용자 목표
> "나는 내 조건에 맞는 주거 지원 공고·정책을 놓치지 않고 싶다. 그래서 마감 전에 신청 준비를 끝내고 싶다."

## 전제 조건
- 로그인한 사용자. 첫 설정에서 공고·정책 조건을 입력했다.
- 수집이 한 번 이상 성공했고, 조건에 맞는 공고·정책이 1건 이상 있다(없으면 E3).
- 휴대폰과 데스크톱 모두. 휴대폰은 아래 탭으로 들어온다.

## 여정 단계

### 1단계: 첫 설정 (MB_010200_PG)
**사용자 행동:** 시도·시군구, 공급 유형, 월 임대료 상한, 나이를 입력하고 저장한다.
**시스템 반응:** 입력을 검사해 저장하고 작성자·시각을 남긴다. 홈으로 보낸다.
**예상 감정:** 0 (가설) — 무엇을 넣어야 하는지 헷갈릴 수 있다.
**성공 기준:**
- [ ] 입력 항목은 4개 이하, 각 칸에 예시가 보인다
- [ ] 잘못된 값(예: 임대료 상한 음수)은 그 칸 아래에 "무엇이 안 됐는지 + 할 일"로 알린다
- [ ] 건너뛸 수 있고, 건너뛰면 홈 맨 위에 "조건을 입력해 주세요" 카드가 보인다
- [ ] 새로고침·다시 로그인해도 값이 남는다(P3-10)
**예상 마찰 → 대응:** 공급 유형을 모름 → 유형마다 한 줄 설명, "모두"를 기본값으로.

### 2단계: 새 사건 보기 (슬랙 알림 또는 HM_000000_PG → IC_020000_PG)
**사용자 행동:** 슬랙 알림의 링크를 누르거나, 홈의 "새 사건" 카드 숫자를 누른다. 처음 보이는 공고는 사건이 아니라 맞는 공고(NT_080000_PG)에 있다(2026-11-17 사건 정의 변경).
**시스템 반응:** 공고·정책 종류로 걸러진 사건 목록을 보여 준다.
**예상 감정:** +1 (가설)
**성공 기준:**
- [ ] 홈에서 사건 목록까지 한 번 누르면 된다
- [ ] 새 사건은 색과 "새 사건" 글자로 함께 표시한다
- [ ] 수집 오류면 "새 공고 없음"이 아니라 "수집 오류"로 보인다(E2)

### 3단계: 사건 상세 이해 (IC_020100_PG) — MOT
**사용자 행동:** 공고·정책 이름, 신청 기간, 조건 요약, 출처를 읽는다.
**시스템 반응:** 수집한 원문 값(출처, 수집 시각)과 AI 요약·신청 준비 계획 초안(출처 표시)을 나눠 보여 준다. 비슷한 지난 사건이 있으면 함께 보여 준다.
**예상 감정:** -1 → +1 (가설) — "자격이 되나?"에서 "할 일이 보인다"로.
**성공 기준:**
- [ ] 신청 마감일과 남은 날 수가 첫 화면에 보인다
- [ ] 자격은 판정하지 않고 "공고문 기준 확인 필요"로 표시한다
- [ ] 원문 공고 링크가 있다
- [ ] 정책 사건에는 "예산이 먼저 끝날 수 있으니 공고문에서 확인하세요"가 보인다
- [ ] AI 요약이 실패해도 원문 값과 승인·거절 버튼은 보인다(E4)

### 4단계: 계획 승인 (IC_020101_MD)
**사용자 행동:** "승인"을 누르고 확인한다.
**시스템 반응:** 신청 준비 계획을 내 일정에 저장하고, 승인한 사람·시각을 기록한다. 사건 상태를 "승인"으로 바꾼다.
**예상 감정:** +1 (가설)
**성공 기준:**
- [ ] 두 번 눌러도 일정이 두 번 생기지 않는다
- [ ] 저장이 끝나면 "내 일정에 넣었습니다"와 일정 링크가 보인다
- [ ] 거절은 사유를 받고, 일정은 바뀌지 않는다(edge-cases E1)

### 5단계: 준비하기 (SC_060100_PG)
**사용자 행동:** 체크리스트(자격 확인 항목, 서류, 마감일)를 하나씩 체크한다.
**시스템 반응:** 체크 상태를 저장한다. 출처 사건 링크를 보여 준다.
**예상 감정:** +1 (가설)
**성공 기준:**
- [ ] 마감일이 지난 일정은 "마감 지남" 글자로 표시한다

## 에러 시나리오
### E1: 거절
[edge-cases/거절과-수집오류.md](../edge-cases/거절과-수집오류.md)의 E1을 따른다.

### E2: 수집 실패
**발생 조건:** 마이홈 API 호출이 실패하거나 응답 형식이 다르다.
**사용자가 보는 것:** 사건 목록 위에 "오늘 공고를 불러오지 못했습니다. 다음 수집 때 다시 확인합니다."
**복구 경로:** 다음 정기 수집, 관리자의 "지금 한 번 실행".
**검증 방법:** 시뮬레이터에서 실패 묶음을 넣고 목록과 관리자 수집 현황에 "수집 오류"가 보이는지 확인.

### E3: 맞는 공고 없음
**사용자가 보는 것:** "조건에 맞는 새 공고·정책이 아직 없습니다. 마지막 확인: (시각)". 조건 수정 링크.
**복구 경로:** 조건을 넓히거나 기다린다.

### E4: AI 요약 실패
**사용자가 보는 것:** 요약 칸에 "요약을 만들지 못했습니다. 원문을 확인해 주세요." 원문 값과 승인·거절은 그대로.
**복구 경로:** 원문 링크. 요약 다시 만들기 버튼(spec에서 정함).

### E5: 같은 공고를 다시 수집
**발생 조건:** 다음 날 같은 공고 ID가 다시 들어온다.
**사용자가 보는 것:** 바뀐 것이 없으면 새 사건이 생기지 않는다. 접수 기간·임대료·공급 유형이 바뀌었으면 그 변화로 사건이 하나 생기고(전 → 후 표시), 같은 변화를 다시 읽어도 더 생기지 않는다.
**검증 방법:** 같은 묶음을 두 번 넣고 사건 수가 그대로인지 함수 시험으로 확인.

## 추적 지표
- 올라온 날(공고일)부터 사건을 처음 본 날까지 걸린 날 수
- 단계별 이탈: 첫 설정 → 홈 → 상세 → 승인
- 상세 → 승인·거절 비율, 승인까지 걸린 시간
- 수집 오류 수와 다음 수집에서 복구된 비율
