- 버전: v0.1
- 작성일 / 최종 갱신: 2026-11-18 / 2026-11-18
- 근거 문서: 사용자가 붙여 준 서비스 화면 구성(기획안 9절, 2026-11-17), docs/IA.md v1.4(CP·KN·AD 화면 ID와 URL), docs/PRD.md v1.6(FR-18~26, FR-28~34, 9절 하지 않을 것), CLAUDE.md "하지 않을 것"

> **진행 방식(사용자 지시 2026-11-18 새벽):** "승인 받지 말고 요청한 것까지 다 만들어 봐. 기능을 다 넣을 필요는 없고 뼈대부터. 단계별로 기록하되 깃에 커밋하지 말고 로컬에서. 화면 볼 수 있게. 주간 사용량 30%면 멈춤."
> 그래서 이 spec은 **승인 없이** 만든 뼈대의 기록이다. 아침에 사용자가 화면을 보고 고칠 것을 정하면 그때 spec을 다시 다듬는다.

## 1. 해결하려는 문제
기획안 9절 화면(Home, Housing Compare, Housing QC, Energy, Work & Policy, Incident Center, AI Assistant, 관리자) 가운데 아직 화면이 없는 것이 많다. 팀과 채점자가 앱 전체 모양을 한눈에 볼 수 없다. [사용자 붙여 준 IA] [평가항목 B절 필수 화면]

## 2. 주요 사용자
- 팀원(아침에 전체 화면을 둘러봄), 채점자(필수 화면이 어디 있는지 찾음)
- 이야기 1 (P1): 메뉴의 "전체 메뉴"에서 기획안 9절 화면을 모두 열어 볼 수 있다. 아직 기능이 없는 칸은 "뼈대"라고 밝힌다.

## 3. 핵심 기능과 요구사항
### FR-001 전체 메뉴 (P1)
시스템은 기획안 9절 화면 묶음 7개와 관리자 화면을 한 화면에 모아 링크로 보여 줘야 한다. 각 칸에 "되는 것 / 뼈대 / 이번 범위 밖"을 글자로 표시한다.
### FR-002 뼈대 화면 (P1)
시스템은 아직 기능이 없는 화면에 무엇이 들어올지(PRD FR 번호)와 "뼈대 화면"이라는 표시를 보여 줘야 한다. 실제 데이터가 있는 것은 읽기만 해서 보여 준다(새 표·새 저장 없음).
### FR-003 결로 위험 시뮬레이터 (P2, Housing QC)
시스템은 실내 온도·습도·바깥 기온·창 종류를 넣으면 기능 003의 계산(이슬점, 창 표면 온도)으로 결로 위험을 바로 보여 줘야 한다. 저장하지 않는다.
### FR-004 입주 전 점검 체크리스트 (P2, Housing QC)
시스템은 채광·소음·냄새·곰팡이·수압·관리비 등 점검 항목을 보여 주고 체크할 수 있게 해야 한다. 이번에는 저장하지 않는다(뼈대). [PRD FR-29]
### FR-005 관리자 화면 (P1)
시스템은 관리자에게만 관리자 화면(회원·수집 현황·사건 현황·오류와 실행 기록·흐름·시뮬레이터·채점·위키 챗봇)을 보여 줘야 한다. 일반 사용자에게는 "관리자만 볼 수 있습니다". 수집 현황·사건 현황·흐름은 이미 있는 기록을 읽기만 한다. [PRD FR-19~26] [IA AD_*]

### 하지 않을 것 (CLAUDE.md, PRD 9절)
- 개인화 추천 점수·추천 결과: 기획안 Housing Compare의 "개인화 추천 결과·추천 근거"는 PRD에서 **하지 않을 것**이다. 화면에 "이번 범위 밖"으로만 적는다.
- 에너지 시뮬레이션 고도화: Energy Analysis는 "이번 범위 밖"으로 적고 계산을 만들지 않는다.
- 출퇴근·건축물 정보: 보류(PRD FR-33·34).
- 새 DB 표·마이그레이션, 외부 API 새로 부르기, 배포, 커밋.

## 4. 성공 기준
- SC-001: 로그인 뒤 메뉴 "전체 메뉴"에서 기획안 9절 화면을 모두 열 수 있고, 각 화면에 상태 글자(되는 것/뼈대/범위 밖)가 보인다.
- SC-002: 결로 시뮬레이터에 20°C·60%·바깥 -5°C·홑유리를 넣으면 "결로 위험"이 보인다.
- SC-003: 일반 사용자는 /admin에서 "관리자만 볼 수 있습니다"를 보고, 관리자는 수집 기록을 본다.
- SC-004: 모든 새 화면이 375px에서 가로로 넘치지 않는다.
