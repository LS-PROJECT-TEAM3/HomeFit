> 승인 없이 만든 초안이다. 아침에 사용자가 보고 고칠 것을 정한다. **DB 표·마이그레이션은 만들지 않는다**(ERD 변경은 먼저 묻는 일, 하네스 5절). 그래서 저장이 필요한 부분(관리자 수정 기록, 채점 결과 저장)은 6절 확인 필요로 미룬다.

## 1. 해결하려는 문제
관리자 화면 대부분과 기록 찾기가 "뼈대"다. 발표·채점 시연(CUJ-04)에서 가짜 자료로 수집 → 사건 → 흐름 → 채점을 끝까지 보여 줄 수 없고, 사용자는 지난 처리 기록을 찾을 수 없다. [CUJ-04] [PRD FR-18, FR-20~25]

## 2. 주요 사용자
- 관리자(팀원): 발표·점검 때 시뮬레이터 → 흐름 화면 → 채점 순서로 시연 (P1) [CUJ-04]
- 일반 사용자: 지난 위험·기회 알림을 처리한 기록을 찾아봄 (P2) [PRD FR-18]

## 3. 핵심 기능과 요구사항
### FR-001 지금 한 번 실행과 연속 실패 수 (P1) [PRD FR-21] [IA AD_070200_TB]
관리자는 수집 현황에서 출처(마이홈 공고, 기상청 예보)마다 "지금 한 번 실행" 버튼으로 실제 수집을 바로 돌릴 수 있어야 한다. 실행 방식은 "손으로"로 기록한다. 출처마다 최근 연속 실패 수를 보인다. 관리자가 아니면 서버가 거절한다.
### FR-002 시뮬레이터 버튼 (P1) [PRD FR-24] [IA AD_070500_TB] [CUJ-04 1단계]
관리자는 가짜 공고 묶음·가짜 예보 묶음을 골라 버튼으로 수집부터 사건까지 돌릴 수 있어야 한다. 실행 방식은 "시뮬레이터"로 기록하고, 사건은 가상 계정(SIMULATION_USER_IDS)에게만 생긴다(기존 규칙). 실행 결과 요약(성공/실패, 새 사건 수)을 화면에 보이고 흐름 화면으로 가는 링크를 준다. 실거래가(시세) 묶음은 기능이 없어 "아직 없음"으로 적는다.
### FR-003 흐름 화면 (P1) [PRD FR-23] [IA AD_070400_TB, AD_070401_MD] [CUJ-04 MOT]
시스템은 출처별로 실행 기록(runs·run_steps)을 골라 단계를 상자와 화살표로 그려야 한다. 시작 상자 3종(마이홈 공고, 기상청 예보, 실거래가)을 두고, 기록이 없는 출처는 "아직 안 켜짐"(회색)으로 보인다. 상자마다 상태 글자(성공/실패/승인 대기/건너뜀)와 들어온·나간 건수를 보이고, 누르면 상자 상세(입력·출력 건수, 상세 내용, 오류)를 연다. 상세에 비밀 키 값이 보이지 않아야 한다. 최근 실행을 골라 볼 수 있다.
### FR-004 감지 채점 (P1) [PRD FR-25] [CUJ-04 5단계]
시스템은 정답이 붙은 가짜 공고 변화 묶음을 감지 규칙(코드)에 넣어 맞힌·놓친·잘못 울린 수를 계산하고 화면에 보여야 한다. 같은 결과를 명령으로 파일(eval/결과)에도 남긴다. DB와 AI를 부르지 않는다.
### FR-005 회원 보기 (P1, 읽기만) [PRD FR-20] [IA AD_070100_TB, AD_070101_PG]
관리자는 회원 목록(가입일, 조건 수, 내 집 유무, 알림 수, 승인 대기 수)과 회원 상세(조건, 내 집 요약, 사건 목록)를 볼 수 있어야 한다. 이메일은 화면 권한으로 읽지 않아 보이지 않고, 회원 ID 앞 8자만 보인다(개인 정보를 덜 보이는 쪽, 구현 중 바꿈). **관리자 수정(AD_070102_MD)은 수정 기록 표가 필요해 이번에 만들지 않는다**(6절 Q1). 관리자에게 승인 버튼은 없다.
### FR-006 기록 찾기 (P2) [PRD FR-18] [IA KN_050000_PG]
사용자는 지난 위험·기회 알림(승인·거절로 끝난 것)을 낱말로 찾고, 결과마다 알림 링크·처리 결과·날짜를 볼 수 있어야 한다. 질문으로 물으면 찾은 기록만 근거로 답하고 출처 링크를 단다(챗봇 FR-007과 같은 방식). 근거가 없으면 "기록에서 찾지 못했습니다"라고 답한다. 임베딩은 쓰지 않는다(ERD Q1 그대로).

### 하지 않을 것
- 새 DB 표·마이그레이션, 관리자 대신 승인, 위키 챗봇(FR-26, chat_logs 표 필요 → Q2), 배포·커밋(사용자 지시)
- PRD 9절 하지 않을 것 전부

## 3-1. 경계·예외
- E1 관리자가 아닌 사람이 실행·시뮬레이터 서버 동작을 부름 → 거절, 수집 안 돎
- E2 수집 중 실패(가짜 failure 묶음) → 수집 오류로 기록, 흐름 화면에 실패 상자
- E3 같은 묶음을 두 번 돌림 → 사건이 두 번 생기지 않음(기존 중복 규칙)
- E4 실행 기록이 하나도 없는 출처 → "아직 안 켜짐"
- E5 상자 상세 내용에 키 모양 문자열 → 가림
- E6 기록 찾기 결과 0건 → "기록에서 찾지 못했습니다", AI를 부르지 않음

## 4. 성공 기준
- SC-001: 관리자가 시뮬레이터에서 가짜 공고 묶음을 돌리면 30초 안에 결과 요약이 보이고, 흐름 화면에 그 실행의 상자들이 그려진다.
- SC-002: 일반 사용자 계정으로 실행·시뮬레이터 동작을 부르면 거절된다.
- SC-003: 채점 화면에 맞힌·놓친·잘못 울린 수가 보이고, 명령으로 같은 숫자의 파일이 생긴다.
- SC-004: 흐름 화면 상자 상세에 키 값이 0건 보인다.
- SC-005: 기록 찾기에서 끝난 알림 제목 낱말로 찾으면 그 알림이 링크와 함께 나온다.
- SC-006: 새 화면이 375px에서 가로로 넘치지 않는다.

## 5. 제외 범위
관리자 수정과 수정 기록, 위키 챗봇, 채점 결과 DB 저장, 실거래가 수집.
