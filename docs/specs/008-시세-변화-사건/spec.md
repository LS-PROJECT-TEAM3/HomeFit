## 1. 해결하려는 문제
사회초년생은 재계약·이사를 결정한 **뒤에야** 주변 시세를 찾아봐서, 비싸게 재계약하거나 싼 집을 놓친다(P01 "시세를 몰라서 재계약 못한게 가장 손해"). 국토부 전월세 실거래가는 무료로 열려 있지만 직접 찾아 비교하기 어렵다. [문제정의 네 칸 3행] [CUJ-03]

## 2. 주요 사용자
- 자취형(내 집 등록, 계약 금액 입력): 내 계약이 주변보다 비싼지·싼지 (P1)
- 준비형(관심 지역 등록): 관심 지역 시세가 많이 바뀌었는지 (P1)

## 3. 핵심 기능과 요구사항
### FR-001 관심 지역 입력 (P1) [PRD FR-05] [IA MY_030300_TB] [ERD interest_areas]
사용자는 내 정보 → 관심 지역에서 시군구·주택 유형·기준 면적·계약 형태를 넣어 여러 개 저장하고 지울 수 있다. 시군구는 한 번에 여러 곳(10곳까지) 고를 수 있고 고른 곳마다 한 줄이 생긴다(사용자 요청 2026-11-18, 10곳은 API 호출 수를 막는 임시 값). 잘못된 값은 칸 아래에 이유와 할 일을 보인다. 작성자·시각을 남긴다.
### FR-002 전월세 실거래가 한 달 1번 수집 (P1) [PRD FR-09]
시스템은 내 집(계약 형태·금액이 있는 집)과 관심 지역이 쓰는 시군구 × 주택 유형만, 주택 유형별 국토부 API(아파트·오피스텔·연립다세대·단독다가구)에서 최근 3개월(실행 달의 앞 3개월) 거래를 받는다. 대상마다 고른 거래의 중간값·거래 수를 같은 모양(observations)으로 남긴다. 읽기 실패는 수집 오류로 기록한다.
### FR-003 거래 고르기 (P1) [문제정의 사건 기준 표]
같은 시군구, 같은 주택 유형, 같은 계약 형태(월세는 월세가 0보다 큰 거래, 전세는 월세 0), 면적 ±20%인 거래만 쓴다. 아파트·오피스텔·연립다세대는 전용면적, 단독·다가구는 API에 연면적만 있어 연면적으로 비교한다(사용자 결정 2026-11-18). 금액은 만원 단위를 원으로 바꾼다.
### FR-004 내 집 시세 알림 (P1) [PRD FR-12 (가)]
거래가 5건 이상이고(사용자 결정, 임시 값), 중간값이 내 계약보다 10% 이상(임시 값) 높거나 낮으면 알림 1건. 월세 계약은 **월세와 보증금을 따로** 비교해 하나라도 넘으면(사용자 결정), 전세는 보증금. 같은 집·같은 달은 한 번.
### FR-005 관심 지역 시세 알림 (P1) [PRD FR-12 (나)]
거래가 5건 이상이고 중간값이 **지난번 본 값**보다 10% 이상 바뀌면 알림 1건. 처음 본 달은 값만 저장하고 알림을 만들지 않는다. 지난번 본 값은 거래가 충분한 달마다 새 값으로 바꾼다. 같은 관심 지역·같은 달은 한 번.
### FR-006 알림 상세와 대응 계획 (P1) [PRD FR-15, FR-16] [CUJ-03 MOT]
상세에 비교표(내 값 또는 지난번 값, 중간값, 차이 %, 거래 수, 기간, 비교 조건: 면적 범위·계약 형태)를 원문 값으로 보이고, "실거래가 기준, 같은 조건 거래만 비교, 전환율 쓰지 않음"을 적는다. 대응 계획: 내 집은 "재계약 판단 메모"(주변 거래 비교, 집주인과 이야기할 점), 승인하면 계약 만료 2달 전 날짜로 내 일정에(만료일 없으면 날짜 없음). 관심 지역은 "관심 지역 다시 보기". AI는 요약·할 일 초안만, 실패하면 기본 할 일.
### FR-007 슬랙 알림·관리자 (P2) [PRD FR-21, FR-23, FR-24, FR-37]
켠 사람에게 숫자와 링크만 슬랙으로 보낸다(주소·AI 요약 없음). 수집 현황(연속 실패·지금 한 번 실행), 흐름 화면 시작 상자 "실거래가", 시뮬레이터 가짜 거래 묶음(오름·적음·실패, 가상 계정에게만).

### 하지 않을 것
- 보증금·월세 전환율 비교(PRD 9절), 민간 플랫폼 매물 크롤링, 매매가
- 관심 주택 목록 반영(FR-28, 표 없음), 계약 만료 일정 자동 표시(FR-31 문서 충돌, 따로 묻는 중)

## 3-1. 경계·예외
- E1 거래 4건 → 알림 없음, 관찰값엔 "거래 부족"
- E2 차이 정확히 10% → 알림(이상). 9.9% → 없음
- E3 월세 계약인데 월세는 그대로, 보증금만 12% 오름 → 알림
- E4 내 집에 계약 형태나 금액이 없음 → 비교 대상 아님
- E5 관심 지역 첫 달 → 값만 저장, 알림 없음
- E6 같은 달 두 번 수집 → 알림 하나
- E7 API 하나가 실패(예: 오피스텔) → 실행은 수집 오류로 기록, 다른 유형 결과는 남김
- E8 금액 칸이 "13,500"(글자, 쉼표) 또는 숫자 → 같은 원 단위
- E9 면적 ±20% 경계(기준 50㎡면 40㎡·60㎡ 포함)
- E10 관심 지역 입력 값이 틀림(면적 0 이하·300㎡ 초과, 모르는 유형) → 칸 아래 오류

## 4. 성공 기준
- SC-001: 가짜 "오름" 묶음을 시뮬레이터로 돌리면 가상 계정에 시세 알림이 생기고, 같은 묶음을 다시 돌려도 늘지 않는다.
- SC-002: 경계 E1~E3, E5, E8, E9가 함수 시험으로 통과한다.
- SC-003: 운영에서 실제 API로 수집이 성공하고 대상마다 중간값·거래 수가 남는다.
- SC-004: 알림 상세에 비교표(중간값·거래 수·기간·조건)와 출처가 보이고, 승인하면 내 일정에 만료 2달 전 날짜로 들어간다.
- SC-005: 관심 지역을 넣고·지우고, 새로고침 뒤에도 남는다. 375px에서 가로 넘침이 없다.

## 5. 제외 범위
관심 주택 반영, 계약 만료 자동 일정, 전환율, 매매.
