## 1. 해결하려는 문제
**지금 방식:** AI 요약은 Claude 한 곳만 부르게 코드에 박혀 있다. 실습 키가 만료돼 지금은 AI 요약이 꺼져 있다. [Intent Q19] [코드 incident/plan-draft.server.ts]
**막히는 지점:**
- 개발하는 동안 AI 요약을 시험할 방법이 없다. 무료로 쓸 수 있는 Gemini로 개발하고, 배포 때 Claude로 바꾸고 싶다. [사용자 요청 2026-11-17]
- 자동 시험과 Ralph Loop가 실제 API를 부르면 무료 한도를 쓰고 결과가 매번 달라진다. [사용자 요청]
- AI를 몇 번 불렀는지, 얼마나 걸렸는지, 토큰을 얼마나 썼는지, 실패했는지 남지 않는다. 지금은 실패 이유만 실행 기록에 남는다. [코드 watch/collect.server.ts draft_plan detail]
- 앞으로 기록 찾기(FR-18)·위키 챗봇(FR-26)도 AI를 쓸 텐데, 지금 구조로는 기능마다 공급자 코드를 다시 짜야 한다. [PRD FR-18, FR-26]

## 2. 주요 사용자
**사용자:** 이 저장소에서 개발하는 팀원과 Claude(코딩 에이전트). 서비스 사용자는 달라진 점을 느끼지 못해야 한다. [CLAUDE.md 팀 하네스]

### 이야기 1 — 개발은 Gemini 무료로, 배포는 Claude로 (P1)
- 장면: 팀원이 `.env.local`에 `AI_PROVIDER=gemini`와 Gemini 키를 넣고 수집을 돌리면 AI 요약이 나온다. 배포 때 Vercel 환경변수만 `AI_PROVIDER=claude`로 바꾸면 코드 수정 없이 Claude로 바뀐다.
- 왜 P1인가: 지금 꺼져 있는 AI 요약(spec 001 C-031)을 다시 확인할 유일한 길이다.
- 혼자 확인하는 방법: 환경변수만 바꿔 수집을 두 번 돌리고, 저장된 계획의 모델 이름이 바뀌었는지 본다.

### 이야기 2 — 시험은 실제 API 없이 (P1)
- 장면: `npm test`와 Ralph Loop가 돌 때 AI 호출은 모두 mock이 받아 같은 입력에 같은 답을 준다. 한도 초과·이상한 JSON도 mock으로 흉내 낸다.
- 왜 P1인가: 무료 한도를 시험에 쓰지 않고, 실패 처리도 시험할 수 있어야 한다.
- 혼자 확인하는 방법: 인터넷을 끊고 `npm test`가 통과하는지 본다.

### 이야기 3 — 호출 기록으로 비용·한도를 본다 (P2)
- 장면: 관리자가 DB에서 오늘 AI 호출 수, 평균 응답 시간, 토큰 합계, 실패 수를 공급자별로 본다.
- 왜 P2인가: 첫 화면 기능에는 없어도 되지만, 무료 한도를 넘기 전에 알아야 한다.
- 혼자 확인하는 방법: 수집 한 번 뒤 호출 기록을 SQL로 센다.

## 3. 핵심 기능과 요구사항

### FR-001 공급자 고르기 (P1)
시스템은 서버 환경변수 `AI_PROVIDER`의 값(`gemini`, `claude`, `mock`)으로 AI 공급자를 골라야 한다. [사용자 요청]
- 수용 기준
  1. **전제** `AI_PROVIDER=mock` **행동** 수집이 계획 초안을 부른다 **결과** 바깥 네트워크 호출 없이 mock 답이 쓰인다
  2. **전제** `AI_PROVIDER`가 비어 있고 개발·시험 환경 **행동** 같은 호출 **결과** mock이 쓰인다
  3. **전제** `AI_PROVIDER`가 비어 있고 운영 배포 **행동** 같은 호출 **결과** AI를 부르지 않고 실패 "AI 설정 없음"으로 끝나며, 계획은 기본 체크리스트로 저장된다
  4. **전제** `AI_PROVIDER=gpt`처럼 모르는 값 **행동** 같은 호출 **결과** 실패 "모르는 AI 공급자: gpt"로 끝나고 기본 체크리스트가 쓰인다

### FR-002 공통 요청·응답 (P1)
시스템은 어느 공급자든 같은 모양으로 요청(용도, 지시문, 사용자 글, 원하는 JSON 모양, 최대 길이)을 받고, 같은 모양으로 답(성공: JSON 값·공급자·모델·토큰·걸린 시간 / 실패: 실패 종류·설명)을 돌려줘야 한다. 기능 코드는 어느 공급자인지 몰라도 된다. [사용자 요청]
- 수용 기준
  1. **전제** 같은 요청 **행동** gemini, claude, mock으로 각각 부른다 **결과** 세 답의 모양(칸 이름)이 같다
  2. **전제** 실패 **행동** 답을 본다 **결과** 실패 종류는 정해진 목록(설정 없음, 인증, 한도 초과, 시간 초과, 거절, JSON 아님, 모양 다름, 서버 오류, 알 수 없음) 중 하나다

### FR-003 JSON 구조화 응답 검사 (P1)
시스템은 공급자에게 원하는 JSON 모양을 알려 주고, 받은 답이 그 모양이 아니면 실패로 처리해야 한다. 모양이 맞지 않은 AI 글은 저장하거나 화면에 보이지 않는다. [사용자 요청] [spec 001 FR-010 수용 기준 3]
- 수용 기준
  1. **전제** 답이 JSON이 아님 **행동** 계획 초안을 만든다 **결과** 실패 "JSON 아님", 기본 체크리스트가 쓰인다
  2. **전제** 답이 JSON이지만 필요한 칸이 없음 **행동** 같은 호출 **결과** 실패 "모양 다름", 기본 체크리스트가 쓰인다

### FR-004 호출 기록 (P1)
시스템은 AI 호출마다 공급자, 모델, 용도, 걸린 시간, 입력·출력 토큰, 성공 여부, 실패 종류, 시도 횟수, 어느 수집 실행에서 불렀는지를 남겨야 한다. 보낸 글·받은 글과 키는 남기지 않는다. [사용자 요청] [PRD FR-27]
- 수용 기준
  1. **전제** 수집에서 AI를 3번 부름 **행동** 호출 기록을 센다 **결과** 3건, 각각 걸린 시간과 토큰(공급자가 알려 준 만큼)이 있다
  2. **전제** 한도 초과로 두 번 다시 시도한 뒤 실패 **행동** 호출 기록을 본다 **결과** 1건, 시도 3회, 실패 종류 "한도 초과"
  3. **전제** 일반 사용자 **행동** 호출 기록을 읽으려 함 **결과** 읽을 수 없다(관리자만)

### FR-005 무료 한도 초과 때 다시 시도 (P1)
공급자가 한도 초과로 답할 때, 시스템은 공급자가 알려 준 대기 시간(없으면 점점 길게)만큼 기다렸다 최대 2번 다시 부르고, 그래도 안 되면 실패로 끝내야 한다. 한 번 수집에서 기다리는 시간은 모두 합쳐 정해진 한도를 넘지 않는다. [사용자 요청]
- 수용 기준
  1. **전제** 첫 호출만 한도 초과 **행동** 계획 초안 **결과** 두 번째에 성공, 호출 기록 시도 2회
  2. **전제** 세 번 다 한도 초과 **행동** 계획 초안 **결과** 실패 "한도 초과", 기본 체크리스트, 시도 3회
  3. **전제** 공급자가 "60초 뒤에" 라고 알려 줌(대기 한도보다 김) **행동** 같은 호출 **결과** 기다리지 않고 바로 실패 "한도 초과"
  4. **전제** 인증 실패(키 틀림) **행동** 같은 호출 **결과** 다시 시도하지 않고 바로 실패 "인증"

### FR-006 한 번 수집의 AI 호출 상한 (P1)
시스템은 한 번 수집에서 AI 호출을 정해진 수까지만 하고, 넘는 계획은 AI 없이 기본 체크리스트로 만들어야 한다. [사용자 요청 "무료 한도"] [spec 001 경계 "공고 수백 건"]
- 수용 기준
  1. **전제** 상한 20, 변화 사건 25건 **행동** 수집 **결과** AI 호출 20건, 나머지 5건은 기본 체크리스트, 실행 기록에 "AI 상한으로 건너뜀 5"

### FR-007 Mock 공급자 (P1)
시스템은 네트워크를 쓰지 않는 mock 공급자를 가져야 한다. 같은 요청에는 늘 같은 답을 주고, 시험에서 실패(한도 초과, JSON 아님, 시간 초과)를 골라 흉내 낼 수 있어야 한다. 자동 시험과 Ralph Loop는 mock만 쓴다. [사용자 요청]
- 수용 기준
  1. **전제** mock **행동** 같은 요청을 두 번 **결과** 같은 답, 토큰은 글 길이로 어림한 값, 호출 기록에 공급자 "mock"
  2. **전제** 시험이 mock에 "한도 초과 두 번" 을 정함 **행동** 계획 초안 **결과** FR-005 수용 기준 1과 같다
  3. **전제** `npm test` **행동** 인터넷 없이 돌린다 **결과** 모두 통과

### FR-008 키는 서버에서만 (P1)
AI 키는 서버 환경변수에만 두고, 화면 코드·저장소·호출 기록·오류 문구에 나오지 않아야 한다. [PRD FR-27] [CLAUDE.md 보안]
- 수용 기준
  1. **전제** 키가 든 오류가 남 **행동** 실행 기록·호출 기록을 본다 **결과** 키 값이 가려져 있다
  2. **전제** 빌드한 화면 코드 **행동** 키 이름·값을 찾는다 **결과** 0건

### FR-009 AI 없는 계산·감지는 따로 (P1)
수치 계산(남은 날 수, 조건 맞추기)과 사건 감지(변화 판단)는 AI 모듈에 기대지 않는 별도 모듈로 두고, AI가 실패해도 같은 결과를 내야 한다. AI 모듈도 감지·계산 모듈을 부르지 않는다. [사용자 요청] [CLAUDE.md 팀 작업 규칙 "비교·저장·권한 검사는 코드로"]
- 수용 기준
  1. **전제** AI 공급자 아무거나 실패 **행동** 수집 **결과** 사건 수와 사건 내용(원문 값, 전 → 후)은 AI가 성공했을 때와 같다
  2. **전제** 코드 **행동** 감지·계산 모듈이 무엇을 불러오는지 본다 **결과** AI 모듈을 불러오지 않는다(시험으로 확인)

### FR-010 신청 준비 계획 초안을 새 구조로 (P1)
spec 001 FR-010의 신청 준비 계획 초안은 이 공통 구조로 AI를 불러야 한다. 사용자에게 보이는 동작(요약·체크리스트·출처, 실패 때 기본 체크리스트)은 그대로이고, 계획에 남는 모델 이름에 공급자가 붙는다. [spec 001 FR-010] [ERD response_plans.model]
- 수용 기준
  1. **전제** gemini 성공 **행동** 사건 상세를 본다 **결과** AI 요약과 출처가 보이고, 계획의 모델 이름이 "gemini:…"다
  2. **전제** 어떤 공급자든 실패 **행동** 사건 상세 **결과** "요약을 만들지 못했습니다. 원문을 확인해 주세요."와 기본 체크리스트, 승인·거절 버튼

### 경계·예외 상황
- 공급자가 시간 안에 답하지 않음: 실패 "시간 초과", 다시 시도하지 않는다(한도 초과만 다시 시도).
- 공급자가 안전 이유로 답을 거절: 실패 "거절", 다시 시도하지 않는다.
- 공급자가 토큰 수를 알려 주지 않음: 토큰 칸은 비우고 실패로 보지 않는다.
- 같은 수집에서 한도 초과가 이어짐: 대기 시간 합계가 한도에 닿으면 남은 호출은 기다리지 않고 기본 체크리스트로 간다.
- 호출 기록을 남기다 실패: AI 결과는 그대로 쓰고, 실행 기록에 "호출 기록 실패"를 남긴다(수집을 실패로 만들지 않는다).
- Gemini 무료 플랜: 보낸 글이 구글의 서비스 개선에 쓰일 수 있어, 공고 원문 값(공개 자료)만 보낸다. 사용자 이름·이메일·조건은 보내지 않는다(가정, Q23).
- 배포 중 `AI_PROVIDER`를 바꿈: 다음 호출부터 새 공급자를 쓴다(재배포 필요 여부는 plan에서 확인).

### 핵심 자료
- **AI 호출 기록(새로)**: 공급자, 모델, 용도(예: 신청 준비 계획), 걸린 시간, 입력·출력 토큰, 성공 여부, 실패 종류, 시도 횟수, 수집 실행, 시각. 보낸 글·받은 글·키는 없다
- **대응안(있음)**: 모델 이름에 공급자를 붙인다(예: `gemini:모델명`, `claude:claude-haiku-5-5`, `mock:fixed`)

## 4. 성공 기준

### 완료 확인
- **SC-001**: `AI_PROVIDER=mock`으로 가짜 변화 수집을 돌리면 바깥 AI 호출 없이 계획이 저장되고, 호출 기록이 사건 수만큼 공급자 "mock"으로 남는다. (관련: FR-001, FR-002, FR-004, FR-007, FR-010)
- **SC-002**: `AI_PROVIDER=gemini`와 실제 키로 가짜 변화 수집을 돌리면 AI 요약이 저장·표시되고(spec 001 C-031 다시 확인), 호출 기록에 걸린 시간·토큰이 있다. (관련: FR-001, FR-003, FR-004, FR-010)
- **SC-003**: mock으로 한도 초과를 흉내 내면 두 번 다시 시도한 뒤 실패하고, 기본 체크리스트가 저장되며, 기다린 시간 합계가 한도 안이다. (관련: FR-005, FR-007)
- **SC-004**: 키 없이 `AI_PROVIDER=gemini`·`claude`로 수집해도 수집은 성공하고, 사건과 기본 체크리스트가 생기며, 실패 종류가 "설정 없음"이다. (관련: FR-001, FR-009, FR-010)
- **SC-005**: 저장소·빌드 결과·실행 기록·호출 기록에서 AI 키 값이 0건이다. (관련: FR-008)
- **SC-006**: 인터넷 없이 `npm test`가 통과하고, 감지·계산 모듈이 AI 모듈을 불러오지 않는다. (관련: FR-007, FR-009)
- **SC-007**: 공급자를 바꾸는 데 환경변수 한 줄만 바꾸면 되고, 새 공급자(예: Groq)를 더할 때 기능 코드는 고치지 않는다(공급자 파일 하나와 등록 한 줄). (관련: FR-001, FR-002)
- **SC-008**: 한 수집에서 변화 사건이 상한보다 많으면 AI 호출은 상한까지만 생긴다. (관련: FR-006)
