## 1. 기술과 버전
2026-11-20 `package.json`·명령으로 확인한 값.
- Next.js 16.4.6(App Router), React 19.3.0, TypeScript 5.9.3(strict), Vitest 5.1.0, Node 24.21.0, Supabase JS 2.119.0
- 브라우저 쪽: 표준 Push API·Notification API·서비스 워커(브라우저에 들어 있음, 라이브러리 없음). 앱 이름·아이콘은 Next.js `app/manifest.ts`(spec Q2)
- **새 의존성 1개(승인 필요)**: `web-push` **3.6.7** + 타입 `@types/web-push` 3.6.4(개발용)
  - 하는 일: 서버에서 브라우저 푸시 서비스(구글·애플·모질라)로 암호화한 알림을 보낸다. 표준(RFC 8291 암호화, VAPID 서명)을 직접 짜면 길고 틀리기 쉽다
  - 무료(MPL-2.0), 계정·API 키 필요 없음. 푸시 서비스도 무료
  - 4.0.0이 2026-11-06에 나왔지만 나온 지 2주 된 큰 버전이라 오래 쓰인 3.6.7을 고른다(타입 패키지도 3.6.x)
- **새 환경변수 3개**: `NEXT_PUBLIC_VAPID_PUBLIC_KEY`(공개해도 되는 키), `VAPID_PRIVATE_KEY`(비밀), `VAPID_SUBJECT`(`mailto:` 연락처). 키 한 쌍은 로컬에서 `web-push`로 만들어 `.env.local`에만 쓰고, 운영 값은 사용자가 Vercel에 넣는다. 값은 대화·코드·문서에 쓰지 않는다
- 시험은 실제 푸시 서비스를 부르지 않는다(보내는 함수를 시험 대역으로 바꾼다)

## 5. 제약과 주의점
**항상**
- 알림 글에는 이름·조건·시군구·AI 요약을 넣지 않는다(슬랙과 같음, E8)
- 켜기 전에 생긴 사건은 보내지 않는다(슬랙과 같음)
- 키가 없거나 보내기가 실패해도 수집과 사건 만들기는 성공으로 끝난다

**먼저 물을 것**
- 0022를 운영 DB에 적용하기 직전(ERD 변경)
- 운영 키를 Vercel에 넣는 일(사용자가 직접), 배포

**절대 하지 말 것**
- 카카오톡, 스토어 앱, 사건 말고 다른 알림, 알림에서 바로 승인·거절, 조용한 시간·종류 고르기, 관리자가 다른 사람 기기 보기(spec 5절)
- 비밀 키를 코드·문서·대화에 쓰기
- 시험에서 실제 푸시 서비스 부르기
