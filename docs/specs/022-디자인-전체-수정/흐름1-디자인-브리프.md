# 디자인 브리프 1: 조건 등록 → 맞춤 공고·정책 → 팔로우 → 알림 → 처리

- 작성: 2026-11-19, 조각 D. 현경님이 정한 첫 디자인 범위
- 쓰임: Claude Design(또는 피그마)에 이 흐름의 화면만 새로 그려 달라고 넘기는 자료
- 근거: `docs/journeys/critical/CUJ-01-공고정책-신청준비.md`, `docs/IA.md` v1.15, 지금 코드 화면. 함께 볼 것: `화면-구성-이유.md` 5절(지켜야 할 것)
- 이번에 **넣지 않는 화면**: 집 비교, 집 점검, 에너지 분석, AI 도우미, 관리자(메뉴 자리만 남긴다)

## 이 흐름의 사용자
- 취업이나 독립을 앞두고 집을 구하는 사회초년생(준비형)과, 지금 혼자 사는 사회초년생(자취형) [journeys README 페르소나]
- 불편: 맞는 공고를 늦게 알고, 정책 문구가 어려워서 넘긴다("무슨 말인지 잘 모르겠어서", P04). 지원금 30만 원 정도를 놓친 사례가 2건 있다. [CUJ-01]
- 바라는 것: **조건을 한 번만 넣으면** 맞는 공고·정책이 알아서 모이고, 바뀌면 알려 주고, 할 일이 일정에 정리되는 것

## 흐름 한 장
```
① 첫 설정: 내 집(없으면 건너뛰기) → 공고·정책 조건
      ↓
② 맞춤 결과: 공공임대 모집(맞춤 공고) / 청년 주거지원 정책
      ↓ 하나를 연다
③ 공고 상세 → 팔로우 / 관심 없음        ③' 정책 상세 → 원문 보기
      ↓ (며칠 뒤, 팔로우한 공고가 바뀜)
④ 알림이 옴: 홈 숫자, 메뉴 배지, (켠 사람만) 슬랙
      ↓
⑤ 알림 상세: 무엇이 바뀌었나 → AI 신청 준비 계획 초안 → 승인 / 거절
      ↓ 승인
⑥ 내 일정: 체크리스트와 마감일
```

## 화면별로 담을 것

### ① 첫 설정 (`/onboarding`, MB_010200_PG)
- 가입 직후 한 번만. 전체를 건너뛸 수도 있다("나중에 입력하기"). 건너뛰면 홈 맨 위에 입력 카드가 뜬다.
- 순서(현경님 결정 2026-11-19, Q1): **1단계 내 집 → 2단계 공고·정책 조건**
  - 1단계 내 집: 시군구, 주택 유형, 전용면적, 계약 형태(월세·전세), 만료일, 창 종류
    - **내 집이 없으면 건너뛰기**: "아직 내 집이 없어요" 버튼으로 2단계로 넘어간다. 이때 관심 지역(시군구)을 넣을 수 있게 하되, 이것도 비워 둘 수 있다
  - 2단계 공고·정책 조건: 지역, 공급 유형, 임대료 상한, 나이. 맞춤 결과는 이 조건으로 고른다
- 디자인에서 풀 것: 단계 표시(1/2, 2/2), 왜 묻는지 한 줄(1단계 "습도·결로와 시세 알림에 써요", 2단계 "이 조건으로 맞는 공고를 골라요"), 지금 채운 정도, 건너뛰기 버튼이 잘 보일 것

### ② 맞춤 결과 (`/notices`, `/policy`)
- 탭 두 개: **공공임대 모집(맞춤 공고)**, **청년 주거지원 정책**
- 맞춤 공고 한 줄: 상태 배지(새 공고 / 팔로우 / 관심 없음 / 마감), 공고 이름, 공급 유형, 마감까지 며칠
- 정책 한 줄: 정책 이름, 기관, 분류(대출·이자 / 월세·전세 지원 / 주택·거주 / 기숙사), 신청 기간과 남은 날, 나이 조건, 한 줄 설명, "자격은 공고문 기준 확인 필요", 원문 보기
- 위쪽: "내 조건에 맞는 정책 56건"처럼 건수, 분류 거르기
- 디자인에서 풀 것: 아직 정하지 않은 새 공고가 가장 먼저 보이게. 마감이 가까운 것을 표시(색 + 글자)

### ③ 공고 상세 (`/notices/[id]`, NT_080100_PG)
- 맨 위: 공고 이름, 상태, 접수 기간, 공급 유형
- 공고 요약: AI가 쓴 쉬운 요약. 출처는 공고 원문
- 공고 원문 값: 공고일, 접수 기간, 단지별 지역·월 임대료
- 이 공고로 생긴 내 알림(있으면)
- 행동: **팔로우**("이 공고를 팔로우할까요?" 확인 창), **관심 없음**(사유를 고르는 창), 원문 링크
- 디자인에서 풀 것: 팔로우가 이 화면의 주 버튼. 팔로우하면 무엇이 달라지는지 한 줄("바뀌면 알려 드려요")

### ③' 정책 상세 (`/policy/[id]`, PL_090100_PG)
- 정책 원문 값(설명, 지원 내용, 신청 방법, 서류, 대상), AI 요약, 원문 링크
- **지금은 팔로우가 없다**(공고만 팔로우된다, spec 006 Q1) → 아래 Q2

### ④ 알림이 오는 곳 (홈 `/`, 메뉴)
- 홈 카드 "새 위험·주거 기회": 새 위험 수, 새 주거 기회 수, 팔로우를 정할 맞춤 공고 수
- 메뉴 "위험·기회 알림" 옆 숫자 배지
- 슬랙: 내 정보 → 계정·알림에서 켠 사람에게만
- 디자인에서 풀 것: 처리할 게 있을 때 홈에서 가장 먼저 보이게. 0건일 때는 다음에 할 일 안내

### ⑤ 알림 상세 (`/incidents/[id]`, IC_020100_PG + 승인·거절 창)
- 순서(IA 콘텐츠 우선순위)
  1. **무엇이 바뀌었나**: 바뀐 값(예: 접수 기간 11.30 → 12.15), 출처, 수집 시각
  2. **대응안 초안**: AI가 쓴 신청 준비 계획(할 일 목록, 마감일). "자격은 공고문 기준 확인 필요"
  3. **승인 / 거절** 버튼
     - 승인 창: "신청 준비 계획을 승인할까요? 승인하면 체크리스트와 마감일이 내 일정에 들어갑니다" → 끝나면 "내 일정에 넣었습니다 · 일정 보기"
     - 거절 창: 사유 필수 → "거절했습니다. 일정은 바뀌지 않았습니다"
  4. 비슷한 지난 알림, 처리 이력
- 상태 배지: 새 알림 → 승인 대기(처음 열면) → 승인 / 거절. 색과 글자를 함께
- 디자인에서 풀 것: 근거(1)를 보고 판단한 뒤 승인하는 순서가 눈에 보일 것. 승인은 사람이 누른다(자동처럼 보이면 안 됨)

### ⑥ 내 일정 (`/schedule`, `/schedule/[id]`)
- 목록: 승인한 계획, 마감일 순. 맨 위에 계약 만료 알림(만료 2달 전부터)
- 상세: 체크리스트(서류, 마감일), 이 일정이 나온 알림 링크
- 디자인에서 풀 것: 마감까지 남은 날과 체크 진행률

## 화면마다 필요한 상태
- 빈 화면: "아직 알림이 없습니다", "아직 승인한 계획이 없습니다", 조건이 비어 맞춤 결과가 없을 때 "조건을 넣어 주세요"
- 불러오는 중, 조회 실패("데이터 없음"과 다른 문구)
- 휴대폰 375px에서 가로 스크롤 없음

## 지켜야 할 것 (요약, 자세히는 `화면-구성-이유.md` 5절)
- 용어: "위험·기회 알림", "맞춤 공고"("추천" 아님), "슬랙 알림"
