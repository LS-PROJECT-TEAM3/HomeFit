# HomeFit 화면 구성과 그렇게 만든 이유

- 작성: 2026-11-19, 조각 D(디자인 전체 수정) 준비 자료
- 쓰임: Claude Design으로 새 디자인을 만들 때 넘겨줄 설명. 지금 화면이 **무엇을 위해** 있고 **왜 이렇게 놓였는지**, 그리고 새 디자인에서도 **바꾸면 안 되는 것**을 담았다.
- 근거: `docs/IA.md` v1.15, `docs/specs/004-화면-뼈대/spec.md` v0.6, `CLAUDE.md` "디자인"·"하지 않을 것", 2026-11-19 로컬 화면(운영 DB 자료, 수집은 돌리지 않음)

## 1. 이 앱이 하는 일 (한 줄)
사회초년생이 공고 사이트·날씨·시세를 직접 찾아보지 않아도, **나에게 맞는 변화(위험·기회)를 알림으로 받고 → AI가 쓴 대응안을 내가 승인하면 → 내 일정에 저장**되는 앱. 집을 고를 때는 월세+관리비+에너지비를 더한 실질 주거비로 비교한다.

### 핵심 흐름 (가장 중요한 동선)
```
매일 자동 수집 → 기준 넘음 → [홈] 새 알림 숫자 → [위험·기회 알림] 목록 → 알림 상세
   → 대응안 승인 → [내 일정]에 저장          → [AI 도우미] 처리 기록·찾기
   → 대응안 거절(사유) → 처리 기록에 남음
```
홈에서 승인까지 3번 안에 닿게 설계했다(IA "Depth 한도").

## 2. 메뉴 구조와 그 이유

| 순서 | 메뉴 | 위쪽 탭 | 왜 이 메뉴가 있나 |
|---|---|---|---|
| 1 | 홈 | — | 로그인 뒤 첫 화면. "내 집" 중심 요약 카드(IA 사용자 결정 2026-11-17) |
| 2 | 집 비교 | 관심 주택 / 실질 비용 비교 / 추천 결과 | 기획안 9절 Housing Compare. 알파 기능(P3-09) |
| 3 | 집 점검 | 결로 위험 시뮬레이터 / 입주 전 품질 점검 / 주거환경·하자 기록 / 건축물 기본 정보 | 기획안 Housing QC |
| 4 | 에너지 분석 | 예상 에너지 사용량 / 월별 예상 비용 / 냉난방비 시뮬레이션 | 기획안 Energy |
| 5 | 청년 정책 | 공공임대 모집(맞춤 공고) / 신청 계획(내 일정) / 청년 주거지원 정책 | 기획안 Work & Policy. 직장·생활권 탭은 2026-11-19 삭제 |
| 6 | 위험·기회 알림 | 종류·상태 거르기 | 기획안 Incident Center. **앱의 핵심 기능** |
| 7 | AI 도우미 | 기록 찾기 / 처리 기록 / 공공데이터 출처 | 기획안 AI Assistant |
| — | 내 일정 | — | 승인한 계획이 쌓이는 곳 |
| — | 내 정보 | 내 집 / 공고·정책 조건 / 관심 지역 / 계정·알림 | 알림 기준이 되는 입력값 |
| — | 관리자 | 개요·회원·수집 현황·사건 현황·흐름 화면·시뮬레이터·채점 결과·위키 챗봇 | 관리자에게만 보임. 평가 시연용 |
| 모든 화면 | 오른쪽 아래 "챗봇" 버튼 | — | 내 처리 기록·공공데이터로만 답하는 도우미(spec 004 FR-007) |

**왜 이렇게 놓였나**
- 메뉴 1~7의 순서는 **기획안 9절의 화면 순서**(Home, Housing Compare, Housing QC, Energy, Work & Policy, Incident Center, AI Assistant)를 그대로 따랐다. 사용자 할 일 순서로 정한 것이 아니다. [spec 004 FR-001]
- PC는 왼쪽 사이드바, 휴대폰은 위쪽 "메뉴" 버튼으로 같은 목록을 연다. 한 메뉴의 하위 화면은 위쪽 탭으로 나눈다. 처음에는 "전체 메뉴" 목록 페이지가 있었는데, "진짜 대시보드랑 탭을 만들어야지 늘어놓으면 어떡해"라는 사용자 의견으로 이 틀이 됐다. [spec 004 v0.2, 2026-11-18]
- "위험·기회 알림" 메뉴에는 새 알림 숫자 배지가 붙는다. 색만 쓰지 않고 숫자를 함께 쓴다. [IA 네비게이션 모델]
- IA 원안은 휴대폰 아래 탭 5개(홈·사건·내 일정·기록 찾기·더 보기)였지만, 구현은 위쪽 메뉴 버튼으로 바뀌었다. [IA 네비게이션 모델, spec 004 v0.2]

## 3. 화면별 구성과 이유

### 홈 (HM_000000_PG, `/`)
- **들어 있는 것**: 벤토 카드 6개 — 나의 주거 정보, 바깥 날씨(지금), 월 예상 주거비, 주거환경 분석 현황(실내 습도·48시간 결로 위험), 새 위험·주거 기회(숫자), 승인 대기·처리 현황(숫자), 최근 알림 타임라인, 다가오는 일정
- **왜**: 앱이 알림 중심이라 "지금 내가 처리할 것이 있나"를 숫자로 먼저 보이려 했다. 숫자를 누르면 그 목록으로 간다(P3-12). 비어 있는 카드는 지우지 않고 "입력해 주세요" 카드로 바꾼다. 카드 크기를 다르게 한 벤토 격자는 2026-11-17 사용자가 고른 스타일이다. [IA 화면별 콘텐츠 우선순위, CLAUDE.md 디자인]
- **사용자가 하는 일**: 새 알림·승인 대기 숫자 확인 → 눌러서 처리. 내 집 정보가 비면 입력하러 감.

### 위험·기회 알림 (IC_020000_PG `/incidents`, 상세 IC_020100_PG)
- **들어 있는 것**: 목록(종류·상태·기간 거르기), 상세(무엇이 바뀌었나·출처·수집 시각 → AI 대응안 초안 → 승인/거절 → 비슷한 지난 알림 → 처리 이력)
- **왜**: 알림 종류는 "위험"(습도·결로, 시세)과 "주거 기회"(팔로우한 공고의 변화) 둘로 묶었다. 상세는 "무엇이 바뀌었나"를 맨 위에 둔다. 사람이 근거를 보고 판단한 뒤에만 승인하게 하려는 것이다. 거절은 사유가 필수이고, 거절해도 기존 일정은 그대로다. [IA IC, CLAUDE.md "사람이 승인하기 전에는 조치하지 않는다"]
- **사용자가 하는 일**: 알림 열기 → 근거 확인 → 승인(내 일정에 저장) 또는 거절(사유)

### 청년 정책 (`/policy`, `/notices`)
- **들어 있는 것**: 탭 3개 — 공공임대 모집(맞춤 공고), 신청 계획(내 일정), 청년 주거지원 정책
- **맞춤 공고**: 내 조건에 맞는 공고 목록. 상세에서 AI 요약을 보고 **팔로우**하거나 **관심 없음**을 고른다. 팔로우한 공고가 바뀌면 그때 "주거 기회" 알림이 생긴다. 새 공고 자체는 알림이 아니다. [IA 확인된 사항 2026-11-17]
- **청년 주거지원 정책**: 온통청년 정책 중 내 지역·나이에 맞고 마감 전인 것. 마감이 가까운 순서. 모든 항목에 "자격은 공고문 기준 확인 필요"가 붙는다(자격 판정은 하지 않을 것).
- **왜 내 일정이 여기 탭에 있나**: 공고 → 신청 계획으로 이어지는 흐름을 한 메뉴 안에서 보이려고 탭으로 붙였다. 같은 화면이 "내 일정" 메뉴에도 있다.

### 내 일정 (SC_060000_PG `/schedule`)
- **들어 있는 것**: 승인한 계획 목록(신청 준비 계획·대응 계획·재계약 판단 메모), 맨 위 계약 만료 알림(만료 2달 전부터), 상세의 체크리스트·출처 알림 링크
- **왜**: 승인만이 일정을 만든다. 일정마다 어느 알림에서 왔는지 링크를 달아 근거를 잃지 않게 했다. [IA SC, spec 013]

### 집 비교 (CP_040000~ `/compare`)
- **들어 있는 것**: 관심 주택 목록·등록, 실질 비용 비교(월세+관리비+에너지비+교통비), 추천 결과(실질 주거비 낮은 순위와 근거 글)
- **왜**: 월세만 보고 고르면 관리비·에너지비 때문에 실제 지출이 달라진다는 문제에서 나왔다. 에너지비를 모르면 한전 시군구 평균 등으로 **추정값**을 넣고, 추정 근거를 글로 붙인다. 추천은 점수 없이 "실질 주거비가 낮은 순"과 근거만 보여 준다(개인화 추천 점수는 하지 않을 것). [PRD FR-28, spec 009·015]

### 집 점검 (QC_100000~ `/qc`)
- **결로 위험 시뮬레이터**: 실내 온도·습도·바깥 기온·창 종류를 넣으면 바로 결로 위험을 계산한다. 저장하지 않는다. 내 집 실내 온습도가 있으면 미리 채워 준다.
- **입주 전 품질 점검**: 관심 주택을 골라 채광·소음·곰팡이·수압 같은 항목을 체크하고 메모한다. 안전 판정은 하지 않는다.
- **주거환경·하자 기록**: 실내 온습도 추이와 하자 기록(날짜·종류·메모·사진 1장).
- **건축물 기본 정보**: 번지를 넣으면 건축물대장(용도·구조·사용승인일·층수·내진설계)을 보여 준다. 넣은 주소는 저장하지 않는다.
- **왜**: "계약 전에 집 상태를 살피고, 사는 동안 결로·습기를 관리한다"는 한 목적으로 묶었다. [spec 004 FR-003·008, spec 019]

### 에너지 분석 (EN_110000~ `/energy`)
- **들어 있는 것**: 한 달 예상 전기 사용량(누진 1·2·3구간 막대 위에 내 위치), 월별 예상 전기요금 12개월, 냉난방비(도시가스) 시뮬레이션
- **왜**: 사용량을 모르는 집이 대부분이라 **추정값**을 기본으로 보여 주고, 무엇으로 추정했는지(한전 통계 월, 패널조사 보정)를 긴 설명으로 밝힌다. 누진 구간을 보여 주는 이유는 "구간이 오르면 단가가 비싸진다"를 한눈에 알게 하려는 것이다. [spec 011·016·017·018]

### AI 도우미 (KN_050000~ `/knowledge`)
- **들어 있는 것**: 기록 찾기(내가 처리한 알림에서 찾고, 답마다 출처 알림 링크), 처리 기록(승인·거절 끝난 알림), 공공데이터 출처(앱이 쓰는 출처와 이용 조건)
- **왜**: AI 답은 반드시 출처와 함께 보여야 한다는 팀 규칙 때문에 "찾기 + 근거 목록" 모양이다. 기상청 자료는 출처 표시가 이용 조건이라 출처 탭이 따로 있다. [CLAUDE.md 팀 작업 규칙, data-sources 2.6]

### 내 정보 (MY_030000~ `/my`)
- **들어 있는 것**: 내 집(기본 정보·계약·실질 주거비 칸을 접었다 펴는 묶음, 실내 온습도), 공고·정책 조건(지역·공급 유형·임대료 상한·나이), 관심 지역, 계정·알림(슬랙 알림 켜기, 로그아웃, 탈퇴)
- **왜**: 알림이 맞는지 틀리는지는 여기 입력값에 달려 있다. "입력이 너무 많고 보기 불편하다"는 사용자 요청(2026-11-18)으로 칸 묶음을 접고 "입력함 4/5"처럼 채운 정도를 글자로 보여 준다. 슬랙 알림은 **사용자가 직접 켠 경우에만** 가고, 켜는 것이 곧 승인이다.

### 첫 설정 (MB_010200_PG `/onboarding`)
- 가입 직후 한 번, 공고·정책 조건과 내 집(또는 관심 지역)을 받는다. 건너뛰면 홈 맨 위에 입력 카드가 뜬다. [IA 유저 플로우]

### 관리자 (AD_070000~ `/admin`)
- 회원, 수집 현황(연속 실패·"지금 한 번 실행"), 사건 현황, 흐름 화면(수집 → 사건 → 승인 대기 상자 그림), 시뮬레이터(가짜 자료로 전체 흐름 시연), 채점 결과(맞힘·놓침·잘못 울림), 위키 챗봇
- **왜**: 평가 시연과 운영 점검용이다. 관리자도 사용자 대신 승인할 수 없다. 흐름 화면 색(성공 초록 실선, 실패 빨강, 승인 대기 주황 점선, 안 켜짐 회색)은 정해진 규칙이고 글자 라벨이 함께 붙는다. [CLAUDE.md 디자인]

## 4. 지금 화면이 한눈에 안 들어오는 이유 (2026-11-19 화면을 보고 정리)
새 디자인에서 풀어야 할 점이다. 판단이 들어간 관찰이니 그대로 따를 필요는 없다.

1. **메뉴가 할 일 순서가 아니다.** 메뉴가 기획안 순서라서, 가장 자주 쓸 "위험·기회 알림"이 6번째에 있고 집 비교·집 점검·에너지가 앞에 있다. 사용자의 주 동선(알림 → 승인 → 일정)이 메뉴에서 보이지 않는다.
2. **같은 화면이 두 메뉴에 있다.** 맞춤 공고와 내 일정이 "청년 정책" 탭 안에도 있어서 위치가 헷갈린다.
3. **설명 글이 본문을 차지한다.** 화면마다 맨 위 설명문이 길고, 추정 근거(통계 이름·기준 달) 문단이 본문과 같은 크기로 보인다. 화면 글에 "(PRD FR-28)" 같은 문서 번호도 그대로 보인다.
4. **홈 카드의 무게가 모두 같다.** 처리할 것(승인 대기, 새 알림)과 참고 정보(날씨, 주거 정보)가 같은 크기·같은 색이다. 0건일 때 다음에 무엇을 하라는 안내도 약하다.
5. **다음 행동 버튼이 잘 안 보인다.** 대부분 글자 링크라서, 화면마다 "이 화면에서 할 일 하나"가 드러나지 않는다.
6. **시각 위계가 약하다.** 흰 카드 + 회색 글 + 파랑 링크가 전부라서, 위험(빨강)·기회(주황)·정보(파랑)의 구분이 화면에서 잘 느껴지지 않는다. 아이콘은 사이드바에만 있다.

## 5. 새 디자인에서도 지켜야 하는 것
디자인을 바꿔도 아래는 그대로 둔다. 바꾸려면 원문 문서(PRD·IA·CLAUDE.md)를 먼저 고쳐야 한다.

- **용어** (IA 용어 정의): "위험·기회 알림"(그냥 "알림"이나 "이벤트"로 쓰지 않음), "맞춤 공고"("추천"이라 쓰지 않음), "슬랙 알림", "월 예상 주거비"(월세+관리비)와 "실질 주거비"(에너지비·교통비까지)는 다른 말, "측정값/추정값", "관심 주택/관심 지역/내 집"은 섞지 않음, "수집 오류"
- **승인 버튼은 사람이 누른다.** 자동 승인처럼 보이는 디자인은 안 된다. 거절에는 사유 칸이 있다.
- **자격 판정 안 함**: 공고·정책에는 "자격은 공고문 기준 확인 필요"를 남긴다.
- **AI 답과 추정값에는 출처·근거를 붙인다.** 접어 두는 것은 괜찮지만 없애면 안 된다. 기상청 자료는 출처 표시가 이용 조건이다.
- **측정값과 추정값은 한 화면에서 구분해 보인다.**
- **하지 않을 것**은 화면에 넣지 않는다: 개인화 추천 점수, 전세사기 판정, 하자 예측, 앱 푸시·카카오톡 알림 등(CLAUDE.md "하지 않을 것").
- **디자인 기본선 7가지** (`.claude/rules/design.md`): 색·간격·글꼴은 토큰 한곳에, Pretendard, 명암비 4.5:1, 키보드 조작과 초점 표시, 상태는 색과 글자를 함께, 375px에서 가로 스크롤 없음, 빈 화면·불러오는 중·오류 상태
- **현재 정해진 취향** (CLAUDE.md 디자인, 2026-11-17 사용자 선택): 신뢰 파랑 미니멀 + 홈만 벤토, 기준 색(primary `#2563EB`, accent `#EA580C`, 위험 `#DC2626` 등), 금액·건수는 자릿수 맞춤. 새 디자인으로 바꾸면 CLAUDE.md 디자인 절도 같이 고친다.

## 6. Claude Design에 넘길 때
- 이 문서와 함께 화면 캡처를 넘기면 좋다. 추천 화면: 홈, 위험·기회 알림 상세, 맞춤 공고, 집 비교 실질 비용 비교, 에너지 분석, 내 정보 → 내 집, 휴대폰 폭(375px) 홈.
- 요청 예: "메뉴를 사용자 할 일 순서로 다시 묶고, 홈에서 처리할 것(승인 대기·새 알림)이 가장 먼저 보이게. 5절은 지킬 것."
