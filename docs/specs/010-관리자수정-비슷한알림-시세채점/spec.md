## 1. 해결하려는 문제
- 채점(감지 맞히기)에 공고·습도만 있어 시세 알림이 맞게 울리는지 숫자로 보일 수 없다. 시연 장면 7과 발표 "채점" 장이 사건 세 종류 중 둘만 보여 준다. [demo-order 장면 7] [P3-06]
- 새 알림을 볼 때 내가 예전에 비슷한 알림을 어떻게 처리했는지 따로 기록 찾기 화면에 가서 찾아야 한다. [PRD FR-18 "새 사건에서 비슷한 과거 사건"] [P3-05]
- 관리자는 회원 입력을 읽기만 할 수 있다. 회원이 잘못 넣은 값을 고쳐 줄 길이 없고, 고친다면 누가·언제·왜 고쳤는지 남아야 한다. [PRD FR-20] [spec 005 Q1] [P3-13]

## 2. 주요 사용자
- 관리자(팀): 채점 결과로 감지가 맞는지 보이고(P1), 회원 입력을 사유와 함께 고친다(P3)
- 회원(준비형·자취형): 알림 상세에서 비슷한 지난 처리를 근거로 본다(P2)

## 3. 핵심 기능과 요구사항
### FR-001 시세 채점 묶음 (P1) [PRD FR-25] [IA AD_070600_TB] [spec 008 규칙]
정답이 붙은 가짜 시세 묶음을 채점에 더한다. 정답은 spec 008의 규칙(같은 조건 거래 5건 이상, 기준 대비 10% 이상 변화, 전용면적 ±20%)과 경계 상황에서 가져오고, 감지 코드에서 만들지 않는다. 내 집(계약 월세·보증금 기준)과 관심 지역(지난 중앙값 기준)을 모두 넣는다. 결과는 지금처럼 파일(`eval/results.json`)과 관리자 채점 화면에 종류별(공고·습도·시세)로 보인다.
### FR-002 알림 상세의 비슷한 지난 알림 (P2) [PRD FR-18] [IA IC_020100_PG]
알림 상세에 "비슷한 지난 알림"을 최대 3건 보인다. 같은 회원이 승인·거절로 끝낸 알림 중 같은 종류이고 제목 낱말이 하나 이상 겹치는 것만, 많이 겹치는 순(겹침 0건은 보이지 않음, PR #11 리뷰로 고침 2026-11-18). 줄마다 제목, 처리 결과(승인/거절과 사유), 처리한 날, 그 알림으로 가는 링크. 없으면 "비슷한 지난 알림이 없습니다." 지금 보고 있는 알림은 빼고, 남의 알림은 보이지 않는다. AI를 부르지 않는다.
### FR-003 관리자 수정과 수정 기록 (P3) [PRD FR-20] [IA AD_070102_MD] [ERD audit_logs]
관리자는 회원 상세에서 회원의 입력(Q1에서 정한 표)을 고칠 수 있다. 사유는 필수(2~200자). 고치면 담당자, 시각, 고친 표·행, 고치기 전·후 값, 사유가 수정 기록에 쌓이고, 수정과 기록은 함께 되거나 함께 안 된다. 회원 상세에 그 회원의 수정 기록 목록을 보인다. 관리자에게 알림 승인·거절 버튼은 여전히 없다. 수정 기록은 지우거나 고칠 수 없다.

### 하지 않을 것
- 관리자가 대신 승인·거절, 알림·일정 직접 수정 (CLAUDE.md 팀 작업 규칙 "관리자도 승인을 건너뛰지 못한다")
- 임베딩(벡터) 찾기: ERD Q1(차원·모델) 미정이라 기록 찾기와 같은 낱말 겹침을 쓴다
- 시세 실제 API를 채점에서 부르기(채점은 가짜 묶음만, 시험·Ralph Loop는 실제 API 안 부름)
- PRD 9절 하지 않을 것 전부

## 3-1. 경계·예외
- E1 시세 거래 4건(기준 5건 미만) → 울리지 않음(거래 부족)
- E2 거래 5건, 중앙값이 기준보다 정확히 10% 높음 → 울림 / 9% → 울리지 않음
- E3 중앙값이 기준보다 10% 이상 낮음 → 울림(내림도 변화)
- E4 거래는 많지만 전용면적이 ±20% 밖이라 같은 조건이 4건 이하 → 울리지 않음
- E5 다른 주택 유형·다른 계약 형태(전세/월세)의 거래만 있음 → 울리지 않음
- E6 관심 지역의 지난 중앙값이 없음(처음 수집) → 울리지 않고 기준만 저장
- E7 월세는 그대로, 보증금만 10% 이상 오름 → 울림
- E8 비슷한 지난 알림이 1건도 없음 → 빈 문구. 지금 알림만 끝난 상태 → 자기 자신은 빼서 0건
- E9 다른 회원의 끝난 알림 → 비슷한 알림에 나오지 않음(권한)
- E10 관리자 수정 사유 비움·1자·201자 → 저장 안 됨, 칸 아래 이유
- E11 관리자 수정 중 기록 쓰기 실패 → 수정도 되돌려짐
- E12 관리자가 아닌 회원이 수정 함수를 부름 → 거절, 아무것도 바뀌지 않음
- E13 바뀐 값이 없는 수정 → 저장하지 않고 "바뀐 내용이 없습니다"

## 4. 성공 기준
- **SC-001**: 채점 결과에 시세 묶음이 종류별로 들어가고, E1~E7 사례가 모두 정답과 같다(놓침 0, 잘못 울림 0).
- **SC-002**: 끝난 알림이 있는 회원의 알림 상세에 비슷한 지난 알림이 최대 3건 링크와 함께 보이고, 없으면 빈 문구가 보인다(E8·E9).
- **SC-003**: 관리자가 사유와 함께 회원 입력을 고치면 회원 화면에 바뀐 값이 보이고, 회원 상세의 수정 기록에 담당자·시각·전후 값·사유가 한 줄 생긴다(E10~E13).
- **SC-004**: 새·바뀐 화면이 375px에서 가로로 넘치지 않는다.
