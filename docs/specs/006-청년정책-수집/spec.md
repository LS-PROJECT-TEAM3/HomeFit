# spec: 온통청년 주거 정책 수집과 청년 주거지원 정책 화면

- 기능 ID: 006

- 작성일 / 최종 갱신: 2026-11-18 / 2026-11-18
- 근거 문서: docs/PRD.md v1.8(FR-07, FR-15 자격 안내, 9절 하지 않을 것), docs/ERD.md(source_items `youth_policy`, sources, runs, run_steps, observations), docs/Intent.md Q6, spec 004(정책 화면 뼈대), CLAUDE.md 팀 작업 규칙
- 다음 문서: plan.md, qa.md

## 1. 해결하려는 문제
사회초년생은 지역마다 흩어진 청년 주거 정책(월세·전세 대출이자·보증금 지원 등)을 직접 찾아야 해서, 문구가 어렵거나 늦게 알아 지원금을 놓친다(P04 예산 소진, P01 거주지 조건). [PRD 2절-1] 온통청년 정책 수집(PRD FR-07, Must)은 키가 없어 막혀 있었고, 정책 화면은 뼈대뿐이다. [spec 004] [Intent Q6]

## 2. 주요 사용자
- 일반 사용자(준비형 사회초년생): 내 지역·나이에 맞는 청년 주거 정책을 한곳에서 본다 (P1) [PRD 4절]
- 관리자: 정책 수집이 매일 도는지, 실패했는지 본다 (P1) [PRD FR-21]

## 3. 핵심 기능과 요구사항
### FR-001 온통청년 주거 정책 하루 1번 수집 (P1) [PRD FR-07] [ERD source_items]
시스템은 온통청년 정책 중 대분류 "주거"를 하루 1번 모두 받아(2026-11-18 기준 424건, 5쪽), 정책 ID(`plcyNo`)로 한 건씩 `source_items`(`youth_policy`)에 저장해야 한다. 마이홈과 같은 모양으로 저장하고(제목·지역·신청 기간·원문 링크), 나이·지역 목록·지원 내용은 원본(raw)에 둔다. 실행은 runs·run_steps에 남는다.
### FR-002 수집 실패는 수집 오류 (P1) [PRD FR-06·07 "변화 없음"으로 쓰지 않음] [CLAUDE.md 팀 작업 규칙]
응답 코드가 정상이 아니거나 형식이 다르면 실행을 실패로 기록하고, 저장된 정책은 그대로 둔다. 오류 문구에 키 값이 보이지 않는다.
### FR-003 청년 주거지원 정책 화면 (P1) [PRD FR-07] [spec 004 정책 뼈대]
사용자는 "직장과 정책 → 청년 주거지원 정책"에서 자기 조건(시도·시군구, 나이)에 맞는 정책을 본다. 지역: 정책의 지역 목록에 내 시군구가 있으면(시군구가 없으면 시도가 같은 지역이 있으면) 맞음. 나이: 정책에 나이 범위가 있고 내 나이가 있으면 범위 안일 때만 맞음. 신청이 끝난 정책은 빼고, 신청 마감이 가까운 순, 상시 신청은 그 뒤에 둔다. 한 줄마다 정책 이름, 운영 기관, 신청 기간(또는 "상시"), 나이 범위, 원문 링크를 보이고, 자격은 판정하지 않고 "자격은 공고문 기준 확인 필요"로 안내한다.
### FR-005 같은 이름 정책은 한 줄 (P1) [사용자 요청 2026-11-18 "같은 정책 두 번 반복"]
같은 정책을 시도·시군구가 따로 올려 이름이 같은 정책이 여러 건 있다(예: "전세보증금반환보증 보증료 지원" 7건). 띄어쓰기를 빼고 이름이 같으면 한 줄만 보인다. 고르는 순서: 내 지역용(전국용이 아닌 것) → 마감이 늦은 것 → 최근 등록. 묶인 수를 "같은 이름 정책 N건"으로 알린다.
### FR-006 종류로 거르기 (P1) [사용자 요청 2026-11-18 "주거인지 대출인지"]
전체 / 대출·이자 / 월세·전세 지원 / 주택·거주 / 기숙사로 거른다. 온통청년 중분류(전월세 및 주거급여 지원, 주택 및 거주지, 기숙사)와 이름·키워드(plcyKywdNm)의 "대출·이자" 낱말로 읽는다. 한 정책이 여러 종류일 수 있다. 고른 종류는 주소(?kind=)에 남는다.
### FR-007 정책 상세와 요약 (P1) [사용자 요청 2026-11-18 "눌렀을 때 대략적인 설명이랑 요약"] [IA PL_090100_PG]
목록에서 정책을 누르면 정책 상세가 열린다. 원문 값(정책 설명, 지원 내용, 신청 기간, 나이, 신청 방법, 심사 방법, 제출 서류, 추가 자격·참여 제한, 운영 기관)을 칸마다 보이고, 맨 위에 AI 요약(2~3문장: 무엇을 지원하는지, 누가, 어떻게 신청하는지)을 둔다. 요약은 처음 연 사람이 한 번 만들고 저장해 모두가 같이 쓴다(공고 요약과 같은 표). 요약은 원문 값만 근거로 하고 자격은 판정하지 않는다. AI 실패 때도 원문 값과 원문 링크는 보인다.
### FR-004 관리자 화면에 정책 출처 (P2) [PRD FR-21, FR-23]
수집 현황(연속 실패 수·지금 한 번 실행)과 흐름 화면 시작 상자에 "온통청년 정책"이 보인다.

### 하지 않을 것
- 정책 변화 사건·알림·팔로우(팔로우 표가 공고 전용이라 ERD 변경이 필요 → Q1), AI 요약
- 자격 자동 판정, 정책 예산 소진 감지, 정책 페이지 긁어 오기, 개인화 추천 점수 (PRD 9절)
- 정책 시뮬레이터 가짜 묶음(Q2)

## 3-1. 경계·예외
- E1 신청 기간이 비어 있음(상시 또는 미정) → 마감 없음으로 보고 "상시·공고문 확인"
- E2 신청 기간이 두 개(`A ~ B\NC ~ D`) → 가장 늦은 끝날을 마감으로
- E3 나이 0~0 → 나이로 거르지 않음, "나이 제한 공고문 확인"
- E4 지역 목록이 비어 있음 → 전국으로 봄
- E5 사용자 조건이 없음 → "조건을 입력하면 보입니다" 빈 화면
- E6 응답 오류 코드·HTML 응답 → 수집 오류, 기존 정책 유지
- E7 같은 정책 ID가 두 번 옴 → 한 건만
- E8 인증 없이 수집 입구 호출 → 401

## 4. 성공 기준
- SC-001: 운영에서 정책 수집을 한 번 돌리면 실행이 성공으로 남고 주거 정책 400건 이상이 저장된다.
- SC-002: 경계 E1~E7이 함수 시험으로 통과한다.
- SC-003: 내 조건(시도·나이)으로 정책 화면을 열면 맞는 정책만, 마감 가까운 순으로 보이고 각 줄에 원문 링크와 "공고문 기준 확인 필요"가 있다.
- SC-004: 수집 현황·흐름 화면에 온통청년 정책이 보이고 지금 한 번 실행이 된다.
- SC-005: 새 화면이 375px에서 가로로 넘치지 않는다.

## 5. 제외 범위
정책 사건·알림, 정책 팔로우, AI 요약, 정책 가짜 묶음.
