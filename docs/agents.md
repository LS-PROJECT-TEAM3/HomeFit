# 서브에이전트·스킬 활용 기록

출처: 안내서 7절(서브에이전트), 8절·하네스 절(스킬), 평가항목 P3-24·P3-25.
기준일: 2026-11-18 (main `65ed611`).

**서브에이전트**는 메인 Claude가 일을 나눠 맡기는 별도의 도우미로, 자기 작업창에서 따로 일하고 결과만 돌려준다. 이 문서는 팀이 **실제로 쓴 것만** 적는다. 쓰지 않은 것을 채우지 않았고, 확인하지 못한 곳은 `확인 필요`로 둔다.

## 1. 서브에이전트

`.claude/agents/`(직접 만든 서브에이전트 설정)는 이 저장소에 **없다**. 아래는 그때그때 Claude가 띄운 도우미다.

### 1.1 AI 페르소나 인터뷰 검증 도우미 3명 (선우)
| 칸 | 내용 |
|---|---|
| 이름과 역할 | 이름 없는 Claude 도우미 3명. 만드는 쪽(인터뷰를 진행한 Claude)과 **검증하는 쪽을 나눴다**. 역할은 "AI가 지어낸 답이 질문지나 진행자가 덧붙인 문장에 이끌린 것인지 확인" |
| 맡긴 일 | 서로 모르는 도우미 3명에게 같은 인물 설정으로 다시 인터뷰를 시켰다. 같은 지시 반복 1회, 인물 설정 원문만 주고 예시 목록과 공공임대 질문을 뺀 질문지 2회 |
| 받은 결과 | 네 번(원래 인터뷰 포함) 모두 나온 장면 4개(사진과 실제 채광 차이, 늦게 연락해 놓친 전세, 등기부등본을 봐도 모름, 낮에는 방음을 알 수 없음), 세 번 나온 장면 2개(관리비가 따로 붙음, 전세대출을 늦게 알아봄) |
| 사람이 확인한 것 | 선우가 검증을 요청하고 결과를 읽었다. 결론은 "질문지 예시가 이끈 것은 아니지만, 네 번의 답이 지나치게 비슷하다 = 인물 설정을 AI가 늘 같은 이야기로 풀어 쓴 것". 그래서 이 기록은 사람 수와 빈도의 근거로 세지 않고 "한 가지 가설"로만 쓰기로 했다 |
| 잘 안 된 점과 고친 것 | 답이 너무 비슷해서 AI 인터뷰만으로는 근거가 되지 않는다는 것이 드러났다. 고친 것: `interviews/종합.md`에서 이 기록을 사람 수에서 빼고 "가상 인물, 4번 물어도 같은 이야기"라고 표시 |
| 근거 | [A01 기록의 "검증 메모"](../interviews/2026-11-17-A01-가상인물-설비관리신입.md), [종합.md](../interviews/종합.md) |

### 1.2 코드 리뷰 도우미 "별도 리뷰어" (기능 001 12단계, 예림)
| 칸 | 내용 |
|---|---|
| 이름과 역할 | Claude에 기본으로 있는 **general-purpose 서브에이전트**. 직접 만든 설정은 아니다. 같은 Claude 창에서 2026-11-17 20:58에 불렀다(다른 창이 아님). 역할은 만든 쪽(메인 Claude)과 **분리된 검토자** (예림님 답 2026-11-18). qa·plan에는 "별도 리뷰어"로 적혀 있다 |
| 맡긴 일 | 기능 001 12단계 마무리 코드 리뷰. **"고치지 말고 보고만"** 조건으로 맡김 |
| 받은 결과 | 지적 5건. 꼭 고칠 것 0, 고치면 좋은 것 2, 있으면 좋은 것 3 (qa 001 변경 기록) |
| 사람이 확인한 것 | plan 001은 "지적 1·2·4·5 고침, 3은 제안", qa 001 "실패와 조치" #14~#17이 고친 내용. 누가 확인했는지는 기록에 없음 |
| 잘 안 된 점과 고친 것 | 고친 것: 새 공고 값을 사건·계획보다 먼저 덮어써 변화를 놓칠 수 있던 문제, 단지마다 사건·DM이 가는 문제, 수집이 300초를 넘길 때 실행 기록이 "도는 중"으로 남는 문제, 슬랙 사람 ID를 API로 바꿀 수 있던 문제 |
| 근거 | `docs/specs/001-공고정책-사건/plan.md` 222줄, `qa.md` 실패와 조치 #14~#17 |
| 기록이 서로 다른 곳 | qa 001 변경 기록은 "2번은 결정 필요, 3·4번 제안"이고, 같은 qa의 실패와 조치는 2번(#16)·4번(#17)을 고친 것으로 적었다. plan 001은 "1·2·4·5 고침"이라 최종은 후자로 보이나 확인 필요 |

## 2. 스킬 (P3-24)
저장소 `.claude/skills/`에 스킬 10개가 들어 있다. **harness-* 7개**(erd, ia, intent, journeys, prd, qa, spec-plan)와 **그 밖 3개**(domain-modeling, grill-with-docs, grilling)다.

"쓴 흔적"은 저장소에 남은 산출물이다. 산출물이 있다고 해서 누가 어떤 입력으로 스킬을 불렀는지가 확인된 것은 아니라서 그 칸은 `확인 필요`로 둔다.

| 스킬 | 쓴 흔적(산출물) | 누가·어떤 입력으로 |
|---|---|---|
| grill-with-docs, grilling, domain-modeling | `docs/문제정의.md`, `GLOSSARY.md`, `docs/adr/` 3개, 인터뷰 종합 | 확인 필요 |
| harness-ia | `docs/IA.md`, `docs/IA.xlsx`, `docs/IA-screens.json`. IA.md 맨 위에 스킬 스크립트 `build_ia_workbook.py`로 엑셀을 다시 만드는 명령이 적혀 있음 | 확인 필요 |
| harness-journeys | `docs/journeys/` (여정 지도, 핵심 여정 4개, 명세, 예외 경로) | 확인 필요 |
| harness-prd | `docs/PRD.md` | 확인 필요 |
| harness-erd | `docs/ERD.md` | 확인 필요 |
| harness-intent | `docs/Intent.md` | 확인 필요 |
| harness-spec-plan | `docs/specs/NNN-기능/spec.md`, `plan.md` 8묶음 | 확인 필요 |
| harness-qa | `docs/specs/NNN-기능/qa.md` 8묶음. plan 001의 단계표에 "`harness-qa` B·C"가 적혀 있음 | 확인 필요 |

### 2.1 저장소 밖 스킬
- **ponytail-review** (코드 검토 스킬): qa 001에 7곳, qa 003에 1곳 언급. 이 스킬은 저장소 `.claude/skills/`에 **없다**(전역 스킬). 어떤 입력으로 어떤 결과를 얻었는지는 qa 표에 남아 있다(qa 001 실패와 조치 #1, #11~#13의 "ponytail-review 지적"). 누가 불렀는지는 확인 필요.
- `humanize-korean`, `ui-ux-pro-max`, `web-design-guidelines`, `code-review`, `simplify` 등 `.claude/rules/`가 부르는 다른 스킬도 저장소에 없다. 실제로 썼는지는 기록에서 찾지 못했다.
- 현경님(`gaangstar`) PC 기록에는 Skill 도구로 스킬을 부른 기록이 없다.
- 서윤님(`lilyoon333`) PC에서는 harness-* 스킬을 직접 부른 기록을 확인하지 못했다(기억 안 남). `ponytail-review`는 서윤님 PC에 개인 플러그인으로 있고 프로젝트 2 작업 기록에는 있으나, HomeFit에서 직접 썼는지는 기억 안 남.
