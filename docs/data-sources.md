# 데이터 출처

출처: 안내서 3절 "데이터 모으기, 저장, 자동화", 평가항목 P3-02·P3-33. 이 문서는 **코드와 설정에서 확인한 사실만** 적는다. 코드나 문서에서 확인하지 못한 것은 `확인 필요`로 둔다.
기준일: 2026-11-18 (main `65ed611`). 그 뒤 예림님이 spec 011·016~018·020의 출처를 더했다(PR #16, #19). 2026-11-19 main `32444a4`에서 1절 표 11줄이 앱의 "공공데이터 출처" 화면과 같은 것을 확인했다(화면은 격자 좌표와 "내가 넣은 값"을 더해 13줄).

## 2. 출처별 자세히

### 2.1 마이홈 공공임대 모집공고 (`myhome_notice`)
- 주소: `apis.data.go.kr/1613000/HWSPR02/rsdtRcritNtcList` (`watch/myhome.server.ts`)
- 읽는 법: 목록을 한 쪽에 100건씩, 최대 20쪽(2,000건)까지 차례로 받는다.
- 저장: 공고마다 `source_items`에 저장하고, 내용이 바뀌었는지는 `content_hash`로 비교한다. 접수 기간·월 임대료·공급 유형이 바뀌거나 정정공고가 올라오면 사건 후보가 된다.
- 응답 칸 확인: 공고 ID·공고일·신청 기간·공급 유형·임대료·지역 코드·원문 링크 칸이 있는지(spec 001 Q6)를 2026-11-17 실제 응답으로 확인했다고 변경 기록에 적혀 있다(`docs/specs/001-공고정책-사건/spec.md` v0.1, `plan.md` v0.3). 칸별 결과는 spec Q6 참고.
- 한 쪽이라도 못 읽거나 해석하지 못하면 그 실행 전체를 실패로 기록한다.
- 한도·약관: 2.6절 참고.

### 2.2 온통청년 주거 정책 (`youth_policy`)
- 주소: `www.youthcenter.go.kr/go/ythip/getPlcy` (`watch/youth-policy.server.ts`), 쓰는 키는 `YOUTH_POLICY_API_KEY`.
- 읽는 법: 정책 대분류가 "주거"인 것을 한 쪽 100건씩, 최대 20쪽까지 받는다.
- 응답 확인: 2026-11-18 실제 응답 424건으로 칸을 확인하고 spec을 썼다(`docs/specs/006-청년정책-수집/spec.md` 변경 기록 v0.1).
- 한도·약관: 2.6절 참고.

### 2.3 기상청 단기예보 (`kma_forecast`)
- 주소: `apis.data.go.kr/1360000/VilageFcstInfoService_2.0/getVilageFcst` (`watch/kma.server.ts`)
- 읽는 법: 사용자가 등록한 내 집의 시군구를 기상청 격자 좌표로 바꿔(`watch/kma-grid.json`) 시군구마다 한 번씩 부른다. 한 번에 1,000줄, 응답을 기다리는 시간은 15초. 시군구 정밀 좌표가 없으면 대체 좌표를 쓰고 그 수를 기록한다.
- 쓰는 값: 시간별 기온·습도 등으로 앞으로 48시간의 결로 위험을 계산한다(`incident/humidity-detect.ts`).
- 한도·약관: 2.6절 참고.

### 2.4 전월세 실거래가 (`rtms`)
- 주소: `apis.data.go.kr/1613000/` 아래 주택 유형별 API 4개 (`watch/rtms.server.ts`)
- 읽는 법: 시군구 코드(`LAWD_CD`)와 계약 년월(`DEAL_YMD`)로, 지난달부터 거슬러 3개월(`recentDealMonths`)을 한 쪽 1,000건씩 최대 10쪽 받는다. 대상은 사용자의 내 집과 관심 지역이다.
- 응답 확인: 2026-11-18 실제 응답(대전 서구 2026-10, 4개 API)으로 칸을 확인했다(`docs/specs/008-시세-변화-사건/spec.md` 변경 기록 v0.1).
- 한도·약관: 2.6절 참고.

### 2.5 법정동코드, 건축HUB

- **기상청 자료는 출처표시가 조건**이다. 앱의 알림 상세와 "공공데이터 출처" 화면에 "기상청 단기예보"로 출처를 적고 있다.
- **트래픽·심의유형은 포털 페이지에 나온다**(브라우저로 열면 보이는 칸, 2026-11-18 다시 확인, PR #11 리뷰 lilyoon333 지적으로 고침). 처음에는 페이지 글을 기계로 읽어 이 칸이 보이지 않아 "공개 페이지에 없다"고 잘못 적었다. 단위는 페이지에 없지만 같은 페이지 오류 안내가 "일일 호출 허용량"이라 하루 기준으로 본다.
- **마이홈(15108420)은 하루 1,000건**(개발계정)이다. 포털 페이지 값이고 예림님이 마이페이지에서 다시 확인했다(2026-11-18). 처음에 "API마다 10,000건"으로 적은 것은 마이홈 행을 확인하지 못한 것이었다. 나머지 공공데이터포털 API는 10,000건이다. 지금 마이홈 쓰는 양은 하루 최대 20번이라 넉넉하다.
- 지금 쓰는 양은 한도보다 훨씬 적다(2026-11-18 운영 DB 기준: 내 집 시군구 4곳, 시세 대상 시군구 4곳). 마이홈은 하루 최대 20번(100건 × 20쪽), 기상청은 하루 8번(시군구 4곳 × 2회), 실거래가는 한 달에 API마다 12번(시군구 4곳 × 3개월 × 1쪽), 법정동코드는 30일 저장, 건축HUB는 사용자가 조회할 때만이다. 한도는 API마다 따로 센다.
- **온통청년**: 공공데이터포털 15143273은 제공형태가 "LINK"라 포털이 직접 주는 API가 아니고 온통청년으로 연결하는 항목이다. 온통청년 안내 페이지는 "회원 전용 서비스", "담당자 심사를 통해 승인 후 인증키가 발급"이라고 적고 있고, 하루 한도는 적혀 있지 않다. 포털 페이지도 운영단계를 "심의승인"으로 적는다. 예림님 키는 **심의를 거쳐 승인**받았고, 승인된 화면에도 하루 한도는 나오지 않는다(예림님 확인, 2026-11-18). 지금 쓰는 양은 하루 최대 20번(100건 × 20쪽)이다. 코드가 온통청년 주소와 별도 키(`YOUTH_POLICY_API_KEY`)를 쓰는 것과 맞는다. 코드가 쓰는 주소(`/go/ythip/getPlcy`)는 안내 페이지에서 직접 확인하지 못했다.
- **한국전력 가구평균 전력사용량**(spec 011): 집 비교·에너지 분석에서 사용량을 모르는 집의 시군구 평균(kWh)을 불러온다. 화면을 열 때 부르고 시군구·날짜마다 하루 동안 기억하므로 호출은 하루에 시군구마다 많아야 2번(전전월, 없으면 그 전 달)이다. 키는 `KEPCO_API_KEY`(서버 환경변수). 통계가 없는 달은 HTTP 404로 와서 "없음"으로 처리하고, 키·네트워크 오류는 그 집 에너지비를 추정하지 않고 화면에 알린다.
- 건축HUB 페이지는 갱신 주기가 "월간"이라 조회한 건축물 정보가 최근 변경을 담지 못할 수 있다.

## 3. 사건 쪽으로 넘기는 같은 모양
수집한 값은 출처가 달라도 `observations` 표에 같은 칸으로 저장한다.

| 안내서 칸 | 표 칸 |
|---|---|
| 시각 | `observed_at` |
| 대상 | `target` |
| 지표 | `metric` |
| 값 | `value_numeric`, `value_text` |
| 바뀐 정도 | `change_amount` |
| 출처 | `source_code` (`sources` 표) |

원본 응답은 `raw`에, 시뮬레이터가 만든 값인지는 `is_simulated`에 남긴다. 공고·정책은 같은 변화를 두 번 사건으로 만들지 않도록 `source_items`의 `content_hash`와 `external_id`로 먼저 비교한다.

## 4. 실패 처리
- 읽기에 실패하면 "변화 없음"이 아니라 **수집 오류**로 기록한다. 해당 실행(`runs`)은 `failed`로, 실패한 단계(`run_steps`)는 `collect`로 남고 `error_message`에 이유가 적힌다. 키와 비밀 값은 가려서 적는다(`watch/mask.ts`).
- 응답이 JSON이 아니면(키 오류 등으로 XML이 올 때) 읽기 오류로 처리한다.
- 시세 수집은 시군구·주택 유형마다, 날씨 수집은 시군구마다 읽는다. 일부만 실패하면 실패한 곳은 목록으로 남기고 나머지로 계속하며(시세는 실패한 곳의 대상을 이번에 판단하지 않아 거래 0건으로 오판하지 않는다), 하나도 못 읽으면 실행 전체를 실패로 기록한다. 마이홈과 온통청년은 한 쪽이라도 실패하면 실행 전체가 실패다.
- 관리자 화면 "수집 현황·오류"에서 출처별 마지막 실행과 **연속 실패 횟수**를 본다(`watch/run-health.ts`). "지금 한 번 실행"으로 바로 다시 돌릴 수 있다.
- 정기 실행 입구는 `CRON_SECRET`이 맞는 요청만 받는다.
- 실패한 호출을 자동으로 다시 부르는 재시도와, 요청 사이의 대기 시간은 수집 코드에 두지 않았다. 쪽과 시군구를 차례로 부르고, 실패하면 위처럼 기록한다. (AI 호출의 재시도는 별개이며 `docs/specs/002-LLM-공급자/spec.md`에 있다.)

## 5. 실수집과 가상 데이터 구분
- **정기 실행**(운영)은 위 출처를 모두 실제 API로 읽는다. 정기 실행 입구에 가짜 응답을 붙이는 길(`?fixture=`)은 운영에서 막혀 있고 개발 환경에서만 된다.
- **관리자 시뮬레이터**는 운영에서도 가짜 묶음을 돌린다(`app/(main)/admin/actions.ts`의 `runSimulation`, 관리자만). 이때 실행은 `simulation`으로 기록되고, 사건·알림은 `SIMULATION_USER_IDS`에 적힌 **가상 계정에만** 생긴다. 목록이 비어 있으면 아무에게도 생기지 않는다(`watch/simulation.ts`).
- 가짜 자료는 세 가지다.
  - 가짜 마이홈 묶음 `sample`, `changed`, `malformed`, `failure`, `bulk`, `fresh`, `correction`, `relaxed`, `extended`, `later`, `bulk-changed` (`watch/sim-fixtures.ts`)
  - 가짜 날씨 `cold`, `colder`, `humid`, `safe`, `failure`, `malformed` (`watch/weather-fixtures.ts`)
  - 가짜 시세 거래 `rise`(같은 조건 거래 6건, 기준보다 20% 높음 → 알림), `few`(거래 3건뿐 → 거래 부족, 알림 없음), `failure`(API 오류 → 수집 오류) (`watch/rent-fixtures.ts`)
- 시세 시뮬레이터에는 가짜가 아닌 **실제 모드 `live`**도 있다. 국토부 API의 진짜 거래를 받아 가상 계정의 집·관심 지역에만 비교한다. 실제 API를 부르므로 호출 한도를 쓴다.
- 시뮬레이터가 만든 값은 `observations.is_simulated`가 켜진다.
- 저장해 둔 샘플은 `watch/fixtures/`에 있다.

| 파일 | 내용 |
|---|---|
| `myhome-sample.json` | 2026-11-17 마이홈 실제 응답에서 3건만 남긴 시험 자료(파일 안 `note`에 적힘). 공개 공고 정보이며 개인 정보 없음 |
| `kma-sample.json`, `building-sample.json`, `region-sample.json` | 날짜(2026-11-17)와 결과 코드로 보아 실제 응답을 저장한 것으로 보인다(예림님 확인, PR #5 리뷰). 파일 안 메모는 예림님이 다음 PR에서 넣기로 함 |
