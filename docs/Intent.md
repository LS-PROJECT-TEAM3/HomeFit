## 1. 문제 (Problem)
- 사회초년생은 집을 구하거나 혼자 사는 동안 자기 조건에 맞는 주거 지원 공고·정책, 날씨로 커지는 습도·결로 위험, 주변 전월세 시세 변화를 늦게 알아 지원금·기회, 곰팡이를 막을 시간, 재계약 판단 근거를 잃는다. [문제정의 한 줄 문제]
- 기존 알림 앱은 팔로우한 공고만 알려 주고, 정책 문구가 어려워 넘긴다. 지원금 30만 원 정도를 놓친 사례가 2건 있다. [PRD 2절-1] [UJ 여정 지도 2단계]
- 곰팡이는 눈에 띌 때까지 모르거나 생긴 뒤에 대응한다. 큰 손해(누수, 건물 하자)는 날씨로 미리 알 수 없다. [PRD 2절-2] [UJ 여정 지도 4단계]
- 재계약을 결정한 뒤에야 주변 시세를 찾아본다. 근거는 1명이다. [PRD 2절-3] [UJ 여정 지도 6단계] [ADR 0002]
- 지금 방법은 부동산 앱·LH 사이트를 생각날 때 직접 보는 것이다. [문제정의 SCQA-S] [인터뷰 종합 1절]

## 2. 기대 결과 (Proposed outcome)
- 공공 API를 정해진 간격으로 저절로 모아, 사용자 조건에 맞는 변화를 사건으로 만들고, AI가 쓴 대응안을 본인이 승인하면 내 일정에 저장하고 기록한다. [문제정의 SCQA-A] [PRD 1절]
- 사건 종류는 셋: 청년 주거 지원 공고·정책, 습도·결로 위험, 주변 전월세 시세 변화(내 집 / 관심 지역). [문제정의 사건 기준 표] [GLOSSARY 사건 종류]
- 첫 기능은 마이홈 공고 → 공고·정책 사건 → 신청 준비 계획 승인을 끝까지 잇는 것이다. [문제정의 SCQA-A] [UJ CUJ-01] [PRD 9절]
- 성공 지표 [PRD 3절]:
  - 조건에 맞는 공고·정책이 올라온 날부터 사용자가 사건을 처음 연 날까지 1일 이내 [문제정의 확인할 것 하나]
  - 시뮬레이터 채점 맞힘 100%, 잘못 울림 0건 [PRD FR-25]
  - 같은 변화를 다시 수집했을 때 중복 사건 0건 [PRD FR-10~12]
- 1차 범위는 Must FR-01~27, 2차는 Should FR-28~32(실질 주거비 비교가 알파). [PRD 7·9절] [ADR 0003]

## 3. 영향 범위 (Affected users and systems)
- 사용자: 준비형(독립 준비 중), 자취형(혼자 월세), 관리자(팀원). [PRD 4절] [UJ README 페르소나]
- 화면: 38개(MVP 29, 2차 7, 보류 2). 사용자 메뉴는 홈·사건·내 정보·집 비교·기록 찾기·내 일정, 관리자는 `/admin` 아래 7개 탭. [IA IA 표] [IA 메뉴구조도]
- 첫 기능이 건드리는 화면: `MB_010000_PG`, `MB_010100_PG`, `MB_010200_PG`, `HM_000000_PG`, `IC_020000_PG`, `IC_020100_PG`, `IC_020101_MD`, `IC_020102_MD`, `SC_060000_PG`, `SC_060100_PG`. [UJ CUJ-01 명세] [PRD 9절]
- 내 일정 `SC_060000_PG` 맨 위에 계약 만료 알림: 내 집 만료일(`homes.contract_end_date`)로 화면을 열 때 계산, 저장·알림 없음. [PRD FR-31 v1.11] [spec 013 FR-001~003]
- 자료: 표 19개(회원·직접 입력 5, 수집 4, 사건·대응 4, 기록·관리자·챗봇·채점 6). [ERD 관계도]
- 첫 기능이 쓰는 표: profiles, policy_conditions, sources, runs, run_steps, source_items, observations, incidents, response_plans, incident_actions, schedule_items. [ERD 화면별로 읽고 쓰는 표]
- 외부 시스템: 공공데이터포털(마이홈, 온통청년, 기상청 단기예보, 국토부 전월세 실거래가), Supabase, Claude API, Vercel. [PRD 8절 종속성] [CLAUDE.md 스택]
- 코드: 아직 없음. 폴더는 안내서 이름(`app/`, `watch/`, `incident/`, `knowledge/`, `sim/`, `eval/`, `flow/`, `chat/`, `wiki/`)을 쓰고, 안에서 순수 함수와 DB·API 호출을 나눈다. [CLAUDE.md 폴더]

## 4. 제약 (Constraints)
- 스택: Next.js(App Router) + TypeScript strict, CSS 변수만(Tailwind 없음), Supabase, Claude API, Vitest, Vercel. n8n은 쓰지 않는다. [CLAUDE.md 스택]
- 비밀 키는 서버 환경변수(`.env`)에만 둔다. 화면 코드·GitHub·발표 자료에 없어야 한다. [PRD FR-27] [CLAUDE.md 스택]
- 사람이 승인하기 전에는 어떤 조치도 실행하지 않는다. 관리자도 승인을 건너뛰지 못한다. [CLAUDE.md 팀 작업 규칙] [PRD FR-20, FR-22]
- 읽기 실패는 "변화 없음"이 아니라 수집 오류다. 같은 변화를 다시 읽어도 사건이 두 번 생기지 않는다. [CLAUDE.md 팀 작업 규칙] [GLOSSARY 수집 오류]
- 비교·저장·권한 검사는 코드로, Claude API는 요약·대응안 초안·기록 찾기 답변에만 쓰고 출처를 보인다. [CLAUDE.md 팀 작업 규칙] [PRD FR-15]
- 권한은 화면·서버·DB(RLS) 세 곳에서 모두 "내 자료만". [PRD FR-19] [ERD 접근 규칙]
- 자격은 판정하지 않고 "공고문 기준 확인 필요"로 안내한다. 예산 소진은 감지하지 않고 화면 안내만 둔다. [문제정의 사건 기준 표] [PRD FR-15]
- 측정값과 추정값을 화면에서 나눈다. 상세 주소는 받지 않는다(시군구까지). [GLOSSARY 측정값·추정값] [PRD 8절 개인정보]
- 하지 않을 것: 매물 크롤링, 전세사기 자동 확정, 계약·금융 거래, 안전 인증, 자격 판정, 예산 소진 감지, 전기요금 사건, 추천 점수, 하자 예측, 전환율 비교. 앱 푸시·메신저 알림은 이후 범위. 에너지비는 입력·한전 요금표 계산·근거 있는 추정까지 범위(PRD v1.10, 사용자 결정 2026-11-18). [PRD 9절] [CLAUDE.md 하지 않을 것]
- 1차 알림은 앱 안에서만(홈 카드, 사건 숫자 배지). [PRD 8절 주요 결정]
- 정기 실행은 Vercel Cron Jobs로 한다. 무료(Hobby) 플랜은 한 작업당 하루 1번까지, 실행 시각은 정한 시간 안에서 ±59분, UTC 기준이다. [사용자 결정 2026-11-17] [Vercel 문서 https://vercel.com/docs/cron-jobs/usage-and-pricing]
- 작업은 `Yelim` 브랜치 하나에서 하고 PR #1로 리뷰받는다. [사용자 결정 2026-11-17]
- 배포는 팀이 "배포해줘"라고 할 때 비용·공개 범위를 보여 주고 한다. [CLAUDE.md 스택]
- 코드 크기: 파일 300줄, 함수 40줄, 인자 3개 이하. [.claude/rules/code.md]
