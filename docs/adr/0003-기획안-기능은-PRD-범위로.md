# 기획안의 사건 밖 기능은 문제정의를 넓히지 않고 PRD 범위로 넣는다

문제정의를 승인한 뒤 팀이 기획안(HomeFit AI)을 다시 대조했더니, 실질 주거비 비교, Housing QC, 출퇴근 분석, 개인화 추천처럼 사건(바깥 변화 감시) 밖의 기능이 문서에서 빠져 있었다. 안내서가 채점하는 중심은 감시 → 사건 → 승인 흐름이라 문제정의는 그대로 둔다. 기획안 기능은 그 흐름을 돕는 화면으로 IA와 PRD에 넣고, 인터뷰 근거로 우선순위를 나눈다(사용자 결정, 2026-11-17).

## PRD로 넘길 우선순위 초안
| 우선순위 | 기능 | 근거 |
|---|---|---|
| 꼭 (Must) | 안내서 필수 8가지, 사건 3종(청년 주거 지원 공고·정책, 습도·결로 위험, 주변 전월세 시세 변화) | 안내서, [문제정의](../문제정의.md) |
| 해야 함 (Should) | 실질 주거비 비교(관심 주택 등록, 관리비·에너지비·교통비 포함). 알파로 쓴다 | P01·A01(가상) 관리비 미기재, P04 교통 |
| 해야 함 (Should) | 입주 전 점검·하자 기록(Housing QC 체크리스트) | P01 냄새·기숙사 상태, P03 입주 전 청소·고장·누수 |
| 해야 함 (Should) | 계약 만료 일정(만료 2달 전 알림, 재계약 판단 메모와 연결). 사건이 아니다 | P01 재계약, P03 계약일 변경 |
| 되면 함 (Could) | 출퇴근 시간 분석, 건축물대장 정보, 냉난방비 추정 | P04 교통, 기획안 4-2·4-3 |
| 이번엔 안 함 (Won't) | 개인화 추천 점수, 전기요금 변경 사건, 에너지 시뮬레이션 고도화 | 근거 약함(요금은 4명 모두 "미리 알아도 같았을 것"), 기획안 Phase 2 |

- 주변 전월세 시세 변화 사건은 "내 집"과 "관심 지역" 두 대상을 받는다. 인터뷰한 4명 중 3명이 독립 준비 중이라 내 집만 보면 집을 구하는 사람이 사건을 받지 못한다.
- 기획안의 n8n, Tailwind는 [CLAUDE.md](../../CLAUDE.md)의 스택 결정(n8n 쓰지 않음, CSS 변수만)을 따른다.

## Considered Options
- 문제정의를 기획안 전체(집 고르기 + 감시)로 넓힌다: 한 번의 결정인 집 고르기는 사건·승인 구조와 맞지 않아 문제가 흐려진다.
- 사건만 만들고 기획안 기능은 버린다: 인터뷰에서 손해가 가장 많이 나온 "계약 전에 알 수 없는 집 정보"(종합 3절 ②)를 다룰 곳이 없어진다.
