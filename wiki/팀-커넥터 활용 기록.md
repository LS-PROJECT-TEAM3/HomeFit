# 팀-커넥터 활용 기록

> 개발할 때 Claude가 외부 서비스(Supabase·Vercel·GitHub 등)에 연결해 실제로 한 일과, 연결에 실패해 다른 길로 간 일. ERD와 실제 DB 대조 결과도 여기 있다(P3-19, P3-16).

## 내용
- 커넥터는 개발 때 Claude가 외부 서비스에 연결해 일하는 길이다. 설치만 한 것은 세지 않고, 앱이 부르는 API는 [[데이터-데이터 출처와 한도]]에 따로 있다. 토큰·키는 적지 않는다. (근거: docs/connectors.md · 머리말)
- 서로 다른 커넥터 3개의 실제 사용(안내서 기준 2개 이상): A Supabase 커넥터(마이그레이션 적용 `apply_migration`, 확인 질의 `execute_sql`, 가상 계정에 관리자 권한 주는 SQL 한 줄), B Vercel 커넥터(배포 목록·상세, 운영 환경변수 확인), C GitHub 커넥터(PR #8·#11 만들기, PR #5·#7 승인·병합). 셋 다 예림님 PC, 개발 때만 쓰고 앱 실행에는 쓰지 않는다. (근거: docs/connectors.md · 1. 지금까지 확인된 사용)
- 커넥터가 아닌 보조 도구: 명령줄 `gh`(선우·서윤 PC, PR 만들기·리뷰), Claude 앱 내장 브라우저(선우: 개발 서버 화면 17곳 검수·노션 제안서 읽기, 현경: 수업 위키 읽기), Claude in Chrome(선우: Supabase 대시보드 읽기만). 2·3번을 평가에 넣을지는 팀이 정한다. (근거: docs/connectors.md · 1. 지금까지 확인된 사용)
- 실패와 대체: Notion 커넥터 404(페이지 권한 없음) → 내장 브라우저, 현경 PC GitHub 연결 인증 오류, 서윤 PC GitHub MCP 연결 오류 → `gh`, 선우 계정 Supabase 커넥터 "권한 없음"(초대 전 개인 조직에만 허용) → 크롬으로 대시보드 읽기. (근거: docs/connectors.md · 2. 연결을 시도했으나 실패한 것)
- 2026-11-23에는 선우 컴퓨터의 Supabase 커넥터에서 HomeFit 프로젝트를 찾지 못해 0022~0025 뒤 DB를 다시 대조하지 못했다. (근거: docs/connectors.md · 6.2 그 뒤 DB 변경 0022~0025)
- 선우 검수(2026-11-18 오전, 일반 계정): 화면 17곳 열림, 관리자 주소 4곳 막힘, 잘못된 입력은 저장 안 됨, 기록 찾기·챗봇은 출처와 함께 답함. 어색한 점 5개(계약 형태 "모름"인데 만료일 보임, 출처 화면에 온통청년 없음 등). 관리자 화면·알림 거절·슬랙은 확인 못 함. (근거: docs/connectors.md · 3. 선우 검수 시험 (2번 내용))
- ERD와 실제 DB 대조(2026-11-18 오후, 선우, 읽기만): 표 20개·표별 칸 수·RLS 정책 35개가 마이그레이션·ERD와 같음. 칸 이름·자료형·정책 조건식·DB 함수는 확인 못 함. `profiles`·`notification_settings`·`schedule_items`의 "API DISABLED"는 정해진 칸만 고치게 막은 의도한 설정(예림님 확인). (근거: docs/connectors.md · 6. ERD와 실제 DB 대조 결과)
- 대조 뒤 바뀐 것: `audit_logs`는 0019로 생김(PR #11). `chat_logs`는 현경님이 SQL 편집기로 먼저 적용했고 파일 0018은 PR #15로 들어옴(다시 돌려도 멈추지 않음). 2026-11-18 기준 DB 마이그레이션 기록은 19개(0001~0017, 0019, 0020)였고 맨 앞 4개는 번호 없는 이름이다. 그 뒤 0021(spec 019)을 예림님이 PR #19가 합쳐지기 전에 Supabase 커넥터(`apply_migration`)로 공용 DB에 먼저 적용했고, 예림님이 센 지금 기록은 20개(0001~0017, 0019~0021)로 0018은 여전히 없다(선우가 직접 세지는 않음). 위 표의 "표 20개, 정책 35개"는 0021 전 값이다. (근거: docs/connectors.md · 6.1 대조한 뒤 바뀐 것)
- 0018 기록 처리: 그대로 둔다(A안, 사용자 결정 2026-11-19). connectors.md 6.1절도 2026-11-19에 "현경님이 그대로 둔다로 정했다"로 고쳤고, 팀 전체가 같이 정한 것인지는 확인 필요로 남겼다. (근거: docs/connectors.md · 6.1 대조한 뒤 바뀐 것) 팀은 `supabase db push`를 쓰지 않고, 쓰기로 하면 그때 기록표 전체를 파일과 맞춘다. (근거: docs/specs/012-위키-챗봇/plan.md · 위험과 대응)
- DB 변경 0022~0025(6.2절, 2026-11-23 main `e8050f7`의 파일과 PR 설명으로 더함): 넷 모두 PR이 main에 합쳐지기 전에 공유 DB(운영과 같은 DB)에 먼저 적용됐다고 PR 설명에 있다. 적용·확인은 예림, 선우는 파일과 PR 설명만 읽었다. 0022 `push_subscriptions` 새 표·`notifications.channel`에 `web_push`(spec 021, PR #44, 2026-11-20 적용, qa 021 C-2105). 0023 `notice_follows` 본인 지우기 정책·`incident_actions` 취소 두 종류·DB 함수 `cancel_approval`·`cancel_rejection`(spec 023, PR #51). 0024 `homes` 칸 3개(`gas_usage_mj`·`gas_bill_month`·`gas_tariff_region`)와 검사 제약 4개(spec 025, PR #51). 0025 DB 함수 `add_policy_to_schedule`(spec 026, PR #55). 0023~0025는 되돌림 SQL로 검사했고 보안 점검(advisors) 새 경고가 없었다고 적혀 있다. (근거: docs/connectors.md · 머리말, 6.2 그 뒤 DB 변경 0022~0025)
- 6.2절이 확인 못 한 것: 새 표가 0022 하나라 6절 "표 20개"는 지금 21개 이상이어야 하지만 지금 DB의 표·정책 수는 확인 못 함. DB 적용 기록에 0022~0025가 남았는지도 PR 설명에 없어 확인 못 함. 공유 DB에 시험 값(정책 일정 2개, 내 집 도시가스 2,800MJ·1월)이 남아 있다(예림님 슬랙 2026-11-23). (근거: docs/connectors.md · 6.2 그 뒤 DB 변경 0022~0025)

## 충돌
- (풀림, connectors.md 6.1절이 "그대로 둔다"로 고쳐짐) 0018 마이그레이션 기록을 맞출지: connectors.md 6.1절은 "팀이 정해야 한다(현경님, 미결정)"이고(근거: docs/connectors.md · 6.1 대조한 뒤 바뀐 것), spec 012 plan은 "그대로 둔다(A안, 사용자 결정 2026-11-19)"다(근거: docs/specs/012-위키-챗봇/plan.md · 위험과 대응). 고르지 않는다. connectors.md 담당(선우, 조각 C1)이 반영할지 정한다.

## 확인 필요
- 커넥터 A·B의 캡처(안내서는 결과 링크나 캡처를 요구). 예림님이 올리기로 함. (근거: docs/connectors.md · 5. 아직 비어 있는 것)
- 조각 A·B와 PR #19가 합쳐진 뒤 ERD와 DB를 다시 대조하지 않았다(2026-11-19 기준). (근거: docs/connectors.md · 6.1 대조한 뒤 바뀐 것)
- (풀림) 0022가 6.1절에 없던 것: connectors.md 6.2절에 0022(PR #44, 2026-11-20 운영 DB 적용, qa 021 C-2105)가 0023~0025와 함께 들어갔다. (근거: docs/connectors.md · 6.2 그 뒤 DB 변경 0022~0025) (근거: docs/specs/021-웹-푸시-알림/qa.md · C-2105)
- 0022~0025 뒤 ERD와 공유 DB를 다시 대조할지, 누가 할지(선우 컴퓨터 커넥터에서는 프로젝트를 못 찾음). 조각 C1·예림에게 확인. (근거: docs/connectors.md · 6.2 그 뒤 DB 변경 0022~0025)
- 공유 DB에 남은 시험 값(정책 일정 2개, 내 집 도시가스 값)을 남길지 지울지 정한 기록이 없다. 팀에 확인. (근거: docs/connectors.md · 6.2 그 뒤 DB 변경 0022~0025)
- 6.2절은 PR #51이 "리뷰 없이 합쳐짐"이라 적는데, 팀 규칙은 리뷰 1명 이상 뒤에 합친다. 뒤에 리뷰를 받았는지 팀에 확인. (근거: docs/connectors.md · 6.2 그 뒤 DB 변경 0022~0025) (근거: docs/plan.md · 머리말 규칙)
