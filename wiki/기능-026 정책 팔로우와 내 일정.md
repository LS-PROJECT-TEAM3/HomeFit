# 기능-026 정책 팔로우와 내 일정

> 청년 주거지원 정책도 공고처럼 팔로우·팔로우 풀기를 하고, 목록에서 "팔로우 중"만 모아 보며, 팔로우한 정책을 내 일정에 넣는다(신청 끝 날짜 또는 마감 없음, 기본 체크리스트 3개 + 원문 제출 서류). PRD v1.25 FR-07·FR-16을 만든 기능이다.

## 내용
- 상태: spec 승인됨 v0.3(사용자 "승인" 2026-11-23), plan 승인됨 v0.1(사용자 "승인" 2026-11-23: plan, 마이그레이션 0025), qa "완료"(C 10/10, H 1/1). (근거: docs/specs/026-정책-팔로우-일정/spec.md · 머리말) (근거: docs/specs/026-정책-팔로우-일정/plan.md · 머리말) (근거: docs/specs/026-정책-팔로우-일정/qa.md · 머리말)
- 결정 변경: spec 006 Q1(정책도 팔로우할까)의 답 "이번엔 목록만"을 "2026-11-23 spec 026: 팔로우·일정 추가는 함, 변화 알림은 아직"으로 바꿨다고 spec 006이 직접 적는다. (근거: docs/specs/006-청년정책-수집/spec.md · Q1) (근거: docs/specs/026-정책-팔로우-일정/spec.md · Q5)
- 출처: 사용자 요청 "청년주거지원정책도 팔로하고 일정에 추가 할 수 있으면 좋겠어"(2026-11-23). (근거: docs/specs/026-정책-팔로우-일정/spec.md · 변경 기록 v0.1)
- 문제: 정책은 목록과 상세만 볼 수 있어, 신청하려던 정책을 다시 찾으려면 처음부터 걸러야 하고, 신청 마감과 준비할 서류를 내 일정에서 챙길 수 없어 놓친다. (근거: docs/specs/026-정책-팔로우-일정/spec.md · 1. 해결하려는 문제)
- FR-001 정책 상세에서 팔로우·팔로우 풀기(공고처럼 정하지 않은 상태로 돌아감), "관심 없음"은 정책에 두지 않음. FR-002 목록에 "팔로우 중" 글자 표시와 "팔로우 중"만 거르기. FR-003 팔로우한 정책만 "내 일정에 추가", 두 번 눌러도 하나, 이미 있으면 "내 일정에 있어요"와 일정 링크. (근거: docs/specs/026-정책-팔로우-일정/spec.md · FR-001~FR-003) (근거: docs/PRD.md · FR-07 v1.25, FR-16 v1.25)
- FR-004 마감일은 신청 기간 끝 날짜가 있으면 그 날짜, 없으면 마감 없이. 상시면 "상시 신청, 공고문 확인", 기간을 알 수 없으면 "신청 기간 공고문 확인"(v0.3). 없는 날짜를 지어내지 않는다. FR-005 체크리스트 기본 3개("공고문에서 자격 확인", "제출 서류 준비", "신청하기")와 원문 제출 서류 칸 그대로(없으면 "공고문 확인"), 자격은 판정하지 않음. FR-006 팔로우를 풀어도 넣은 일정은 그대로, 정책 변화 알림은 보내지 않음. (근거: docs/specs/026-정책-팔로우-일정/spec.md · FR-004~FR-006)
- 결정 변경(spec v0.3): Q2 답은 "상시·모름은 마감 없이 '상시 신청, 공고문 확인'"이었는데, 1단계 리뷰에서 기간 모름도 "상시 신청"으로 보여 체크리스트와 어긋나 사용자 "따로 표시"로 모름은 "신청 기간 공고문 확인"으로 바꿨다고 spec 변경 기록과 qa가 적는다. (근거: docs/specs/026-정책-팔로우-일정/spec.md · Q2, 변경 기록 v0.3) (근거: docs/specs/026-정책-팔로우-일정/qa.md · 3. 실패와 조치 #1)
- 경계 E1~E7: 다른 창에서 또 팔로우하거나 또 풀어도 오류 없음(E1), 팔로우 안 한 정책의 일정 추가는 "먼저 팔로우해 주세요"(E2), 끝 날짜가 지났으면 넣되 "마감 지남"(E3), 수집에서 사라진 정책은 "정책을 찾을 수 없습니다"(E4), 같은 이름 지역별 여러 건이면 연 그 정책 ID 기준(E5), 남의 팔로우·일정은 못 읽고 못 고침, 로그인 끝나면 로그인 화면(E6), 저장 실패 안내(E7). (근거: docs/specs/026-정책-팔로우-일정/spec.md · 경계·예외 상황 E1~E7)
- 결정 Q1~Q5(2026-11-23): 팔로우는 "팔로우 중" 표시·모아 보기와 일정 추가 조건만, 변화 알림은 다음(Q1), 마감일 규칙(Q2), 체크리스트 3개 + 원문 서류(Q3), 팔로우·풀기만(Q4), PRD v1.25·ERD v1.16·spec 006 Q1·마이그레이션 0025를 먼저(Q5). (근거: docs/specs/026-정책-팔로우-일정/spec.md · 6. 확인 필요 사항)
- 하지 않을 것: 정책 변화 알림·사건·슬랙·웹 푸시, 정책 "관심 없음", 여러 정책 한꺼번에 팔로우, 자격 자동 판정·예산 소진 감지·정책 페이지 긁어 오기, 팔로우를 풀 때 일정 지우기. (근거: docs/specs/026-정책-팔로우-일정/spec.md · 5. 제외 범위)
- 기술·DB: 새 라이브러리 없음. 마이그레이션 0025(`0025_policy_schedule.sql`)로 DB 함수 `add_policy_to_schedule` 하나(팔로우 확인, 제목·끝 날짜는 source_items `youth_policy`에서, 같은 사람·같은 정책은 하나). 순수 함수 `incident/policy-schedule.ts`(체크리스트, 마감 글자, 팔로우 거르기), 일정 출처가 정책이면 "/policy/…" "출처 정책 보기". 공유 DB 정책 425건 중 끝 날짜 183건, 상시 150건(2026-11-23 확인). ERD v1.16은 notice_follows·schedule_items에 출처 `youth_policy` 줄을 두고(결정은 `follow`만) 표 모양은 그대로라고 적는다. (근거: docs/specs/026-정책-팔로우-일정/plan.md · 1. 기술과 버전, 2. 구조와 파일) (근거: docs/ERD.md · #### notice_follows, schedule_items.source_code, 변경 기록 v1.16)
- 단계 1~3(모두 체크): 1 시험 먼저와 일정 읽기에 source_code → 2 0025를 공유 DB에 적용, 되돌림 SQL 검사 → 3 정책 상세 팔로우·일정 추가, 목록 거르기, 일정 상세. (근거: docs/specs/026-정책-팔로우-일정/plan.md · 3. 단계별 접근)
- Claude QA: C-2601~2610 모두 통과. 되돌림 SQL에서 팔로우 전 `not_followed`, 기간 정책 마감일 = 끝 날짜, 두 번 → 하나, 상시 → 마감 없음, 팔로우를 지워도 일정 남음, 없는 정책 `policy_not_found`, 남의 것·anon 막힘(C-2605). advisors 새 종류 경고 없음(C-2606). 미리보기에서 팔로우 → "팔로우 중"·"내 일정에 있어요", 풀어도 일정 그대로(C-2607). 기간 모름 문구는 시험으로만(C-2609). 전체 시험 833개·tsc·lint·build 통과(C-2610). (근거: docs/specs/026-정책-팔로우-일정/qa.md · 1. Claude QA)
- 사람 QA: H-2601 통과(사용자 "둘 다 통과", 2026-11-23). (근거: docs/specs/026-정책-팔로우-일정/qa.md · 2. 사람 QA)
- 실패와 조치 3건: 기간 모름도 "상시 신청"으로 보임 → spec v0.3(#1), 목록은 같은 이름의 다른 지역 건 팔로우도 "팔로우 중"인데 상세는 아님 → 사용자 결정 "ID가 같을 때만", 글자 버튼의 aria-pressed 제거, 처리 중 상태 분리, 팔로우 목록 실패 때 표시만 숨김(#2), 정책 상세 모양을 공고 상세와 같게(사용자 "팔로우 모양 주택이랑 같이 만들어줘 부연설명같은거 빼고")(#3). (근거: docs/specs/026-정책-팔로우-일정/qa.md · 3. 실패와 조치)

## 충돌
- plan 근거 버전: plan 머리말은 근거를 "spec 026 v0.2"로 적고 변경 기록은 v0.1뿐인데(근거: docs/specs/026-정책-팔로우-일정/plan.md · 머리말, 변경 기록), spec은 v0.3이고 qa 근거도 "spec v0.3"이다(근거: docs/specs/026-정책-팔로우-일정/spec.md · 머리말) (근거: docs/specs/026-정책-팔로우-일정/qa.md · 머리말). 고르지 않는다.
- 팔로우 표가 공고 전용인가: spec 006 하지 않을 것은 "팔로우 표가 공고 전용이라 ERD 변경이 필요"라고 적고(근거: docs/specs/006-청년정책-수집/spec.md · 하지 않을 것), plan 026은 "notice_follows는 출처 제한이 없어(FK sources만) 정책 줄을 그대로 넣을 수 있다", ERD v1.16은 "표 모양은 그대로"라고 적는다(근거: docs/specs/026-정책-팔로우-일정/plan.md · 2. 구조와 파일) (근거: docs/ERD.md · 변경 기록 v1.16). 고르지 않는다.
- ERD 안의 notice_follows 출처: 표 머리 설명은 출처 `youth_policy` 줄(정책 ID, `follow`만)을 적는데, 같은 표의 source_code 칸 설명은 `myhome_notice`만 적는다(근거: docs/ERD.md · #### notice_follows). 고르지 않는다.
- PR 상태: Intent 문서 지도 31행은 "PR 대기(#51 합친 뒤)"이고(근거: docs/Intent.md · ## 6. 문서 지도 31), connectors 6.2절은 0025를 "PR #55 설명" 기준으로 적고 PR #55가 2026-11-23 13:45 합쳐졌다고 적는다(근거: docs/connectors.md · 6.2 그 뒤 DB 변경 0022~0025). 고르지 않는다.

## 확인 필요
- 정책 변화(신청 기간 바뀜 등) 알림은 "다음"으로 미뤘다. 언제 다룰지 원본에 없다. 기능 담당(예림)에게 확인. (근거: docs/specs/026-정책-팔로우-일정/spec.md · Q1, 5. 제외 범위)
- 기간을 모르는 정책의 "신청 기간 공고문 확인" 화면은 시험으로만 확인했다(C-2609). 화면에서 볼지 qa 담당에게 확인. (근거: docs/specs/026-정책-팔로우-일정/qa.md · C-2609)
- DB의 마이그레이션 적용 기록에 0025가 남았는지는 확인하지 못했다. connectors 담당에게 확인. (근거: docs/connectors.md · 6.2 그 뒤 DB 변경 0022~0025)
