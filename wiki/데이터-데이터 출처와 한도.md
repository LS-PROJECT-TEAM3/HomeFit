# 데이터-데이터 출처와 한도

> 앱이 읽는 공공 자료 7개의 주소·간격·하루 한도·약관, 실패 처리, 실수집과 가짜 자료 구분, 키 이름(값은 적지 않음)(P3-02, P3-33).

## 내용
- 출처 7개: 마이홈 공공임대 모집공고(매일 09:00), 온통청년 주거 정책(매일 09:10), 기상청 단기예보(매일 05:30·17:30), 전월세 실거래가 4종(매월 2일 10:00), 법정동코드(화면에서 필요할 때, 30일 저장), 건축HUB 건축물대장(사용자가 조회할 때), 한국전력 가구평균 전력사용량(화면을 열 때, 시군구·날짜마다 하루 저장, spec 011). 시각은 `vercel.json`의 UTC 설정을 한국 시각으로 바꾼 것. (근거: docs/data-sources.md · 1. 한눈에 보기)
- 모두 공개 정부 자료를 정해진 API로 받는다. 로그인 페이지·개인 정보·유료 글은 쓰지 않고, 크롤러·Firecrawl은 쓰지 않는다. (근거: docs/data-sources.md · 1. 한눈에 보기)
- 읽는 법: 마이홈·온통청년은 한 쪽 100건씩 최대 20쪽, 기상청은 내 집 시군구를 격자 좌표로 바꿔 시군구마다 1번(기다림 15초), 실거래가는 내 집·관심 지역 시군구로 지난달부터 3개월을 한 쪽 1,000건씩 최대 10쪽. (근거: docs/data-sources.md · 2.1~2.5)
- 하루 한도(공공데이터포털 개발계정, 2026-11-18 확인): 마이홈 1,000건, 기상청·실거래가 4종·법정동코드·건축HUB 10,000건, 온통청년은 "기관 정책에 따라 상이"(심의 승인, 한도 표시 없음), 한전은 포털에 적혀 있지 않음. 지금 쓰는 양은 한도보다 훨씬 적다(마이홈 하루 최대 20번, 기상청 하루 8번 등). (근거: docs/data-sources.md · 2.6 한도·약관 확인)
- 약관: 모두 무료. 기상청은 공공누리 제1유형이라 출처표시가 조건이고, 알림 상세와 "공공데이터 출처" 화면에 "기상청 단기예보"로 적는다. 건축HUB는 갱신 주기가 월간이라 최근 변경이 빠질 수 있다. (근거: docs/data-sources.md · 2.6 한도·약관 확인)
- 같은 모양: 출처가 달라도 `observations`에 시각·대상·지표·값·바뀐 정도·출처 칸으로 저장하고, 원본 응답은 `raw`, 시뮬레이터 값은 `is_simulated`. 공고·정책은 `content_hash`·`external_id`로 먼저 비교해 같은 변화를 두 번 사건으로 만들지 않는다. (근거: docs/data-sources.md · 3. 사건 쪽으로 넘기는 같은 모양)
- 실패 처리: 읽기 실패는 "변화 없음"이 아니라 수집 오류(`runs` failed, `run_steps` collect, 이유는 키를 가려 기록). 시세·날씨는 일부만 실패하면 나머지로 계속하고 실패한 곳을 목록으로 남기며, 마이홈·온통청년은 한 쪽이라도 실패하면 전체 실패. 자동 재시도와 요청 사이 대기는 두지 않았다. (근거: docs/data-sources.md · 4. 실패 처리)
- 실수집과 가짜: 정기 실행은 운영에서 모두 실제 API이고 `?fixture=`는 개발에서만 된다. 관리자 시뮬레이터는 운영에서도 가짜 묶음을 돌리되 사건·알림은 `SIMULATION_USER_IDS`의 가상 계정에만 생긴다. 시세에는 실제 거래로 비교하는 `live` 모드도 있다(호출 한도 사용). (근거: docs/data-sources.md · 5. 실수집과 가상 데이터 구분)
- 키는 서버 환경변수에만 두고 저장소 `.env.example`에는 이름만: `DATA_GO_KR_SERVICE_KEY`(마이홈, 기상청 단기예보·초단기, 실거래가, 법정동코드, 건축HUB, 공동주택 에너지 사용 정보), `YOUTH_POLICY_API_KEY`, `KEPCO_API_KEY`, `CRON_SECRET`. (근거: docs/data-sources.md · 6. 비밀 키)
- 머리말(2026-11-19 고침): 기준일 2026-11-18(main `65ed611`) 뒤 예림님이 spec 011·016~018·020 출처를 더했고(PR #16, #19), 2026-11-19 main `32444a4`에서 1절 표 11줄이 앱의 "공공데이터 출처" 화면과 같음을 확인했다(화면은 격자 좌표와 "내가 넣은 값"을 더해 13줄). (근거: docs/data-sources.md · 머리말)
- 웹 푸시(spec 021)의 VAPID 키 3개(`NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`)는 공공데이터 출처가 아니라 data-sources.md 6절 표에 없다. 이름은 plan 021에 있다. (근거: docs/specs/021-웹-푸시-알림/plan.md · 1. 기술과 버전) (근거: docs/data-sources.md · 6. 비밀 키)
- 2026-11-19에 출처 4개가 더해졌다: 국토교통부 공동주택 에너지 사용 정보(아파트 에너지비 추정 spec 018, 공공데이터포털 15012964, 자동승인, 개발계정 하루 5,000건, 화면을 열 때 부르고 시군구·날짜마다 하루 저장), 기상청 초단기실황·초단기예보(홈 바깥 날씨 spec 020, 같은 키 `DATA_GO_KR_SERVICE_KEY`, 격자·기준 시각마다 10분 저장), 한국가스공사 도시가스 소매요금표(냉난방비 계산 spec 016, 공공데이터포털 15157367 파일, 연 1회 받아 `watch/gas-tariff.json`), 가구에너지패널조사 14차 결과표(에너지 추정 보정 spec 017, KESIS 공개 파일, 전국 값 9개를 `watch/energy-panel.json`). (근거: docs/data-sources.md · 1. 한눈에 보기, 2.6 한도·약관 확인)
- 2026-11-23에 출처 1개가 더해져 1절 표가 12줄이 됐다: 한국가스공사 월별 시도별 도시가스 판매현황(난방비 12개월 추정 spec 025, 공공데이터포털 15040819 파일(CSV), 이용허락 제한 없음, 수정일 2026-09-29). 연 1회 파일을 받아 2022·2023·2024년마다 12개월 합으로 나눈 달별 비율을 구하고, 세 해를 평균한 뒤 합이 1이 되게 맞춰 소수 넷째 자리로 `watch/gas-monthly-share.json`에 둔다(17개 시도, 전국은 17개 시도 합으로 같은 방법). 받은 CSV는 약 45KB, 1989-01~2024-12, 단위 천㎥이고 원본 CSV는 저장소에 넣지 않는다. 새 해 파일이 올라오면 최근 3년을 다시 뽑는다. ([[기능-025 도시가스 12개월 난방비]]) (근거: docs/data-sources.md · 1. 한눈에 보기, 2.6 한도·약관 확인)
- 가스공사 판매현황의 한계: 가정용만 나눈 값이 아니라 산업용 등을 포함한 전체 용도 판매량이다(가정용 월별 공식 자료는 찾지 못함). 판매월은 검침·청구 기준이라 실제 쓴 달과 한 달쯤 다를 수 있다(예: 대구는 2월이 1월보다 큼). 화면은 이 한계를 "추정" 근거로 밝힌다. 전체 판매량을 쓰는 것은 사용자 결정이다. (근거: docs/data-sources.md · 2.6 한도·약관 확인) (근거: docs/specs/025-도시가스-12개월-난방비/spec.md · FR-004, 5. 제외 범위)

## 확인 필요
- 온통청년의 하루 한도는 아직 모른다. 코드가 쓰는 주소(`/go/ythip/getPlcy`)도 안내 페이지에서 직접 확인하지 못했다. (근거: docs/data-sources.md · 2.6 한도·약관 확인, 7. 아직 남은 것)
- data-sources 머리말은 아직 "1절 표 11줄이 앱의 공공데이터 출처 화면과 같음(2026-11-19 `32444a4`)"이지만 지금 1절 표는 12줄이다(가스공사 판매현황 추가). 앱 "공공데이터 출처" 화면에도 이 줄이 들어갔는지, 머리말을 고칠지 data-sources 담당(예림)에게 확인. (근거: docs/data-sources.md · 머리말, 1. 한눈에 보기)
- 요청 사이 간격과 재시도를 둘지 팀이 정한다. (근거: docs/data-sources.md · 7. 아직 남은 것)
- `kma-sample.json` 등 저장 샘플에 "실제 응답" 메모 넣기(예림님 다음 PR 예정), 문제정의 확인 필요 6번의 온통청년 설명 고치기. (근거: docs/data-sources.md · 7. 아직 남은 것)
- (풀림) 머리말 기준일과 표가 다르던 것은 머리말에 "그 뒤 출처를 더했다, 32444a4에서 화면과 같음을 확인"이 더해져 풀렸다. VAPID 키 이름을 6절 비밀 키 표에 더할지는 담당(조각 C1)에게 확인. (근거: docs/data-sources.md · 머리말, 6. 비밀 키)
