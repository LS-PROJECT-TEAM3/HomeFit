# 팀-서브에이전트와 스킬 기록

> 팀이 실제로 쓴 서브에이전트(일을 나눠 맡기는 별도 Claude 도우미)와 스킬, 그리고 만드는 쪽과 검토하는 쪽을 나눈 사례(P3-24, P3-25).

## 내용
- 기록 원칙: 실제로 쓴 것만 적고, 확인 못 한 곳은 "확인 필요"로 둔다. 직접 만든 서브에이전트 설정(`.claude/agents/`)은 저장소에 없고, 그때그때 Claude가 띄운 도우미만 있다. (근거: docs/agents.md · 머리말, 1. 서브에이전트)
- 인터뷰 검증 도우미 3명(선우): 서로 모르는 도우미에게 같은 인물 설정으로 다시 인터뷰를 시켰다. 네 번 모두 같은 장면 4개가 나와 "AI가 인물 설정을 늘 같은 이야기로 풀어 쓴 것"으로 보고, 이 기록은 사람 수·빈도의 근거로 세지 않고 가설로만 쓰기로 했다. (근거: docs/agents.md · 1.1 AI 페르소나 인터뷰 검증 도우미 3명)
- 별도 리뷰어(기능 001 12단계, 예림): 기본 general-purpose 서브에이전트에게 "고치지 말고 보고만"으로 맡겨 지적 5건(꼭 고칠 것 0, 고치면 좋은 것 2, 있으면 좋은 것 3). 고친 것은 qa 001 실패와 조치 #14~#17. (근거: docs/agents.md · 1.2 코드 리뷰 도우미 "별도 리뷰어")
- 예림님 도우미 9번: 웹 문서 읽기 4번(공공 API, Vercel 정기 실행 한도, Gemini 문서, 한전 요금표), 조사 3번, 코드 리뷰 2번. 처음 12번으로 센 것은 같은 호출이 두 줄씩 남아 잘못 센 것. (근거: docs/agents.md · 1.3 조사·문서 읽기·코드 리뷰 도우미)
- 저장소 스킬(agents.md 2절, 2026-11-19 `32444a4`에 고침): 13개 = harness-* 7개(erd, ia, intent, journeys, prd, qa, spec-plan), 인터뷰·용어 3개(domain-modeling, grill-with-docs, grilling), 위키 3개(wiki-ingest, wiki-query, wiki-lint, 조각 A PR #15). 위키 스킬의 쓴 흔적은 `wiki/`의 주제 쪽과 `wiki/log.md`, `scripts/wiki-lint.mjs`(현경, 건별 입력은 확인 필요). "8묶음"은 2026-11-18 기준이고 009~020을 어느 스킬로 만들었는지는 확인하지 않았다. (근거: docs/agents.md · 머리말, 2. 스킬 (P3-24))
- 스킬 수 변경(2026-11-23 PR #47 뒤 agents.md 고침): 저장소 스킬은 15개다. 위 13개에 디자인 2개(ui-ux-pro-max: MIT, nextlevelbuilder/ui-ux-pro-max-skill `2de1134` / frontend-design: Apache-2.0, Anthropic)를 조각 D(PR #47)에서 더했다. 쓴 흔적은 spec 022의 새 색·글꼴 토큰, 포스터형·기본형 화면, qa 022 점검 체크리스트이고 현경이 2026-11-21 넣었다(건별 입력은 확인 필요). 예림이 쓴 ui-ux-pro-max는 저장소 밖 스킬에서 2절 표로 옮겼다. (근거: docs/agents.md · 머리말, 2. 스킬 (P3-24), 2.1 저장소 밖 스킬)
- 위키 쪽 수 세는 법(2026-11-23, #43 리뷰 반영): 위키 주제 쪽은 64개다. `wiki/`의 md 68개에서 목차 `index.md`·기록 `log.md`·연결지도·위키 규칙 파일 `wiki/CLAUDE.md` 4개를 뺐고, "규칙-"으로 시작하는 주제 쪽 6개는 셈에 들어간다. 위키 그래프가 세는 방식(qa 012 C-913)과 같고 위키 챗봇 화면에도 "쪽 64개"로 나온다. 2026-11-23 main에서 셌고, 2026-11-19에는 같은 방식으로 56개였다. (근거: docs/agents.md · 2. 스킬 (P3-24) wiki-ingest 줄)
- 검토하고 넣지 않은 스킬: `design-taste-frontend`. 최신판은 크기가 크고 자동 실행 훅·사진 내려받기가 있으며, 예전판은 Tailwind·framer-motion을 요구하고 대시보드 세리프 글꼴을 막아 이번 디자인과 맞지 않았다(현경 결정 2026-11-21). (근거: docs/agents.md · 2.1 저장소 밖 스킬)
- 처음 기록(2026-11-18): 저장소 스킬 10개(harness-* 7개와 domain-modeling, grill-with-docs, grilling). 쓴 흔적은 산출물(문제정의, IA, 여정, PRD, ERD, Intent, spec·plan·qa)로 남았고, 예림님이 harness 계열을 모두 썼다고 답함. 건별 입력은 확인 필요. (근거: docs/agents.md · 2. 스킬 (P3-24))
- 저장소 밖 스킬: `ponytail-review`(단계 끝 리뷰 7번, 예림), `ui-ux-pro-max`·`react-best-practices`·`composition-patterns`·`claude-api`(예림). 전역 스킬이라 다른 팀원 PC에서는 불리지 않는다. (근거: docs/agents.md · 2.1 저장소 밖 스킬)
- 현경 PC(agents.md 1.4, 2026-11-19 고침): 서브에이전트 "쓰지 않음"은 2026-11-18 답 기준이고, 그 뒤 조각 A에서 `/ralph-loop` 플러그인으로 위키 찾기를 다듬은 기록이 ralph-progress.md에 있다(기준선 12/13에서 두 번 고쳐 13/13, qa 012는 "1바퀴"로 적음). 서브에이전트 호출은 0건(현경 답, 2026-11-19). (근거: docs/agents.md · 1.4 쓰지 않은 것, 2.1 저장소 밖 스킬)
- 위키 스킬과 랄프 루프: spec 012는 위키 스킬 3개(wiki-ingest·wiki-query·wiki-lint)를 만들고, 6단계에서 랄프 루프로 찾기를 다듬은 기록을 남겼다. (근거: docs/specs/012-위키-챗봇/plan.md · 1단계 작업, 6단계 작업) (근거: docs/specs/012-위키-챗봇/ralph-progress.md · 머리말)

## 충돌
- (풀림) 현경 PC의 서브에이전트·스킬 사용과 저장소 스킬 10개 ↔ 위키 스킬 3개: agents.md가 2026-11-19에 1.4·2절을 고쳐 랄프 루프와 위키 스킬 3개(13개)를 적었다. (근거: docs/agents.md · 머리말, 1.4 쓰지 않은 것, 2. 스킬 (P3-24))
- (풀림) 저장소 스킬 수 13개 ↔ 15개, ui-ux-pro-max가 저장소 밖인지: agents.md가 2026-11-23에 2절을 15개로 고치고 2.1절에서 ui-ux-pro-max를 2절 표로 옮겼다고 적어 팀-알림 #1과 같아졌다. (근거: docs/agents.md · 2. 스킬 (P3-24), 2.1 저장소 밖 스킬) (근거: docs/specs/022-디자인-전체-수정/팀-알림-모음.md · #1)
