# 팀-서브에이전트와 스킬 기록

> 팀이 실제로 쓴 서브에이전트(일을 나눠 맡기는 별도 Claude 도우미)와 스킬, 그리고 만드는 쪽과 검토하는 쪽을 나눈 사례(P3-24, P3-25).

## 내용
- 기록 원칙: 실제로 쓴 것만 적고, 확인 못 한 곳은 "확인 필요"로 둔다. 직접 만든 서브에이전트 설정(`.claude/agents/`)은 저장소에 없고, 그때그때 Claude가 띄운 도우미만 있다. (근거: docs/agents.md · 머리말, 1. 서브에이전트)
- 인터뷰 검증 도우미 3명(선우): 서로 모르는 도우미에게 같은 인물 설정으로 다시 인터뷰를 시켰다. 네 번 모두 같은 장면 4개가 나와 "AI가 인물 설정을 늘 같은 이야기로 풀어 쓴 것"으로 보고, 이 기록은 사람 수·빈도의 근거로 세지 않고 가설로만 쓰기로 했다. (근거: docs/agents.md · 1.1 AI 페르소나 인터뷰 검증 도우미 3명)
- 별도 리뷰어(기능 001 12단계, 예림): 기본 general-purpose 서브에이전트에게 "고치지 말고 보고만"으로 맡겨 지적 5건(꼭 고칠 것 0, 고치면 좋은 것 2, 있으면 좋은 것 3). 고친 것은 qa 001 실패와 조치 #14~#17. (근거: docs/agents.md · 1.2 코드 리뷰 도우미 "별도 리뷰어")
- 예림님 도우미 9번: 웹 문서 읽기 4번(공공 API, Vercel 정기 실행 한도, Gemini 문서, 한전 요금표), 조사 3번, 코드 리뷰 2번. 처음 12번으로 센 것은 같은 호출이 두 줄씩 남아 잘못 센 것. (근거: docs/agents.md · 1.3 조사·문서 읽기·코드 리뷰 도우미)
- 저장소 스킬 10개: harness-* 7개(erd, ia, intent, journeys, prd, qa, spec-plan)와 domain-modeling, grill-with-docs, grilling. 쓴 흔적은 산출물(문제정의, IA, 여정, PRD, ERD, Intent, spec·plan·qa)로 남았고, 예림님이 harness 계열을 모두 썼다고 답함. 건별 입력은 확인 필요. (근거: docs/agents.md · 2. 스킬 (P3-24))
- 저장소 밖 스킬: `ponytail-review`(단계 끝 리뷰 7번, 예림), `ui-ux-pro-max`·`react-best-practices`·`composition-patterns`·`claude-api`(예림). 전역 스킬이라 다른 팀원 PC에서는 불리지 않는다. (근거: docs/agents.md · 2.1 저장소 밖 스킬)
- 위키 스킬과 랄프 루프: spec 012는 위키 스킬 3개(wiki-ingest·wiki-query·wiki-lint)를 만들고, 6단계에서 랄프 루프로 찾기를 다듬은 기록을 남겼다. (근거: docs/specs/012-위키-챗봇/plan.md · 1단계 작업, 6단계 작업) (근거: docs/specs/012-위키-챗봇/ralph-progress.md · 머리말)

## 충돌
- 현경(gaangstar) PC의 서브에이전트·스킬 사용: agents.md는 "서브에이전트 호출이 없다, 쓰지 않음", "Skill 도구로 스킬을 부른 기록이 없다"고 적고(근거: docs/agents.md · 1.4 쓰지 않은 것, 2.1 저장소 밖 스킬), spec 012 plan·ralph-progress에는 위키 스킬과 랄프 루프 사용이 적혀 있다(근거: docs/specs/012-위키-챗봇/plan.md · 6단계 작업) (근거: docs/specs/012-위키-챗봇/ralph-progress.md · 머리말). agents.md 기준일(2026-11-18, main `65ed611`)이 그 전이다. 고르지 않는다. agents.md 담당(조각 C1)이 반영할지 정한다.
- 저장소 스킬 수: agents.md는 10개로 적고(근거: docs/agents.md · 2. 스킬 (P3-24)), spec 012 plan은 위키 스킬 3개를 더 만들었다(근거: docs/specs/012-위키-챗봇/plan.md · 1단계 작업). 고르지 않는다.
