# 기능-021 웹 푸시 알림

> 사용자가 기기(브라우저)마다 직접 켜면, 슬랙 알림과 같은 조건·같은 내용의 사건 알림을 브라우저 알림으로 받는다. PRD v1.20 FR-35를 1차로 만든 기능이다.

## 내용
- 상태: spec 승인됨 v0.3(사용자 "추천대로 승인" 2026-11-20, v0.3 "로그아웃 때 끄기" 2026-11-20), plan 승인됨 v0.1(사용자 "모두 승인" 2026-11-20: plan, web-push 3.6.7, 0022), qa "Claude QA 진행 중"(C 7/8, 부분 통과 1: C-2108, H 0/4). (근거: docs/specs/021-웹-푸시-알림/spec.md · 머리말) (근거: docs/specs/021-웹-푸시-알림/plan.md · 머리말) (근거: docs/specs/021-웹-푸시-알림/qa.md · 머리말)
- 문제: 슬랙은 팀 워크스페이스에 가입한 사람만 받을 수 있어, 팀 밖 사용자는 앱을 열기 전까지 사건을 모른다. 대응할 시간이 남았을 때 알아야 하는데 앱을 매일 열지는 않는다. (근거: docs/specs/021-웹-푸시-알림/spec.md · 1. 해결하려는 문제)
- FR-001 이 기기 켜기(MY_030400_TB): 브라우저 허락을 받은 뒤 이 기기를 저장. 거절하면 저장하지 않고 브라우저 설정 안내, 지원하지 않는 브라우저는 안내(아이폰은 홈 화면에 추가한 뒤). FR-002 끄기(다른 기기·슬랙은 그대로). FR-007 로그아웃하면 이 기기 끄기(끄기가 실패해도 로그아웃, 사용자 결정 2026-11-20). (근거: docs/specs/021-웹-푸시-알림/spec.md · FR-001, FR-002, FR-007)
- FR-003 정기 수집에서 새 사건이 생기면 주인이 켠 모든 기기로 보낸다. 내용은 슬랙과 같다(제목, 바뀐 것 전 → 후, 마감일 또는 할 날, 사건 상세 링크). 한 사람에게 한 수집에서 6개 이상이면 하나로 묶는다. FR-004 같은 사건은 같은 사람에게 한 번. FR-005 실패해도 사건은 만들고 실행 기록에 "알림 실패", 다음 수집에 한 번만 다시, "더는 받을 수 없음"이면 그 기기를 지움. FR-006 시험 알림(사건 기록에 남기지 않음). (근거: docs/specs/021-웹-푸시-알림/spec.md · FR-003~FR-006)
- 경계 E1~E8: 기기 여러 개면 모두에게(하나라도 성공하면 "보냄"), 같은 기기 다시 켜도 하나, 같은 브라우저 다른 계정이면 나중 계정 것(한 기기에 한 사람), 구독 만료면 기기 지움, 그 밖 실패는 한 번 더(슬랙과 같음), 운영에 키가 없으면 "아직 쓸 수 없습니다" 안내, 슬랙과 웹 푸시는 따로 켜고 끔, 알림 글에 이름·조건·시군구·AI 요약을 넣지 않음. (근거: docs/specs/021-웹-푸시-알림/spec.md · 경계·예외 상황 E1~E8)
- 결정 Q1~Q3(2026-11-20, 추천대로): 알림 기록은 사람마다 한 번(Q1), 아이폰용 "홈 화면에 추가" 준비(앱 이름·아이콘, Q2), 1차 시연에서 운영 화면으로 실제 기기에 보내도 됨(받는 사람은 직접 켠 팀원, Q3). (근거: docs/specs/021-웹-푸시-알림/spec.md · 6. 확인 필요 사항)
- 하지 않을 것: 카카오톡(이후 범위), 스토어 앱, 사건 말고 다른 알림, 알림에서 바로 승인·거절, 조용한 시간·종류 고르기, 관리자가 다른 사람 기기 보기. (근거: docs/specs/021-웹-푸시-알림/spec.md · 5. 제외 범위)
- 기술(plan): 새 의존성 `web-push` 3.6.7과 `@types/web-push` 3.6.4(4.0.0은 나온 지 2주라 고르지 않음). 새 환경변수 3개 이름 `NEXT_PUBLIC_VAPID_PUBLIC_KEY`·`VAPID_PRIVATE_KEY`·`VAPID_SUBJECT`(값은 대화·코드·문서에 쓰지 않음, 운영 값은 사용자가 Vercel에). 시험은 실제 푸시 서비스를 부르지 않는다. (근거: docs/specs/021-웹-푸시-알림/plan.md · 1. 기술과 버전)
- DB: 마이그레이션 0022로 새 표 `push_subscriptions`(본인만 읽기·지우기, 넣기·바꾸기는 서버만, 관리자도 못 봄)와 `notifications.channel`의 `web_push`. ERD v1.12. (근거: docs/specs/021-웹-푸시-알림/plan.md · 2. 구조와 파일) (근거: docs/ERD.md · #### push_subscriptions, ## 접근 규칙)
- 단계 1~5: DB·순수 함수 → 서버 보내기와 수집 세 곳 연결(실행 기록 `notify` 단계 이름은 그대로) → 서비스 워커·앱 이름·아이콘 → 계정·알림 화면 → QA. 운영 배포는 사용자가 키 3개를 Vercel에 넣고 "배포해줘"라고 할 때. (근거: docs/specs/021-웹-푸시-알림/plan.md · 3. 단계별 접근)
- QA: C-2101~2107 통과. C-2105는 2026-11-20 운영 DB에 0022를 적용하고 칸 6개·RLS·정책 select_own·delete_own만·channel check를 조회했다. C-2108 부분 통과: 앱 안 브라우저가 서비스 워커 등록과 알림 권한을 막아 켜기 성공·시험 알림·끄기·로그아웃 때 끄기는 확인 못 하고 사람 QA H-2101~2104로 넘김. (근거: docs/specs/021-웹-푸시-알림/qa.md · 1. Claude QA)
- 실패와 조치 10건: 리뷰 지적으로 응답 없음 판정 좁힘, 지운 기기 다시 보내기 막음, 한쪽 실패 때 다른 쪽 결과 보존, 6개 묶음은 먼저 켠 기기에만, 로그인 검사 예외(서비스 워커·아이콘), 받을 주소를 실제 푸시 서비스 호스트만 받게 함(#8), 흐름 화면 상자 이름 "알림(슬랙·웹 푸시)"과 라벨 한국어(#10, PR #44 리뷰). (근거: docs/specs/021-웹-푸시-알림/qa.md · 3. 실패와 조치)

## 충돌
- 문서 상태: Intent 문서 지도 27행은 "spec v0.2 승인, plan 초안 v0.1(승인 전)"이고(근거: docs/Intent.md · ## 6. 문서 지도 27), plan 머리말은 "승인됨 v0.1(모두 승인 2026-11-20)", spec은 v0.3이다(근거: docs/specs/021-웹-푸시-알림/plan.md · 머리말) (근거: docs/specs/021-웹-푸시-알림/spec.md · 머리말). 고르지 않는다.
- 진행 표시: plan 3절 체크 칸은 1~5가 모두 비어 있고(근거: docs/specs/021-웹-푸시-알림/plan.md · 3. 단계별 접근), qa 변경 기록은 1~4단계 절차 B를 마쳤다고 적는다(근거: docs/specs/021-웹-푸시-알림/qa.md · 4. 변경 기록). 고르지 않는다.
- 로그아웃 때 구독: qa 변경 기록은 "로그아웃 때 구독 — spec에 없어 사용자 결정 대기"라 적고(근거: docs/specs/021-웹-푸시-알림/qa.md · 4. 변경 기록 3·4단계 ponytail-review), spec v0.3은 FR-007로 정했다(근거: docs/specs/021-웹-푸시-알림/spec.md · FR-007, 변경 기록 v0.3). 고르지 않는다.
- 한 번 보내는 단위: PRD FR-35는 "같은 사건은 기기마다 한 번"이라 적고(근거: docs/PRD.md · ## 7. 기능 요구사항 FR-35), spec Q1·ERD notifications는 "사람마다 한 번 기록(기기 중 하나라도 보내면 sent)"이다(근거: docs/specs/021-웹-푸시-알림/spec.md · Q1) (근거: docs/ERD.md · #### notifications). 고르지 않는다.
- 흐름 화면 알림 상자 이름: flow.md는 5번 상자를 "슬랙 알림"으로 적고(근거: docs/flow.md · 2.2 단계 상자), qa 021 실패와 조치 #10은 상자 이름을 "알림(슬랙·웹 푸시)"로 바꿨다(근거: docs/specs/021-웹-푸시-알림/qa.md · 3. 실패와 조치 #10). 고르지 않는다.
- 설정 탭 이름은 [[기능-022 디자인 전체 수정]]의 충돌 절에 있다(spec 021은 "계정·알림").
