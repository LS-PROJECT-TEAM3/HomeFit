# 팀-시연 순서

> 발표 시연 장면 9개와 시연 전 준비, 발표 중 문제가 생기면 할 일. 관리자가 가짜 자료를 넣으면 수집 → 사건 → 알림이 생기고, 사용자가 승인해야 일정에 들어간다(P3-34, P3-06, P3-08).

## 내용
- 상태: 초안 v0.1(팀 확인 전, 조각 C2, 2026-11-23 맡을 사람·남은 일 갱신). 화면·묶음 이름은 코드에서 확인했고, 운영에서 처음부터 끝까지 돌려 본 기록은 없다. (근거: docs/demo-order.md · 머리말)
- 장면 9개: 1 수집 현황·오류(P3-17) → 2 시뮬레이터 가짜 공고(P3-06) → 3 흐름 화면(P3-08) → 4 가상 계정에서 알림 → 승인 → 내 일정, 관리자 화면엔 승인 버튼 없음(P3-04) → 5 실패 묶음은 수집 오류(P3-02, P3-08) → 6 예보·시세 묶음으로 사건 종류 셋(P3-03) → 7 채점 결과(P3-06) → 8 기록 찾기(P3-05) → 9 위키 챗봇(P3-20·21). 시간이 모자라면 6·8·9를 줄이고 2·3·4·5·7은 지킨다. (근거: docs/demo-order.md · 1. 한눈에)
- 시연 전 준비: 관리자·가상 계정 창 둘(로그인 정보는 팀 비공개 채널에만), 운영 `SIMULATION_USER_IDS` 확인, 같은 묶음은 알림을 두 번 만들지 않음(spec 005 E3), 가상 계정이 공고를 팔로우해 둠(팔로우한 공고가 바뀔 때만 사건), AI 요약용 `AI_PROVIDER`와 키, 끝난 알림이 있는 계정. (근거: docs/demo-order.md · 2. 시연 전 준비)
- 장면 2 주의: `changed` 묶음은 마감일만 하루 늦춘다(월세·공급 유형은 그대로). 발표에서 "마감일이 하루 늦어졌습니다"라고 말한다. (근거: docs/demo-order.md · 장면 2)
- 장면 5 주의(2026-11-19 고침): 실패 묶음을 돌리면 수집 현황의 최근 실행 표에 "시뮬레이터 · 수집 오류" 한 줄이 생기는 것을 보여 준다. 시뮬레이터 실행은 연속 실패 수에 들어가지 않아 그 수는 그대로다. (근거: docs/demo-order.md · 장면 5)
- 장면 7 숫자: 28건 중 맞힘 11, 놓침 0, 잘못 울림 0, 조용히 맞음 17(2026-11-18 `eval/results.json`). 발표 직전 `npm run eval`로 다시 확인. (근거: docs/demo-order.md · 장면 7)
- 장면 8 주의: 알림 상세의 "비슷한 지난 알림"은 낱말이 겹치는 순으로 찾는다. AI·임베딩을 쓰지 않으니 RAG라고 말하지 않는다. (근거: docs/demo-order.md · 장면 8)
- 발표 중 문제: 새 알림 0건 → 다른 묶음으로, "대상 0곳" → 로컬 화면으로, AI 요약 안 나옴 → 기본 체크리스트가 정상 동작, 발표 직전 배포는 피함, 운영 화면 안 열림 → 로컬 `npm run dev`. (근거: docs/demo-order.md · 4. 발표 중 문제가 생기면)
- 장면 9 위키 챗봇(관리자, P3-20·21): 정답표 질문으로 세 갈래를 한 번씩 보인다. 위키에 답이 있는 질문(출처 쪽을 펼침), 위키에 없는 질문("위키에 없습니다"), 문서끼리 어긋난 곳을 묻는 질문(두 출처와 함께). 하루 20번 한도, "모의 답" 표시면 발표에 쓰지 않음, 질문은 chat_logs에 남으니 개인정보·키를 넣지 않음. 장면 9를 넣을지·누가 맡을지는 팀이 정한다(조각 A는 현경). (근거: docs/demo-order.md · 장면 9, 5. 확인하지 못한 것 / 정할 것)
- 장면 9 정답표 결과: 실제 Gemini로 6문항 중 6개 맞았지만 Q5·Q6 정답 문장을 고치기 전(옛 정답) 기준이라 새 정답으로 다시 돌려야 한다. 확인 스크립트로 한 번 돌린 결과이고 운영 화면에서 물은 기록은 아니다. (근거: docs/demo-order.md · 장면 9)
- 맡을 사람(2026-11-23 갱신, PR #63 지적 반영): PR #63 설명 기준 팀 결정은 "발표 슬라이드는 서윤, 시연은 선우가 10장 뒤에 혼자"다. 다만 이 결정이 나온 슬랙·회의 기록은 원본도 확인하지 못했다고 적는다. 시연 길이는 정하지 않았고, 장면 9를 넣을지·누가 말할지는 팀이 정한다(조각 A는 현경). (근거: docs/demo-order.md · 5. 확인하지 못한 것 / 정할 것)
- 슬라이드 18장에서 뺀 "발표 준비" 남은 일(2026-11-23, PR #63): 시연 리허설(날짜를 정하고 운영에서 처음부터 끝까지), 사람 QA 빈 칸과 DB 적용 기록(0018, 0021~0025) 맞추기, 설문 수집 경로 확인, 강사 계정을 저장소에 초대하기. 어느 것도 완료를 확인하지 못했다. (근거: docs/demo-order.md · 5. 확인하지 못한 것 / 정할 것)

## 확인 필요
- 운영 주소에서 처음부터 끝까지 돌린 리허설 결과를 qa 005 H-501에 팀이 적는다. (근거: docs/demo-order.md · 5. 확인하지 못한 것 / 정할 것)
- 시연 길이, 운영 `AI_PROVIDER` 정확한 값, `SIMULATION_USER_IDS`가 가상 계정과 맞는지, 운영 DB에 `sample` 기준 공고가 있는지. (근거: docs/demo-order.md · 2. 시연 전 준비, 5. 확인하지 못한 것 / 정할 것)
  - "누가 화면을 누르고 누가 말할지"는 일부 풀림: PR #63 설명 기준 슬라이드 서윤·시연 선우로 적혔다. 결정 기록(슬랙·회의)은 원본도 확인 못 했으니 팀에 확인. (근거: docs/demo-order.md · 5. 확인하지 못한 것 / 정할 것)
- 발표 준비 남은 일 4가지(리허설, 사람 QA 빈 칸·DB 적용 기록 맞추기, 설문 수집 경로, 강사 계정 초대)의 완료 여부. 조각 C2·팀에 확인. (근거: docs/demo-order.md · 5. 확인하지 못한 것 / 정할 것)
- spec 005가 "초안 v0.1(승인 전)"인데 시연의 중심 기능이다. 팀이 승인할지 정한다. (근거: docs/demo-order.md · 5. 확인하지 못한 것 / 정할 것)
