# 화면-흐름 화면

> 관리자 메뉴의 흐름 화면(`/admin/flow`). 미리 그린 그림이 아니라 실행 기록(`runs`, `run_steps`)을 읽어 상자와 화살표를 그린다(P3-08).

## 내용
- 상태: 초안 v0.6, 캡처 4장(2026-11-23 오전 PR #47 새 디자인으로 다시 찍은 v0.5에 이어, 같은 날 오후 PR #52 디자인 2차가 배포된 운영 화면에서 다시 찍음, main `e8050f7`). 코드와 캡처에서 확인한 것만 적고, 화면은 5절 네 장면을 운영에서 관리자 가상 계정으로 열어 보고 감지 상자 하나와 시작 상자·"실패만" 거르기를 눌러 본 것까지다. 코드는 `flow/graph.ts`, `app/(main)/admin/flow/`, `watch/run-log.server.ts`. (근거: docs/flow.md · 머리말)
- 세 부분: 시작 상자(출처마다 하나씩 4개, 그 출처의 최근 실행 상태), 단계 흐름(고른 실행의 단계 상자 7개와 화살표, 화살표 위 건수, 상자를 누르면 상세), 다른 실행 보기(최근 30건). 주소에 `?run=<실행 ID>`가 붙어 새로고침해도 같은 실행이 보인다. (근거: docs/flow.md · 1. 한눈에)
- 시작 상자 4종: 마이홈 공고(`myhome_notice`), 기상청 예보(`kma_forecast`), 온통청년 정책(`youth_policy`), 실거래가(`rtms_trade`). 시작 방식(정기·손으로·시뮬레이터)은 `runs.trigger`에 남고 화면에는 제목과 목록에 글자로 보인다. (근거: docs/flow.md · 2.1 시작 상자 (출처 4종))
- 단계 상자 7개: 수집 `collect` → 비교 `compare` → 감지 `detect` → 계획 초안 `draft_plan`(AI 실패면 기본 체크리스트) → 슬랙 알림 `notify` → 승인 대기 `await_approval`(여기서 멈춤) → 기록 `record`(자리만, 기록하는 코드 없음). (근거: docs/flow.md · 2.2 단계 상자 (7개, 이 순서))
- 상태와 색(글자 라벨 함께): 성공 초록 실선, 실패 빨강, 승인 대기 주황 점선, 실행 중 파랑 점선(시작 상자만, PR #16), 건너뜀 회색 실선, 도달 못 함·아직 안 켜짐 회색 점선. "아직 안 켜짐"은 기록이 없다는 뜻이 아니라 최근 실행 30건 안에 그 출처가 없다는 뜻이다. (근거: docs/flow.md · 2.3 상자 상태와 색, 4. 실패했을 때)
- 온통청년 정책은 감지가 늘 건너뜀(정책 변화 알림은 아직 만들지 않음, spec 006 Q1). (근거: docs/flow.md · 3.3 온통청년 정책)
- 비밀 값은 두 번 가린다: 기록에 쓰기 전(`watch/mask.ts`)과 화면에 그릴 때(`key`·`token`·`secret` 같은 이름이면 `***`). (근거: docs/flow.md · 3.5 비밀 값 가리기)
- 실패할 때: 읽기 실패면 수집 상자 빨강, 뒤 상자는 "도달 못 함", 그림 아래 오류 문구. 시세 일부 실패는 수집 상자 "성공"인데 시작 상자는 "실패". 슬랙·AI 실패는 수집을 실패시키지 않는다. 중간 단계 오류도 `collect` 이름으로 한 줄 남아 어느 단계인지는 오류 문구로 구분한다. (근거: docs/flow.md · 4. 실패했을 때)
- 캡처 4장(선우가 관리자 가상 계정으로 2026-11-23 오후 PR #52 배포 뒤 다시 찍음, 화면 폭 800픽셀, 시뮬레이터를 새로 돌리지 않음, 키·이메일·계정 정보 안 보임): 화면은 최근 30건 안의 실행만 열 수 있어 5.1·5.2·5.4를 30건 안의 실행으로 바꿨다. 5.1 성공은 마이홈 공고 11.23 13:46 정기(수집 들어옴 320·나감 245, 중복 75, 새로 바뀐 공고 0건이라 뒤 상자 건너뜀). 5.2 승인 대기는 시뮬레이터가 아니라 기상청 예보 11.22 18:16 실제 정기 수집이 사람 승인 앞에서 멈춘 모습(감지 6 → 2, 알림 2 → 1). 5.3 실패는 앞판과 같은 마이홈 11.20 09:01 시뮬레이터 `failure` 묶음(키 `***` 가림, 쉬운 오류 문장). 5.4 상세는 5.2 실행의 감지 단계 기록(위험 없음 3, 새 알림 2, 같은 48시간 창 중복 막음 1 등)이 한국어로 보여 같은 변화가 사건을 두 번 만들지 않는 것이 숫자로 보인다. (근거: docs/flow.md · 5. 화면 캡처, 5.1~5.4)
- PR #52로 바뀐 화면: 시작 상자를 누르면 그 출처의 가장 최근 실행으로 바뀌고 보는 상자에 색과 ▼ 표시, 단계 상자를 누르면 그림 아래 "단계 기록 칸"에 상세(처음엔 수집 단계), 실행 목록은 처음 10줄과 "더 보기", "전체 / 실패만 N" 거르기(주소 `&runs=failed`), 수집 실패 때 쉬운 오류 문장(`friendlyRunError`)과 "원문 보기". 800픽셀에서 단계 상자는 한 줄에 3개씩 세 줄, PR #47 때의 "보는 중" 글자는 없어졌다. (근거: docs/flow.md · 1. 한눈에, 4. 실패했을 때, 5.5 캡처에서 보이는 점)
- `?run=` 주소는 최근 30건 안에서만 찾으므로, 30건 밖으로 밀려난 실행 주소를 열면 가장 최근 실행이 대신 보인다(`app/(main)/admin/flow/page.tsx`). 5.3 실패 실행은 2026-11-23 오후 기준 30건 중 25번째라 실행이 더 쌓이면 고를 수 없게 된다. (근거: docs/flow.md · 1. 한눈에, 5.3 실패한 실행)
- spec 021 이후 알림 단계는 슬랙과 웹 푸시를 함께 보내고, 실행 기록 `notify` 단계 detail에 둘을 따로 남긴다(단계 이름은 그대로). 흐름 화면 상자 이름은 "알림(슬랙·웹 푸시)"로 바뀌었다(qa 021 #10). (근거: docs/specs/021-웹-푸시-알림/plan.md · 2. 구조와 파일) (근거: docs/specs/021-웹-푸시-알림/qa.md · 3. 실패와 조치 #10)
- 안내서와 다른 8곳(시작 방식 상자, 분기 건수, 승인 뒤 조치·기록 연결, 호출 주소·응답 코드·걸린 시간, 목록의 걸린 시간, 단계 "실행 중", 흐름 정의 파일 이름, spec 005의 3종). 예림님 제안은 고치지 않고 발표에서 설명. (근거: docs/flow.md · 6. 안내서 기준과 다른 점)

## 충돌
- 시작 상자가 무엇인가: PRD FR-23과 spec 005 FR-003은 흐름 화면의 "시작 상자 3종"을 적고(근거: docs/PRD.md · ## 7. 기능 요구사항 FR-23) (근거: docs/specs/005-관리자-시연-기록찾기/spec.md · FR-003), flow.md는 시작 상자가 출처 4종이고 시작 방식 3종은 글자로만 보인다고 적는다(근거: docs/flow.md · 2.1 시작 상자 (출처 4종), 6. 안내서 기준과 다른 점). 고르지 않는다. 팀이 정한다.

- 알림 상자 이름: 풀림. flow.md 2.2절 5번 상자가 "알림(슬랙·웹 푸시)"이고 PR #44 전 이름이 "슬랙 알림"이었다고 적어 qa 021 #10과 같다. (근거: docs/flow.md · 2.2 단계 상자 (7개, 이 순서), 5.5 캡처에서 보이는 점) (근거: docs/specs/021-웹-푸시-알림/qa.md · 3. 실패와 조치 #10)

## 확인 필요
- 안내서와 다른 8곳을 고칠지, 발표에서 설명할지 팀 결정 대기(예림님 제안만 있음). (근거: docs/flow.md · 6. 안내서 기준과 다른 점)
- 일부 시군구 실패, 슬랙 실패, 중간 단계 실패, 승인·거절 뒤 모습, "실행 중"·"아직 안 켜짐" 색은 화면으로 확인하지 못했다. 웹 푸시 실패 모습도 flow.md에 없다. (근거: docs/flow.md · 7. 이 문서에서 확인하지 못한 것)
- 2.3절 색 이름(초록 실선·회색 점선)과 PR #52의 ⓘ 설명 문장은 새 디자인 화면(진한 녹회색 선·옅은 선)과 다르다고 flow.md가 직접 적는다. 표와 ⓘ 문장을 고칠지 flow.md 담당(조각 C1)과 화면 담당에게 확인. (근거: docs/flow.md · 2.3 상자 상태와 색, 7. 이 문서에서 확인하지 못한 것)
