# 화면-흐름 화면

> 관리자 메뉴의 흐름 화면(`/admin/flow`). 미리 그린 그림이 아니라 실행 기록(`runs`, `run_steps`)을 읽어 상자와 화살표를 그린다(P3-08).

## 내용
- 상태: 초안 v0.2, 캡처 4장. 코드와 캡처로 확인한 것만 적었고 화면을 직접 눌러 보지는 않았다. 코드는 `flow/graph.ts`, `app/(main)/admin/flow/`, `watch/run-log.server.ts`. (근거: docs/flow.md · 머리말)
- 세 부분: 시작 상자(출처마다 하나씩 4개, 그 출처의 최근 실행 상태), 단계 흐름(고른 실행의 단계 상자 7개와 화살표, 화살표 위 건수, 상자를 누르면 상세), 다른 실행 보기(최근 30건). 주소에 `?run=<실행 ID>`가 붙어 새로고침해도 같은 실행이 보인다. (근거: docs/flow.md · 1. 한눈에)
- 시작 상자 4종: 마이홈 공고(`myhome_notice`), 기상청 예보(`kma_forecast`), 온통청년 정책(`youth_policy`), 실거래가(`rtms_trade`). 시작 방식(정기·손으로·시뮬레이터)은 `runs.trigger`에 남고 화면에는 제목과 목록에 글자로 보인다. (근거: docs/flow.md · 2.1 시작 상자 (출처 4종))
- 단계 상자 7개: 수집 `collect` → 비교 `compare` → 감지 `detect` → 계획 초안 `draft_plan`(AI 실패면 기본 체크리스트) → 슬랙 알림 `notify` → 승인 대기 `await_approval`(여기서 멈춤) → 기록 `record`(자리만, 기록하는 코드 없음). (근거: docs/flow.md · 2.2 단계 상자 (7개, 이 순서))
- 상태와 색(글자 라벨 함께): 성공 초록 실선, 실패 빨강, 승인 대기 주황 점선, 실행 중 파랑 점선(시작 상자만, PR #16), 건너뜀 회색 실선, 도달 못 함·아직 안 켜짐 회색 점선. "아직 안 켜짐"은 기록이 없다는 뜻이 아니라 최근 실행 30건 안에 그 출처가 없다는 뜻이다. (근거: docs/flow.md · 2.3 상자 상태와 색, 4. 실패했을 때)
- 온통청년 정책은 감지가 늘 건너뜀(정책 변화 알림은 아직 만들지 않음, spec 006 Q1). (근거: docs/flow.md · 3.3 온통청년 정책)
- 비밀 값은 두 번 가린다: 기록에 쓰기 전(`watch/mask.ts`)과 화면에 그릴 때(`key`·`token`·`secret` 같은 이름이면 `***`). (근거: docs/flow.md · 3.5 비밀 값 가리기)
- 실패할 때: 읽기 실패면 수집 상자 빨강, 뒤 상자는 "도달 못 함", 그림 아래 오류 문구. 시세 일부 실패는 수집 상자 "성공"인데 시작 상자는 "실패". 슬랙·AI 실패는 수집을 실패시키지 않는다. 중간 단계 오류도 `collect` 이름으로 한 줄 남아 어느 단계인지는 오류 문구로 구분한다. (근거: docs/flow.md · 4. 실패했을 때)
- 캡처 4장(예림, 2026-11-18 운영): 성공, 승인 대기에서 멈춤, 수집 실패, 상자 상세. 상세의 영어·JSON 표시는 PR #16에서 한국어로 고쳐져 발표용으로는 다시 찍어야 한다. (근거: docs/flow.md · 5. 화면 캡처)
- 안내서와 다른 8곳(시작 방식 상자, 분기 건수, 승인 뒤 조치·기록 연결, 호출 주소·응답 코드·걸린 시간, 목록의 걸린 시간, 단계 "실행 중", 흐름 정의 파일 이름, spec 005의 3종). 예림님 제안은 고치지 않고 발표에서 설명. (근거: docs/flow.md · 6. 안내서 기준과 다른 점)

## 충돌
- 시작 상자가 무엇인가: PRD FR-23과 spec 005 FR-003은 흐름 화면의 "시작 상자 3종"을 적고(근거: docs/PRD.md · ## 7. 기능 요구사항 FR-23) (근거: docs/specs/005-관리자-시연-기록찾기/spec.md · FR-003), flow.md는 시작 상자가 출처 4종이고 시작 방식 3종은 글자로만 보인다고 적는다(근거: docs/flow.md · 2.1 시작 상자 (출처 4종), 6. 안내서 기준과 다른 점). 고르지 않는다. 팀이 정한다.

## 확인 필요
- 안내서와 다른 8곳을 고칠지, 발표에서 설명할지 팀 결정 대기(예림님 제안만 있음). (근거: docs/flow.md · 6. 안내서 기준과 다른 점)
- 일부 시군구 실패, 슬랙 실패, 중간 단계 실패, 승인·거절 뒤 모습, 실제 색은 화면으로 확인하지 못했다. (근거: docs/flow.md · 7. 이 문서에서 확인하지 못한 것)
