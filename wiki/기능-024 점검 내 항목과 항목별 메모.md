# 기능-024 점검 내 항목과 항목별 메모

> 입주 전 점검에서 관심 주택마다 내 항목을 더하고, 항목마다 메모를 쓰며, 기본 항목을 7개에서 12개로 늘린 기능. DB 칸은 늘리지 않고 같은 점검 칸에 담는다. PRD v1.22·v1.23 FR-29를 만들었다.

## 내용
- 상태: spec 승인됨 v0.3(사용자 "승인" 2026-11-23), plan 머리말 "승인됨 v0.1"(사용자 "승인" 2026-11-23, 변경 기록에는 v0.2까지), qa "완료"(C 9/10, 부분 1: 관심 주택이 한 곳이라 다른 집 오가기 확인 못 함, H 1/1). (근거: docs/specs/024-점검-내항목-메모/spec.md · 머리말) (근거: docs/specs/024-점검-내항목-메모/plan.md · 머리말, 변경 기록) (근거: docs/specs/024-점검-내항목-메모/qa.md · 머리말)
- 출처: PR #47 "추가하면 좋은 것", 캔버스 v2-qc-check 보드의 "+ 항목 추가"·항목 메모. spec 022 v0.5에서 "추후 기능"으로 미뤘던 것을 이번에 만든다. (근거: docs/specs/024-점검-내항목-메모/spec.md · 머리말 근거 문서, 변경 기록 v0.1)
- 문제: 정해진 점검 7개(채광·소음·냄새·곰팡이·수압·관리비·창 종류)와 집마다 메모 하나뿐이라, 집마다 보고 싶은 것(주차·엘리베이터 등)을 더할 수 없고 "어느 항목에서 무엇을 봤는지"가 한 칸에 섞여 여러 집을 비교하기 어렵다. (근거: docs/specs/024-점검-내항목-메모/spec.md · 1. 해결하려는 문제)
- FR-001 관심 주택 한 곳에만 내 항목을 더한다(집마다 10개, 이름 40자). FR-002 내 항목은 이름 고치기·지우기, 기본 항목은 못 지움. FR-003 모든 항목에 메모 200자, 집 전체 메모 500자는 그대로. FR-004 저장 버튼으로 한 번에 저장, 저장 안 한 변경은 알림. FR-005 이 기능 전에 저장한 체크·집 메모는 그대로 보임. FR-006 "확인한 항목 N / 전체"와 집 고르기 목록의 확인 수에 내 항목도 셈(spec에 "가정" 표시). (근거: docs/specs/024-점검-내항목-메모/spec.md · FR-001~FR-006) (근거: docs/PRD.md · FR-29 v1.22)
- FR-007(v0.3) 기본 항목 7 → 12개: 배수, 난방·보일러, 전기·콘센트, 방범, 누수 흔적을 더함. 예전 7개 체크·메모는 그대로, 새 5개는 확인 안 함으로 시작. 누수는 보이는 자국만 기록하고 예측하지 않는다(사용자 "추천 5개 더해"). (근거: docs/specs/024-점검-내항목-메모/spec.md · FR-007, 변경 기록 v0.3) (근거: docs/PRD.md · FR-29 v1.23)
- 경계 E1~E8: 빈 이름 → "항목 이름을 적어 주세요"(E1), 40자·10개 넘으면 한도 안내(E2), 같은 집에 같은 이름(앞뒤 공백 무시)이나 기본 항목 제목과 같은 이름은 막음(E3, "가정" 표시), 항목 메모 200자 넘으면 어느 항목인지 알림(E4), 저장 값의 모르는 키·틀린 내 항목은 버리고 예전 형식은 그대로 읽음(E5), 내 항목을 지우면 그 체크·메모도 지움(E6), 남의 점검은 못 읽고 못 고침(E7), 저장 실패 때 입력 유지 + 안내(E8). (근거: docs/specs/024-점검-내항목-메모/spec.md · 경계·예외 상황 E1~E8)
- 결정(2026-11-23): spec을 둘로 나눠 점검이 024, 도시가스가 025(Q1), 내 항목은 집마다 따로·한도 10개·40자·메모 200자·집 메모 500자 유지·예전 값 그대로 읽음(Q2), PRD v1.22·ERD v1.14 설명을 먼저 고침, DB 변경 없음(Q3). (근거: docs/specs/024-점검-내항목-메모/spec.md · 6. 확인 필요 사항)
- 하지 않을 것: 모든 집에 같이 쓰는 "내 기본 목록", 기본 항목 지우기·이름 바꾸기, 항목 순서 바꾸기(내 항목은 기본 뒤에 더한 순서), 점검 결과로 안전·적합 판정, 점검 항목에 사진 붙이기. (근거: docs/specs/024-점검-내항목-메모/spec.md · 5. 제외 범위)
- 기술·DB: 새 라이브러리 없음, 마이그레이션 없음. `interest_homes.move_in_checklist`(jsonb 객체, 0021)에 기본 항목 체크는 지금처럼 `키: true`로 두고 `notes`(기본 항목 키 → 메모)와 `custom`(내 항목: id, 이름, 체크, 메모)을 더한다. 순수 함수는 `incident/move-in-checklist.ts`, 새 화면 부품은 `checklist-item.tsx`·`add-custom-item.tsx`, AI 도우미 자료(`knowledge/chat-sources.ts`)도 새 모양에 맞춤. v0.2에서 `MOVE_IN_ITEMS`에 키 5개(drain, heating, electric, security, leak). (근거: docs/specs/024-점검-내항목-메모/plan.md · 1. 기술과 버전, 2. 구조와 파일, 변경 기록 v0.2) (근거: docs/ERD.md · interest_homes.move_in_checklist, 변경 기록 v1.14)
- 단계 1~2(모두 체크): 1 시험 먼저와 저장 액션·화면·AI 도우미 자료를 새 타입에 맞춤(화면 모양은 그대로) → 2 항목 메모 펼치기, "+ 항목 추가", 내 항목 고치기·지우기, 확인 수. (근거: docs/specs/024-점검-내항목-메모/plan.md · 3. 단계별 접근)
- Claude QA: C-2401~2407, C-2409, C-2410 통과. 함수 시험(예전 값 읽기, 틀린 값 버리기, 이름 검사, 200/201자, 확인 수 "3 / 9"), 전체 시험 802개·tsc·lint·build 통과, 미리보기에서 기본 12개 + 내 항목 = "2 / 13". C-2408은 부분 통과(저장 뒤 다시 열면 그대로인 것은 확인, 다른 집 오가기는 관심 주택이 한 곳뿐이라 H-2401로 넘김). (근거: docs/specs/024-점검-내항목-메모/qa.md · 1. Claude QA)
- 사람 QA: H-2401 처음 실패("입주전 점검 저장란이 챗봇에 가려져") → 조치 뒤 재확인 통과(사용자 "둘 다 통과", 2026-11-23). (근거: docs/specs/024-점검-내항목-메모/qa.md · 2. 사람 QA)
- 실패와 조치 5건: 틀린 id·공백 붙은 40자 이름이 저장 뒤 조용히 사라짐 → 서버 검사에서 거절(#1), 체크를 껐다 켜면 "저장하지 않은 변경"이 잘못 뜸 → 순서와 무관한 비교(#2), 저장 중 고친 내용이 저장된 것으로 기록될 수 있음(#3), 키보드 초점이 사라지고 메모 버튼 이름이 없음(#4), 휴대폰에서 저장 버튼이 떠 있는 챗봇·맨 위로 버튼에 가려짐 → 앱 틀 아래 여백(휴대폰 104px, PC 64px)을 모든 화면에 같이 적용(#5). (근거: docs/specs/024-점검-내항목-메모/qa.md · 3. 실패와 조치)
- PR: Intent 문서 지도 29행은 PR #51로 적는다. (근거: docs/Intent.md · ## 6. 문서 지도 29)

## 충돌
- plan 버전: plan 머리말은 "승인됨 v0.1"이고 근거를 "spec 024 v0.2"로 적는데(근거: docs/specs/024-점검-내항목-메모/plan.md · 머리말), 같은 plan 변경 기록에는 v0.2(spec v0.3 FR-007 반영)가 있고(근거: docs/specs/024-점검-내항목-메모/plan.md · 변경 기록 v0.2), Intent 문서 지도 29행은 "spec v0.3·plan v0.2 승인"이다(근거: docs/Intent.md · ## 6. 문서 지도 29). 고르지 않는다.
- 기본 항목 수: spec FR-002와 Q2 답은 "기본 7개 항목은 지우지 못한다"이고(근거: docs/specs/024-점검-내항목-메모/spec.md · FR-002, Q2), 같은 spec FR-007과 제외 범위는 기본 항목을 12개로 적는다(근거: docs/specs/024-점검-내항목-메모/spec.md · FR-007, 5. 제외 범위). PRD도 v1.22 "기본 7개는 그대로", v1.23 "기본 항목 12개"로 둘 다 남아 있다(근거: docs/PRD.md · 변경 이력 v1.22, v1.23). 고르지 않는다.

## 확인 필요
- C-2408은 qa에 "부분 통과"로 남아 있고 다른 집 오가기는 H-2401에서 확인했다고만 적었다. C-2408 결과를 바꿀지 qa 담당(예림)에게 확인. (근거: docs/specs/024-점검-내항목-메모/qa.md · C-2408, 머리말)
- spec FR-006과 E3에 붙은 "가정" 표시가 승인 뒤에도 남아 있다. 확정인지 spec 담당에게 확인. (근거: docs/specs/024-점검-내항목-메모/spec.md · FR-006, E3)
- 실패와 조치 #5의 앱 틀 아래 여백은 모든 화면의 마지막 버튼에 같이 적용됐다. 이 화면 말고 다른 화면을 다시 확인했는지는 원본에 없다. 디자인 담당에게 확인. (근거: docs/specs/024-점검-내항목-메모/qa.md · 3. 실패와 조치 #5)
