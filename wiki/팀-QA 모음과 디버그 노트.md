# 팀-QA 모음과 디버그 노트

> 기능별 QA 결과를 한 곳에 모은 표, 자동 채점, 사람 QA 목록, 그리고 실패 → 규칙 반영 → 재검사 사례(P3-26, P3-32).

## 내용
- 원본은 기능별 `docs/specs/NNN-기능/qa.md`다. 모음 문서는 결과를 모으고 남은 문제와 사람 QA를 따로 보여 주며, 같은 내용을 다시 쓰지 않고 번호로 잇는다. Claude QA(C-)와 사람 QA(H-)를 나누고, 통과=Pass, 실패=Fail, 확인 못 함=No Run, 부분 통과는 팀 말이다. (근거: docs/qa.md · 머리말, 0. 읽는 법)
- 기능 001~020 합계(기준일 2026-11-19, main `32444a4`, PR #19·#21·#24까지. 015~020 사람 QA는 2026-11-20 값): Claude QA 191건 중 통과 149, 부분 통과 39, 확인 못 함 3(001 C-030, 013 C-1303, 014 C-1404), 실패 0. 사람 QA 36건 중 결과가 적힌 것 22건(통과 21, 확인 못 함 1: 018 H-1801). 004는 표의 C-410을 더해 10건으로 센다(머리말 요약과 다름). 012 번호(C-901~912, H-901~906)는 009와 겹치는데, 기능 번호를 바꿀 때 QA ID를 그대로 두기로 했기 때문이다. (근거: docs/qa.md · 머리말, 1. 기능별 한눈에)
- 2026-11-23 갱신(모음): 022는 PR #47 뒤, 023~026은 PR #51·#55(main `ba12bd2`) 뒤 더했고, 022 상태는 PR #52 뒤 머리말로 다시 옮겼다. 001~026 합계 Claude QA 263건 중 통과 215, 부분 통과 43, 확인 못 함 5, 실패 0. 사람 QA 49건 중 결과가 적힌 것 34건(통과 33, 확인 못 함 1), 비어 있는 것 15건. 023 C 12/12·H 2/2, 024 C 9/10(부분 통과 C-2408: 관심 주택이 한 곳이라 다른 집 오가기 못 봄)·H 1/1, 025 C 11/11·H 1/1, 026 C 10/10·H 1/1, 모두 "완료". 022는 "Claude QA 진행 중(C-2202·C-2204 남음), 사람 QA 남음" C 15건 중 통과 13·확인 못 함 2, H 0/3. 부분 → 통과로 바뀐 것에 023 C-2302·C-2311이 더해졌다. (근거: docs/qa.md · 머리말, 1. 기능별 한눈에, 4. 남은 문제 024) (근거: docs/specs/023-결정-되돌리기/qa.md · 머리말) (근거: docs/specs/024-점검-내항목-메모/qa.md · 머리말)
- 사람 QA 새 기록(2026-11-23): 012 H-907(위키 그래프)은 qa에 "사용자"로만 적혀 있었는데 현경이 관리자 화면에서 확인했다고 적혔다(현경님 답, 슬랙 2026-11-23). 023~026의 5건(H-2301·H-2302·H-2401·H-2501·H-2601)은 예림이 확인했고, H-2401은 1차 "저장란이 챗봇에 가려짐" 실패 뒤 화면 아래 여백 조치(PR #51)로 재확인 통과(PR #55). 비어 있는 15건은 003 H-201·H-202, 004 H-401, 005 H-501·H-502, 009 H-901, 010 H-1001·H-1002, 021 H-2101~H-2104, 022 H-2201~H-2203. (근거: docs/qa.md · 3. 사람 QA (49건), 5. 이 문서에서 확인하지 못한 것)
- 자동 채점: 정답 붙은 가짜 묶음 28건(공고 10, 습도·결로 8, 시세 10)에서 맞힘 11, 놓침 0, 잘못 울림 0, 조용히 맞음 17. 결과 파일 `eval/results.json`(생성 2026-11-18T08:24Z), 화면 `/admin/eval`. 시세 10건은 조각 B(PR #11)에서 더해짐. (근거: docs/qa.md · 2. 자동 채점 (감지 맞히기))
- 사람 QA: 001~011의 13건과 013 H-1301은 예림님, 012 H-902는 현경·예림 둘 다, 015~020의 7건은 선우가 운영 화면에서 관리자 가상 계정으로 확인했다(2026-11-20). 비어 있는 14건은 003 H-201·H-202, 004 H-401, 005 H-501·H-502, 009 H-901, 010 H-1001·H-1002, 012 H-901·H-903~H-906, 014 H-1401. AI가 대신 통과로 적지 않는다. 015~020 사람 QA 때 운영 DB에 시험 자료("시험용" 관심 주택 3곳 등)가 남았고 남길지 정하지 않았다. 자동 시험은 2026-11-19 main `32444a4`에서 73개 파일 668개 통과(선우). (근거: docs/qa.md · 2. 자동 채점, 3. 사람 QA (36건), 5. 이 문서에서 확인하지 못한 것)
- 실패와 조치 모아 보기: 기능 001~020 합계 63건(001이 20건으로 가장 많음, 013·015~018·020은 0건인데 오류가 없었다는 뜻이 아니라 표에 적힌 것이 없다는 뜻). 새로 고른 사례: PR 리뷰에서 찾은 보안 문제(qa 014 #1·#2), 실패를 "없음"으로 처리(qa 011 #4), 시험 자료가 시험을 깨뜨림(qa 012 #1), 화면을 본 사람이 찾음(qa 019 #1). 대표 종류는 운영 빌드에서만 드러남(Suspense 밖의 `usePathname`, 세 번 반복), 배포 직후 옛 코드로 돎, 운영 설정 빠짐, 375px 넘침, 권한·보안, 같은 변화 겹침·빠짐, 실패를 잘못 다룸, PR 리뷰에서 팀원이 찾음, 실제 API로 찾음, 개발 서버 문제. (근거: docs/debug-note.md · 1. 모아 보기, 2. 어떤 종류의 오류였나)
- 실패와 조치 2026-11-23 추가: 021~026 줄을 main `e8050f7`(PR #44·#47·#51·#52·#55까지)에서 각 qa 표를 줄 단위로 세어 더했다. 021 10건, 022 31건, 023 5건(1건은 고치지 않고 남김), 024 5건(1건은 H-2401에서 나옴), 025 4건, 026 3건으로 합계 121건(020까지 63 + 021~026 58). 3절 사례는 여전히 001~008에서 고른 것이다. (근거: docs/debug-note.md · 머리말, 1. 모아 보기)
- 실패 → 규칙 반영 → 재검사 사례: ① 빌드를 빼먹어 운영 빌드 실패 → `docs/plan.md` 2절에 "커밋 전에 test·tsc·lint·build 넷 다" 규칙 → 운영에서 정책 49건 확인. ② 배포 직후 수집이 옛 배포로 가서 사건 7건 잘못 생김 → `scripts/deploy.mjs`가 새 배포를 확인한 뒤에만 수집하도록 코드로 강제, `tests/deploy.test.ts`. ③ 채점 정답 샘플의 단지 키가 틀림 → 정답만 고침(규칙 반영은 없음). (근거: docs/debug-note.md · 3. 실패 → 규칙 반영 → 재검사 사례)
- 합친 뒤 생긴 오류: PR #1을 squash로 합쳐 `Yelim`과 main 이력이 갈라짐 → 기록만 합치는 병합 커밋으로 풀고 "Create a merge commit(squash 금지)" 규칙을 plan.md에 적음. (근거: docs/debug-note.md · 4. 합친 뒤 생긴 오류)
- 저장소에 자동 검사(CI)는 없어 커밋 전 4종 규칙은 사람이 지킨다. PR #16·#19·#24와 main `32444a4`(668개)는 선우가 직접 4종을 돌려 통과했다. (근거: docs/debug-note.md · 사례 1)
- 아직 열려 있는 것(debug-note 5절 추가분): 사람 QA 14건 비어 있음, qa 014 H-1401(실제 메일로 끝까지 안 해 봄), qa 019 C-1904(H-1902에서 저장·사진·지우기 확인, 내 집을 지우면 사진 파일은 남음), qa 015 #1(근거 글 표시, 담당 확인 대기), 0018·0021을 파일보다 먼저 DB에 적용, 사용자 챗봇이 자료 7가지 중 하나라도 실패하면 답 전체 실패. (근거: docs/debug-note.md · 5. 아직 열려 있는 것)

DB 적용 기록은 0018·0021에 더해 0022~0025도 파일이 합쳐지기 전에 공유 DB에 먼저 적용했고 지금 DB와 다시 대조하지 못했다(connectors.md 6.1·6.2절). qa 023 #5: 승인·거절 취소에 성공하면 버튼이 사라져 키보드 초점이 페이지 맨 앞으로 간다(기존 승인·거절 버튼도 같음), spec 밖이라 고치지 않고 재확인 "확인 못 함".
