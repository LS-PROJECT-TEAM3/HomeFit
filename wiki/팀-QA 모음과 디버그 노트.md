# 팀-QA 모음과 디버그 노트

> 기능별 QA 결과를 한 곳에 모은 표, 자동 채점, 사람 QA 목록, 그리고 실패 → 규칙 반영 → 재검사 사례(P3-26, P3-32).

## 내용
- 원본은 기능별 `docs/specs/NNN-기능/qa.md`다. 모음 문서는 결과를 모으고 남은 문제와 사람 QA를 따로 보여 주며, 같은 내용을 다시 쓰지 않고 번호로 잇는다. Claude QA(C-)와 사람 QA(H-)를 나누고, 통과=Pass, 실패=Fail, 확인 못 함=No Run, 부분 통과는 팀 말이다. (근거: docs/qa.md · 머리말, 0. 읽는 법)
- 기능 001~011 합계: Claude QA 153건 중 통과 121, 부분 통과 31, 확인 못 함 1(001 C-030), 실패 0. 사람 QA 21건 중 결과가 적힌 것 13건. (근거: docs/qa.md · 1. 기능별 한눈에)
- 자동 채점: 정답 붙은 가짜 묶음 28건(공고 10, 습도·결로 8, 시세 10)에서 맞힘 11, 놓침 0, 잘못 울림 0, 조용히 맞음 17. 결과 파일 `eval/results.json`(생성 2026-11-18T08:24Z), 화면 `/admin/eval`. 시세 10건은 조각 B(PR #11)에서 더해짐. (근거: docs/qa.md · 2. 자동 채점 (감지 맞히기))
- 사람 QA: 결과가 적힌 13건은 모두 예림님이 확인했다. 비어 있는 8건은 003 H-201·H-202, 004 H-401, 005 H-501·H-502, 009 H-901, 010 H-1001·H-1002. AI가 대신 통과로 적지 않는다. (근거: docs/qa.md · 3. 사람 QA (21건), 5. 이 문서에서 확인하지 못한 것)
- 실패와 조치 모아 보기: 기능 001~011 합계 58건(001이 20건으로 가장 많음). 대표 종류는 운영 빌드에서만 드러남(Suspense 밖의 `usePathname`, 세 번 반복), 배포 직후 옛 코드로 돎, 운영 설정 빠짐, 375px 넘침, 권한·보안, 같은 변화 겹침·빠짐, 실패를 잘못 다룸, PR 리뷰에서 팀원이 찾음, 실제 API로 찾음, 개발 서버 문제. (근거: docs/debug-note.md · 1. 모아 보기, 2. 어떤 종류의 오류였나)
- 실패 → 규칙 반영 → 재검사 사례: ① 빌드를 빼먹어 운영 빌드 실패 → `docs/plan.md` 2절에 "커밋 전에 test·tsc·lint·build 넷 다" 규칙 → 운영에서 정책 49건 확인. ② 배포 직후 수집이 옛 배포로 가서 사건 7건 잘못 생김 → `scripts/deploy.mjs`가 새 배포를 확인한 뒤에만 수집하도록 코드로 강제, `tests/deploy.test.ts`. ③ 채점 정답 샘플의 단지 키가 틀림 → 정답만 고침(규칙 반영은 없음). (근거: docs/debug-note.md · 3. 실패 → 규칙 반영 → 재검사 사례)
- 합친 뒤 생긴 오류: PR #1을 squash로 합쳐 `Yelim`과 main 이력이 갈라짐 → 기록만 합치는 병합 커밋으로 풀고 "Create a merge commit(squash 금지)" 규칙을 plan.md에 적음. (근거: docs/debug-note.md · 4. 합친 뒤 생긴 오류)
- 저장소에 자동 검사(CI)는 없어 커밋 전 4종 규칙은 사람이 지킨다. (근거: docs/debug-note.md · 사례 1)
