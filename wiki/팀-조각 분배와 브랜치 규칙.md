# 팀-조각 분배와 브랜치 규칙

> 팀이 남은 일을 조각으로 나눈 표(docs/plan.md)와, 이름 브랜치·PR로 함께 작업하는 규칙.

## 내용
- 규칙(팀 결정 2026-11-18): 사람마다 이름 브랜치 하나를 계속 쓰고, 조각 하나가 끝날 때마다 그 브랜치에서 PR 하나를 올린다. 리뷰 1명 이상 뒤 main에 합친다. 기능별 자세한 계획은 `docs/specs/NNN-기능/plan.md`, 확인 결과는 같은 폴더 `qa.md`다. (근거: docs/plan.md · 머리말)
- 0절: 기능 001~008은 처음에 `Yelim` 브랜치에 있었고, 이것을 main에 합친 뒤에 모두 main에서 브랜치를 딴다. (근거: docs/plan.md · ## 0. 먼저: Yelim → main 합치기)
- 조각 A 위키·위키 챗봇(`gaangstar`, P3-20·21, PRD FR-26, DB 번호 0018, 리뷰 예림). 조각 D 디자인 전체 수정(`gaangstar`, 토큰·공통 부품 PR을 먼저 따로). (근거: docs/plan.md · ## 1. 분배)
- 조각 B 관리자 수정 기록·비슷한 지난 알림(RAG)·시세 채점(`Yelim`, P3-13·05·06, DB 0019). 조각 E 알파: 집 비교 실질 주거비(`Yelim`, P3-09, PRD FR-28, DB 0020 `interest_homes`는 ERD에 먼저 올리고 승인). (근거: docs/plan.md · ## 1. 분배)
- 조각 C1 제출 문서(data-sources, connectors, agents, debug-note, qa 모음, ERD와 실제 DB 대조)와 C2 발표·README(slides, README, 시연 순서)는 나머지 두 팀원이 나눠 맡는다. (근거: docs/plan.md · ## 1. 분배)
- 이름 브랜치 쓰는 순서: (1) 시작 전 main을 내 브랜치에 받는다 (2) 조각 하나만 작업·커밋·push (3) `내이름` → `main` PR, 설명 첫 줄에 조각 이름과 출처(예: `조각 A: 위키 챗봇, spec 010 FR-001, P3-21`) (4) 합쳐지면 다음 조각 전에 (1)을 다시 (5) 리뷰 중에는 그 브랜치에 다른 조각을 올리지 않는다. (근거: docs/plan.md · ## 2. 충돌을 줄이는 약속)
- PR은 "Create a merge commit"으로 합친다(squash 금지, 2026-11-18 PR #1 사례). DB 마이그레이션 번호는 표대로(0018 A, 0019 B, 0020 E). (근거: docs/plan.md · ## 2. 충돌을 줄이는 약속)
- 여러 명이 고치는 파일: `lib/supabase/database.types.ts`, `docs/ERD.md`, `docs/Intent.md`, `app/tokens.css`. 늦게 합치는 사람이 충돌을 정리한다. (근거: docs/plan.md · ## 2. 충돌을 줄이는 약속)
- 커밋 전에 넷 다 통과: `npm test`, `npx tsc --noEmit`, `npm run lint`, `npm run build`(2026-11-18 빌드를 빼먹어 운영 배포가 한 번 실패함). 배포는 main에 합친 뒤 한 사람이 한다. (근거: docs/plan.md · ## 2. 충돌을 줄이는 약속)
- 아직 정할 것: (1) 계약 만료 일정의 범위, (2) 알파 범위(교통비 포함 여부, `interest_homes` 칸). (근거: docs/plan.md · ## 3. 아직 정할 것)

## 충돌
- 계약 만료 일정의 PRD 범위: plan.md 3절 질문 1은 "PRD FR-31은 1차 Should, IA SC_060000_PG는 2차"라고 적는다(근거: docs/plan.md · ## 3. 아직 정할 것), PRD 9절은 "2차 범위: Should(FR-28~32)"라서 FR-31도 2차다(근거: docs/PRD.md · ## 9. 출시 계획). PRD와 IA는 서로 같고 plan.md의 설명이 다르다. 고르지 않는다. spec 008의 "만료 2달 전 일정"과 이어지는 충돌은 [[기능-008 시세 변화 사건]]에 있다.
- 위키 표: plan.md 조각 A는 출처 문서에 "ERD wiki_chunks·chat_logs"를 적는다(근거: docs/plan.md · ## 1. 분배), spec 010 Q3은 "wiki_chunks는 미룸, 배포 묶음의 위키 파일을 바로 읽음"으로 정했다(근거: docs/specs/010-위키-챗봇/spec.md · Q3). 고르지 않는다. 조각 A 담당이 plan.md 칸을 고칠지 정한다.
- 작업 브랜치: Intent 4절의 "`Yelim` 브랜치 하나, PR #1"과 다르다. [[팀-작업 의도와 열린 질문]]의 충돌 절에 둘 다 있다.
