# 연결 지도

PRD 요구(FR)마다 어느 문서에서 왔고 어디로 이어졌는지 보는 표다(spec 012 FR-006, 평가항목 P3-20).
칸에는 문서 ID를 적고, 이어진 것이 없으면 "없음"이라고 쓴다. "없음"이나 "뼈대만"이 많은 줄이 아직 덜 만든 요구다.

칸을 채운 방법(2026-11-18, 넣기 묶음 4):
- 화면(IA)·여정(UJ): PRD 7절 표의 "관련 화면 ID"와 "여정 출처" 칸 그대로.
- 데이터(ERD): ERD "화면별로 읽고 쓰는 표"와 엔터티 표의 PRD 출처에서 이 요구가 쓰는 표.
- 규칙(spec): 각 spec의 FR 제목·첫 줄에 달린 PRD 요구. spec 004는 화면 뼈대라 "(뼈대)"로 표시한다.
- 조각(plan): docs/plan.md의 조각 표. 기능 001~008은 0절 "Yelim → main 합치기"로 들어갔다.
- 작업 의도(Intent): Intent 6절 문서 지도의 해당 spec 행. spec 012는 아직 문서 지도에 없다.
- PR: git 기록의 PR 합치기 커밋(spec 012 Q7). 기능 001~008은 PR #4(`65ed611`, 2026-11-18)로 main에 합쳐졌다. spec 004 뼈대뿐인 요구는 "뼈대만"으로 적는다.
- QA: 해당 spec qa.md 머리말의 상태.

## 이 표에서 보이는 것
- FR-22 관리자 사건 현황은 spec 004의 화면 뼈대뿐이고, 이 요구를 직접 만든 기능 spec이 없다.
- FR-26 위키 챗봇은 spec 012가 진행 중이고 PR이 아직 없다(뼈대 화면만 PR #4).
- FR-20의 "관리자 수정 기록"은 spec 005가 읽기만 만들었고, 수정과 수정 기록 표(audit_logs)는 spec 010이 PR #11로 만들었다([[기능-005 관리자 시연과 기록 찾기]], [[기능-010 관리자 수정·비슷한 지난 알림·시세 채점]]). (근거: docs/specs/010-관리자수정-비슷한알림-시세채점/spec.md · FR-003)
- QA가 "사람 QA 대기"나 "사람 확인 대기"인 요구(spec 003·004·005)는 사람 확인이 남아 있다.
