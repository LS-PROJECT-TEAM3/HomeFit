# 기능-014 비밀번호 재설정

> 비밀번호를 잊은 회원이 로그인 화면에서 메일을 받아 새 비밀번호를 정하는 기능. Supabase Auth 기본 메일을 쓴다.

## 내용
- 상태: spec·plan 초안 v0.1(사용자 지시 2026-11-19, 질문은 추천안, 승인 전), qa "사람 QA 끝 (C 부분 통과 1·확인 못 함 1 남음)"(C 2/4, H 1/1, 2026-11-20). (근거: docs/specs/014-비밀번호-재설정/spec.md · 머리말) (근거: docs/specs/014-비밀번호-재설정/qa.md · 머리말)
- FR-001 로그인 화면 "비밀번호를 잊으셨나요?" → 이메일을 넣으면 재설정 링크 메일. 가입한 이메일인지와 상관없이 같은 안내(가입 여부를 드러내지 않음). (근거: docs/specs/014-비밀번호-재설정/spec.md · FR-001)
- FR-002 메일 링크 → 새 비밀번호 화면(MB_010301_PG). 8자 이상, 확인 칸과 같을 때만 바꾸고 홈으로. FR-003 만료·이미 쓴 링크는 다시 요청하라고 안내. (근거: docs/specs/014-비밀번호-재설정/spec.md · FR-002, FR-003)
- 경계: 이메일 모양 아니면 안 보냄, 요청이 잦아 막히면 "잠시 뒤", 링크 없이 새 비밀번호 화면을 열면 로그인으로, 이미 로그인했으면 홈으로. (근거: docs/specs/014-비밀번호-재설정/spec.md · 3-1. 경계·예외)
- 결정(추천안): 직접 메일 서버는 연결하지 않고 시연은 팀원 주소로(Q1), 돌아올 주소는 Supabase Redirect URLs에 localhost·운영 주소를 넣음(Q2, 설정 변경이라 승인 뒤), 다른 기기 로그인은 끊지 않음(Q3). (근거: docs/specs/014-비밀번호-재설정/spec.md · 6. 확인 필요 사항)
- QA 실패와 조치(PR #19 리뷰): 돌아갈 주소 검사가 제어 문자가 든 주소를 통과시킴 → 제어 문자면 홈으로, 메일 링크 주소를 요청 Origin 헤더로 만들던 것 → 고정 사이트 주소. (근거: docs/specs/014-비밀번호-재설정/qa.md · 3. 실패와 조치)
- 하지 않을 것: 직접 메일 서버·유료 메일, 문자·소셜 재설정, 로그인한 상태의 비밀번호 바꾸기, 메일 문구 바꾸기. (근거: docs/specs/014-비밀번호-재설정/spec.md · 하지 않을 것)
- 사람 QA H-1401 통과(2026-11-20, 운영 주소·실제 메일 계정): 메일이 바로 열리고 운영 주소로 열려 비밀번호가 바뀌고 로그인까지 됨. Site URL·Redirect URLs에 운영 주소가 이미 있었다. (근거: docs/specs/014-비밀번호-재설정/qa.md · H-1401)

## 충돌

- Claude QA C-1402(부분 통과), C-1404(확인 못 함: 로그인 상태라 로그아웃 화면을 열지 못함)가 남아 있다. (근거: docs/specs/014-비밀번호-재설정/qa.md · 머리말)
