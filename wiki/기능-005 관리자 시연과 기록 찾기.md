# 기능-005 관리자 시연과 기록 찾기

> 관리자 화면 뼈대에 실행·시뮬레이터·흐름 화면·채점·회원 보기를 붙이고, 사용자 기록 찾기를 만든 기능. 승인 없이 만든 초안이다.

## 내용
- 상태: spec·plan 초안 v0.1(사용자 지시로 승인 없이, 2026-11-18 밤), qa "사람 QA 대기"(C 통과 7·부분 통과 1, H 0/2). (근거: docs/specs/005-관리자-시연-기록찾기/spec.md · 머리말) (근거: docs/specs/005-관리자-시연-기록찾기/plan.md · 머리말) (근거: docs/specs/005-관리자-시연-기록찾기/qa.md · 머리말)
- 목적: 시연(CUJ-04)에서 가짜 자료로 수집 → 사건 → 흐름 → 채점을 끝까지 보여 주고, 사용자가 지난 처리 기록을 찾게 한다. (근거: docs/specs/005-관리자-시연-기록찾기/spec.md · 1. 해결하려는 문제)
- FR-001 출처마다 "지금 한 번 실행"과 연속 실패 수, FR-002 시뮬레이터 버튼(사건은 가상 계정에만), FR-003 흐름 화면(시작 상자 3종, 기록 없는 출처는 "아직 안 켜짐", 키 가림), FR-004 감지 채점(맞힌·놓친·잘못 울린 수, 파일 `eval/results.json`에도), FR-005 회원 보기(읽기만, 회원 ID 앞 8자만, 관리자 수정은 안 만듦), FR-006 기록 찾기(낱말로 찾고 출처 링크, 임베딩 안 씀). (근거: docs/specs/005-관리자-시연-기록찾기/spec.md · FR-001~FR-006)
- 채점 정답 묶음 18건의 결과: 맞힘 7, 놓침 0, 잘못 울림 0, 조용히 맞음 11. (근거: docs/specs/005-관리자-시연-기록찾기/qa.md · C-505)
- 성공 기준 SC-001: 시뮬레이터 결과 요약이 30초 안에 보인다. (근거: docs/specs/005-관리자-시연-기록찾기/spec.md · SC-001)
- 하지 않을 것: 새 DB 표·마이그레이션, 관리자 대신 승인, 위키 챗봇(FR-26), 채점 결과 DB 저장, 배포·커밋. (근거: docs/specs/005-관리자-시연-기록찾기/spec.md · 하지 않을 것, 5. 제외 범위)
- QA 확인 못 함: 일반 계정으로 관리자 동작을 직접 부르기(C-503, 시험 계정 비밀번호가 필요), 찾은 기록이 있는 화면과 AI 답(C-507 → H-502). (근거: docs/specs/005-관리자-시연-기록찾기/qa.md · C-503, C-507)

## 충돌
- FR-003 "시작 상자 3종"과 구현(출처 4종)이 다르다: flow.md는 시작 상자를 출처 4종으로 적고 spec 쪽을 맞추면 된다고 한다(근거: docs/flow.md · 6. 안내서 기준과 다른 점). 자세한 것은 [[화면-흐름 화면]] 충돌 절. 고르지 않는다.
- 관리자 수정 기록 표 이름: ERD·PRD는 `audit_logs`(담당자·시각·사유)(근거: docs/ERD.md · #### audit_logs) (근거: docs/PRD.md · ## 7. 기능 요구사항 FR-20), spec 005 Q1은 "새 표 admin_edits가 필요하다"(근거: docs/specs/005-관리자-시연-기록찾기/spec.md · Q1). 고르지 않는다. 그 뒤 spec 010(조각 B)이 ERD대로 `audit_logs`를 마이그레이션 0019로 만들었고, spec 005 Q1은 아직 `admin_edits`로 남아 있다(근거: docs/specs/010-관리자수정-비슷한알림-시세채점/plan.md · 1. 기술과 버전). 자세한 것은 [[기능-010 관리자 수정·비슷한 지난 알림·시세 채점]].
- 기록 찾기 임베딩: ERD knowledge_chunks.embedding 필수(근거: docs/ERD.md · #### knowledge_chunks) ↔ spec 005 FR-006 "임베딩은 쓰지 않는다"(근거: docs/specs/005-관리자-시연-기록찾기/spec.md · FR-006). 위키 챗봇의 wiki_chunks 결정(spec 012 Q3)과는 별개다. 고르지 않는다. 기록 찾기 담당이 정한다.

## 확인 필요
- FR-002·FR-003은 실거래가를 "아직 없음/안 켜짐"으로 적었는데 그 뒤 spec 008이 실거래가 묶음을 더했다. 005 문서는 고쳐지지 않았다. (근거: docs/specs/005-관리자-시연-기록찾기/spec.md · FR-002, FR-003) (근거: docs/specs/008-시세-변화-사건/spec.md · FR-007)
- 열린 질문 Q1(수정 기록 표, spec 010이 `audit_logs`로 만듦), Q2(위키 챗봇 시기), Q3(정답 묶음)과 사람 QA H-501·H-502가 남아 있다. plan 3단계는 시험과 코드를 함께 써서 실패를 먼저 보지 못했다. (근거: docs/specs/005-관리자-시연-기록찾기/spec.md · 6. 확인 필요 사항) (근거: docs/specs/005-관리자-시연-기록찾기/qa.md · 2. 사람 QA, 4. 변경 기록)
