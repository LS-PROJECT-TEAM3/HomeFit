# 기능-023 결정 되돌리기

> 공고의 팔로우·관심 없음을 "새 공고"로 되돌리고, 알림(사건)의 승인·거절을 "승인 대기"로 되돌린다. 승인 취소는 그 승인으로 만든 일정을 지우고, 처리 이력에는 취소를 새 줄로 남긴다. PRD v1.21 FR-16·FR-17·FR-38을 만든 기능이다.

## 내용
- 상태: spec 승인됨 v0.2(사용자 "추천대로 승인" 2026-11-23), plan 승인됨 v0.1(사용자 "승인" 2026-11-23: plan, 마이그레이션 0023), qa "완료"(C 12/12, H 2/2, 2026-11-23). (근거: docs/specs/023-결정-되돌리기/spec.md · 머리말) (근거: docs/specs/023-결정-되돌리기/plan.md · 머리말) (근거: docs/specs/023-결정-되돌리기/qa.md · 머리말)
- 출처: PR #47 "추가하면 좋은 것" 첫 줄과 사용자 "Start with undo". (근거: docs/specs/023-결정-되돌리기/spec.md · 변경 기록 v0.1)
- 문제: 공고 상세에서 팔로우와 관심 없음은 서로 바꿀 수 있지만 정하지 않은 "새 공고"로는 못 돌아가, 잘못 누른 팔로우를 풀려면 이유까지 골라 "관심 없음"으로 남겨야 했다. 승인한 알림은 되돌릴 수 없어 잘못 누른 승인이 내 일정에 할 일을 남기고, 사용자는 그 일정을 지울 수도 없었다. "본인이 승인한 대응만 일정에 저장"한다는 약속이 실수 하나로 깨진다. (근거: docs/specs/023-결정-되돌리기/spec.md · 1. 해결하려는 문제)
- FR-001 팔로우 중인 공고 상세에서 "팔로우 풀기", FR-002 관심 없음 공고 상세에서 "관심 없음 취소"(기존 "팔로우로 바꾸기"는 그대로). 둘 다 "새 공고"로 돌린다. FR-003 "새 공고"로 돌아가면 목록·홈이 정하지 않은 공고로 세고(홈 "정할 공고 N"), 다시 팔로우하기 전까지 변화는 알림을 만들지 않으며, 이미 생긴 알림·일정은 그대로 둔다. (근거: docs/specs/023-결정-되돌리기/spec.md · FR-001~FR-003) (근거: docs/PRD.md · FR-38 v1.21)
- FR-004 승인한 알림 상세의 "승인 취소"는 "이 승인으로 만든 일정과 체크한 내용이 지워집니다" 확인을 받은 뒤 알림을 "승인 대기"로 돌리고 그 승인으로 만든 일정 하나를 지운다. FR-005 취소는 처리 이력에 누가·언제를 새 줄로 남기고 앞의 승인 줄은 고치지 않는다. FR-006 다시 승인하면 처음 승인과 같다(일정 하나, 두 번 눌러도 하나). (근거: docs/specs/023-결정-되돌리기/spec.md · FR-004~FR-006) (근거: docs/PRD.md · FR-16 v1.21)
- FR-007 본인 공고 결정과 본인 알림에만 되돌리기, 관리자도 남의 것은 못 함, 로그인이 끝났으면 로그인 화면으로. FR-008 거절한 알림에도 "거절 취소"(승인 대기로, 이력 새 줄, 지울 일정 없음). (근거: docs/specs/023-결정-되돌리기/spec.md · FR-007, FR-008) (근거: docs/PRD.md · FR-17 v1.21)
- 경계 E1~E7: 이미 "새 공고"인 것을 다시 풀면 오류 없이 "새 공고"(E1), 이미 승인 대기인 알림의 승인 취소는 아무것도 지우지 않고 "이미 승인 대기입니다"(E2), 승인한 적 없는 알림의 승인 취소는 거절(E3), 공고 상세 버튼으로 직접 넣은 일정은 팔로우를 풀어도 그대로(E4, spec에 "가정" 표시), 저장 실패면 화면 상태 그대로 + 안내(E5), 풀고 다시 팔로우하면 결정 시각이 새로 정해짐(E6), 승인 취소한 알림은 "처리 기록"에서 빠졌다가 다시 승인·거절하면 돌아옴(E7). (근거: docs/specs/023-결정-되돌리기/spec.md · 경계·예외 상황 E1~E7)
- 결정 Q1~Q3(2026-11-23, 추천대로): 거절 취소를 넣는다(Q1, FR-008), 승인 취소 때 일정을 지우고 확인 창에서 미리 알린다(Q2), PRD v1.21·ERD v1.13을 먼저 고친다(Q3). Q1은 Intent의 열린 질문 Q5("거절한 사건을 다시 승인할 수 있나")와 같은 질문이고, Intent v0.4 변경 기록이 "Q5 해결"로 적었다. (근거: docs/specs/023-결정-되돌리기/spec.md · 6. 확인 필요 사항) (근거: docs/Intent.md · 변경 기록 v0.4 결정 되돌리기)
- 하지 않을 것: 목록에서 여러 공고 한꺼번에 되돌리기, 공고 상세 "내 일정에 추가"로 넣은 일정 지우기, 되돌렸다는 슬랙·웹 푸시 알림, 관리자가 남의 것을 대신 되돌리기, 처리 이력 줄 지우기·고치기. (근거: docs/specs/023-결정-되돌리기/spec.md · 5. 제외 범위)
- 기술: 새 라이브러리 없음. 마이그레이션 0023(`0023_undo_decisions.sql`) 하나로 notice_follows 본인 지우기 권한, 처리 종류 `cancel_approve`·`cancel_reject`, DB 함수 `cancel_approval`·`cancel_rejection`. 두 함수는 사건을 잠그고 이력·일정·상태를 한 번에 바꾸며(security definer, anon 실행 막음), 상태가 맞지 않으면 `incident_not_approved`·`incident_not_rejected` 오류. 거절 상태에서 바로 승인은 지금처럼 막고 거절 취소 뒤에 승인한다. 거절 사유는 세 곳(알림 상세·처리 기록·기록 찾기 자료)이 순수 함수 `latestRejectReason`으로 마지막 거절 줄을 읽는다. (근거: docs/specs/023-결정-되돌리기/plan.md · 1. 기술과 버전, 2. 구조와 파일)
- DB(ERD v1.13): notice_follows는 "내 행 읽기·쓰기·지우기(지우면 새 공고)", incident_actions.action에 `cancel_approve`·`cancel_reject`(취소도 새 줄), schedule_items는 승인 취소 때 그 일정을 지움. (근거: docs/ERD.md · #### incident_actions, ## 접근 규칙, 변경 기록 v1.13)
- 단계 1~4(모두 체크): 1 `latestRejectReason` 시험 먼저와 세 곳 연결 → 2 0023을 공유 Supabase에 적용하고 되돌림 SQL 검사 → 3 공고 되돌리기 버튼 → 4 알림 되돌리기(`undo-panel`, 확인 창). (근거: docs/specs/023-결정-되돌리기/plan.md · 3. 단계별 접근)
- Claude QA: C-2301~2312 모두 통과. C-2303~2307은 공유 DB에서 시뮬레이터 사건으로 되돌림 SQL(승인→취소에 일정 1→0·이력 [approve, cancel_approve], 취소 뒤 두 번 승인에 일정 1개, 거절 취소 뒤 승인, 남의 사건·anon 막힘). C-2308 advisors 새 종류 경고 없음(기존 승인 함수와 같은 WARN). C-2312 전체 시험 782개·tsc·lint·build 통과, 공고 상세로 넣은 일정은 `response_plan_id`가 비어 지워지지 않음. C-2302·C-2311은 부분 통과였다가 재확인으로 통과. (근거: docs/specs/023-결정-되돌리기/qa.md · 1. Claude QA)
- 사람 QA: H-2301(팔로우 풀기·관심 없음 취소, 홈 "정할 공고" 수)과 H-2302(승인 취소 → 일정 사라짐 → 다시 승인 하나, 거절 취소) 모두 통과(사용자 "세 개 통과", 2026-11-23). (근거: docs/specs/023-결정-되돌리기/qa.md · 2. 사람 QA)
- 실패와 조치 5건: 팔로우 풀기가 아이콘뿐이라 휴대폰에서 찾기 어려움 → 안내 줄 + "팔로우 풀기" 글자 버튼(#1), 로그인이 끝났을 때 로그인 화면으로 보내지 않음 → `redirect("/login")`(#2), 오류 문구가 두 번 읽힐 수 있음 → alert 뺌(#3), 확인 창을 다시 열면 지난 오류가 남음 → 열 때 비움(#4), 취소 성공 뒤 키보드 초점이 페이지 맨 앞으로 감 → spec 밖이라 남김(#5). (근거: docs/specs/023-결정-되돌리기/qa.md · 3. 실패와 조치)
