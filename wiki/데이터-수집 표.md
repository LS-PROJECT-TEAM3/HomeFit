# 데이터-수집 표

> 바깥 자료를 모으고 실행 기록을 남기는 표 5개.

## 내용
- sources(수집 출처): code, name, schedule(간격 설명, 실제 예약은 정기 실행 설정), enabled. (근거: docs/ERD.md · #### sources)
- runs(실행 기록): source_code, trigger(`scheduled`/`manual`/`simulation` = 시작 상자 3종), triggered_by, status(`running`/`succeeded`/`failed`, 실패는 "수집 오류"), error_message(키·토큰 가린 뒤 저장), started_at, finished_at. 연속 실패 수는 저장하지 않고 계산한다. (근거: docs/ERD.md · #### runs)
- run_steps(실행 단계): step_order, step_name(`collect` → `compare` → `detect` → `draft_plan` → `notify` → `await_approval` → `record`), status(`succeeded`/`failed`/`waiting`/`skipped`, waiting은 승인 대기), items_in, items_out, detail(키 가림). 흐름 화면이 이것으로 그린다. (근거: docs/ERD.md · #### run_steps)
- source_items(공고·정책 한 건): external_id((source_code, external_id) 유일 → 중복 방지), title, 지역, supply_type, monthly_rent, announced_at(대표 KPI 시작점), apply_start·apply_end, url, content_hash, complex_key(마이홈 `hsmpNm` + 시군구), status_name(`sttusNm`), before_external_id(`beforePblancId`), previous_values(전 → 후), raw, first_seen_at·last_seen_at. (근거: docs/ERD.md · #### source_items)
- observations(모은 값, 같은 모양): run_id, source_code, observed_at, target, metric, value_numeric·value_text, change_amount, source_item_id, raw, is_simulated(시뮬레이터 자료 표시). (근거: docs/ERD.md · #### observations)

## 충돌
- 실거래가 출처 코드: ERD sources 표는 `molit_rent_apartment`, `molit_rent_officetel`, `molit_rent_row_house`, `molit_rent_detached` 네 개를 적는다(근거: docs/ERD.md · #### sources), ERD 변경 기록 v1.8은 "sources `rtms_trade`"를 적는다(근거: docs/ERD.md · ## 변경 기록 2026-11-18 v1.8). 같은 문서 안에서 다르다. 고르지 않는다. spec 008 plan은 마이그레이션 0017에서 `rtms_trade` 출처 하나를 쓴다고 적어 변경 기록 쪽과 같다(근거: docs/specs/008-시세-변화-사건/plan.md · 1. 기술과 버전). ERD 표를 고칠지는 팀이 정한다.
