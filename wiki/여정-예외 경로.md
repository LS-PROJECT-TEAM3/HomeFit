# 여정-예외 경로

> 세 사건 종류 모두에 적용하는 실패·복구 기준 E1~E5. 각 기능 spec이 이 문서를 출처로 쓴다.

## 내용
- E1 대응안 거절(IC_020102_MD): 사유 입력 필수(예: "자격이 안 됨", "이미 처리함", "필요 없음"). 사유·사람·시각을 기록하고 내 일정과 다른 값은 바꾸지 않으며 상태를 "거절"로 바꾼다(P3-04). 다시 승인할 수 있는지는 spec에서 정한다. (근거: docs/journeys/edge-cases/거절과-수집오류.md · ## E1)
- E2 수집 오류: API 실패, 시간 초과, 응답 형식 다름, 호출 한도 초과. 목록 위에 "(출처)에서 자료를 불러오지 못했습니다"("새 사건 없음"과 다른 문구). 실행 기록에 실패와 오류 메시지(키 가림)를 남기고 "변화 없음"으로 기록하지 않는다. 관리자 수집 현황에 실패와 연속 실패 수. 복구는 다음 정기 수집이나 "지금 한 번 실행". (근거: docs/journeys/edge-cases/거절과-수집오류.md · ## E2)
- E3 입력이 비어 사건이 생길 수 없음: 공고·정책 조건 없음 → 홈 맨 위 "조건을 입력해 주세요", 내 집·최근 측정값 없음 → "실내 온습도를 입력해 주세요", 계약 금액·형태 없음 → 내 집 탭 안내, 관심 지역 없음 → 관심 지역 탭 안내. (근거: docs/journeys/edge-cases/거절과-수집오류.md · ## E3)
- E4 권한 없는 접근: 일반 사용자가 `/admin`이나 관리자 API를 부르거나 남의 사건 ID로 접근하면 "볼 수 없는 페이지입니다"와 홈 링크, 자료는 한 줄도 안 보임. 화면·서버·DB 세 곳에서 확인(P3-14). (근거: docs/journeys/edge-cases/거절과-수집오류.md · ## E4)
- E5 관리자가 대신 승인하려 함: 관리자 화면에는 승인 버튼이 없다. 관리자 수정은 사유를 받고 기록하지만 승인 단계를 건너뛰지 못한다(P3-13). (근거: docs/journeys/edge-cases/거절과-수집오류.md · ## E5)
