# 위키 점검

## 순서
1. `node scripts/wiki-lint.mjs`를 돌린다. 결과 표와 종료 코드를 그대로 보여 준다.
2. 도구가 못 보는 것을 눈으로 본다. 많아도 세 개까지만.
   - 근거 문장과 원본 내용이 실제로 맞는가(원본 줄을 열어 대조)
   - 오래된 사실(원본이 바뀌었는데 쪽은 그대로)
   - 같은 일을 두 쪽이 다르게 말하는데 `## 충돌`이 없는 곳
3. 두 결과를 한 표로 합친다. 열: `# / 종류 / 쪽 / 문제 / 제안`.
4. "몇 번을 고칠까요?"라고 묻고 멈춘다.
5. 사람이 번호를 고르면 그 번호만 고치고, `wiki/log.md`에 한 줄 덧붙이고, 다시 `node scripts/wiki-lint.mjs`를 돌린다.

## 원본 바뀜·새 원본이 나오면
원본은 고치지 않는다. 되돌리거나 지문을 다시 기록하지 말고, 바뀐 원본을 넣을지(wiki-ingest) 사람에게 묻는다. 팀원이 고친 원본이면 `git log -1 -- <경로>`로 누가 언제 왜 바꿨는지 함께 보여 준다.

## 하지 않을 것
- 표를 보여 주기 전에 고치기
- 점검을 통과시키려고 링크나 sources를 지우기
- 승인 없이 `--record` 돌리기
- docs/·interviews/ 파일 고치기
