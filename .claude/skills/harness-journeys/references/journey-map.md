## 1. 정의와 쓰임

제품·서비스를 이용하는 **전 과정**에서 고객이 겪는 요소를 고객 입장에서 하나씩 짚고 분석·정리한 자료. 이용 전·중·후를 모두 다루고, 행동뿐 아니라 동기·감정·페인포인트·여러 채널의 터치포인트를 담는다. 마찰과 감동 지점, 감정의 높낮이를 찾는 것이 목적이다.

CUJ와의 차이: CUJ는 핵심 과업 하나를 좁고 깊게, 여정 지도는 전체 경험을 넓게 본다. 여정 지도에서 가장 아픈 구간을 찾은 뒤 그 구간을 CUJ로 파고드는 식으로 함께 쓴다.

## 2. 작성 원칙

**핵심 기능만 보지 않는다.** 서비스의 진짜 차이는 핵심 기능 앞뒤에서 자주 드러난다. 예를 들어 차량 경험을 분석한다면 운전 중만이 아니라 탑승 전 준비, 탑승, 충전·주차, 하차까지 본다. 앱이라면 알게 되는 순간, 설치·가입, 첫 사용, 반복 사용, 문제 해결, 이탈/재방문까지.

**단계는 5~7개로 나눈다.** 너무 적으면 통찰이 없고, 너무 많으면 화면 목록이 된다. 단계 이름은 사용자 관점의 행동으로 짓는다 ("결제 모듈" X → "결제하기" O).

**As-Is와 비교한다.** 단계마다 기존 방식(경쟁 서비스, 아날로그 방식, 개선 전 버전)에서의 행동과 불편을 함께 적는다. 비교가 있어야 "무엇이 새로운 경험인지"가 분명해진다.

**터치포인트와 상호작용 주체를 적는다.** 사용자가 어떤 접점(앱, 웹, 기기 화면, 오프라인 매장, 알림, 상담원)으로 만나는지, 그리고 누가 먼저 움직이는지 본다. 시스템이 먼저 제안하고 사용자는 승인만 하는 구간(예: 경로·기능 자동 제안)은 경험이 크게 달라지는 지점이므로 따로 표시한다.

**실제 사용에 근거한다.** 가능하면 실제 시나리오(구체적 날짜·장소·목적이 있는 하루)로 처음부터 끝까지 써보고 기록한다. 여러 명이 각자 써보면 페르소나별 차이가 드러난다.

**감정은 근거와 함께.** 감정 점수(-2 매우 부정 ~ +2 매우 긍정)에는 그 순간의 생각 한 줄("…해서 불안했다")을 붙인다. 감정 곡선이 가장 낮은 곳이 개선 1순위, 가장 높은 곳이 지켜야 할 강점이다.

## 3. 인터뷰 질문 (추천 답과 함께)
- 누구의 여정인가? 페르소나 1~3명 (기본: 주 사용자 1명으로 시작)
- 어떤 구체적 시나리오인가? (언제, 어디서, 왜 이 서비스를 쓰는가)
- 여정의 시작과 끝은? (기본: 필요를 느끼는 순간 ~ 다음 이용 의향이 생기는 순간)
- 비교 대상(As-Is)은? 경쟁 서비스 / 기존 방식 / 이전 버전
- 근거는? 직접 사용 / 인터뷰 / 리뷰 / 데이터 / 가설
- 결과물 용도는? 팀 공유 / 포트폴리오 / 개선 과제 도출

## 4. 템플릿

```markdown
# 고객 여정 지도: [서비스명] — [페르소나명]

## 개요
| 항목 | 내용 |
|---|---|
| 페르소나 | [이름, 한 줄 설명] |
| 시나리오 | [언제, 어디서, 무엇을 하려고] |
| 여정 범위 | [시작] → [끝] |
| 비교 대상 (As-Is) | [기존 방식/경쟁 서비스] |
| 근거 | 직접 사용 / 인터뷰 n명 / 리뷰 n건 / 데이터 / 가설 |

## 사용자 목표
> "[상황]일 때, 나는 [하고 싶은 것]을 하고 싶다. 그래서 [얻고 싶은 결과]를 얻고 싶다."

## 여정 지도
| | 1. [단계] | 2. [단계] | 3. [단계] | 4. [단계] | 5. [단계] |
|---|---|---|---|---|---|
| **행동 (To-Be)** | | | | | |
| **터치포인트** | | | | | |
| **상호작용 주체** | 사용자 / 시스템 제안 | | | | |
| **생각·감정 (점수)** | "…" (+1) | | | | |
| **As-Is 행동·불편** | | | | | |
| **페인포인트** | | | | | |
| **기회 (개선 아이디어)** | | | | | |

## 감정 곡선
(HTML 여정 지도로 시각화. 표만 쓸 땐 단계별 점수를 한 줄로: 1단계 +1 → 2단계 -1 → …)

## 핵심 발견
1. 가장 큰 감동 지점: [단계] — 이유
2. 가장 큰 불편 지점: [단계] — 이유 → CUJ 후보
3. As-Is 대비 가장 달라진 점: …

## 개선 과제 (우선순위)
```

## 5. 페르소나 & 경험 리뷰

페르소나별로 여정 지도를 따로 만들거나, 한 지도에 페르소나별 감정 곡선을 겹친다. 페르소나 카드에는 다음만 간결히:

```markdown
### [이름] — [한 줄 정의, 예: 주말마다 장거리 이동하는 30대 직장인]
- 이용 맥락: 언제, 얼마나 자주, 무엇 때문에
- 기대: 이 서비스에서 바라는 것
- 걱정·불만: 기존 방식에서 싫었던 것
- 경험 리뷰: 실제로 써본 뒤의 총평 2~3줄 (좋았던 점 / 아쉬운 점)
```

## 6. 사례에서 배울 점
- **차량 경험 분석 (예: 소프트웨어 중심 차량)**: 운전 기능만이 아니라 탑승 전 원격 준비, 스마트폰 인식 자동 잠금 해제, 충전 경로 자동 제안, 자동 주차, 하차 시 자동 잠금까지 6단계로 나눠 기존 차량과 비교하면 "이동 경험"이 어떻게 바뀌는지가 드러난다. 시스템이 먼저 제안하고 사용자는 승인만 하는 순간들이 감동 지점이었다.
- **디즈니**: 여행 계획부터 귀가까지 전 과정을 보니 결정할 것과 챙길 것이 너무 많아 지친다는 점이 보였고, 출입·결제·예약을 하나로 묶는 웨어러블로 이어졌다. 범위를 넓게 볼수록 혁신 여지가 커진다.
- **에미레이트 항공**: 예약~사후 관리까지 보면서 "통제감을 느끼고 싶다", "변경 사항에 안심하고 싶다" 같은 감정 터치포인트를 기록해 실시간 수하물 추적 등으로 연결했다.
- **텔러스(통신사)**: 온라인·전화·매장에서 안내가 달라 혼란스러운 지점을 찾아 메시지를 통일했다. 채널이 여러 개라면 채널 간 일관성을 꼭 본다.
