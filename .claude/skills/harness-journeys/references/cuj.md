## 1. 정의

사용자가 제품의 **핵심 과업**을 완료하는 경로. 이것이 실패하면 사용자에게는 제품 전체가 망가진 것처럼 느껴진다. 구글 UX 팀에서 발전시킨 방법으로, "모든 것"이 아니라 "가장 중요한 것"에 집중하게 만든다.

| | CUJ | 고객 여정 지도 |
|---|---|---|
| 초점 | 핵심 과업 하나 | 이용 전·중·후 전체 |
| 목적 | 성공/이탈이 갈리는 순간 확보 | 마찰·감동·감정 기복 파악 |
| 범위 | 좁다 | 넓다 |
| 결과물 | 단계별 과업 흐름 + 지표 | 타임라인·페르소나·채널·감정 지도 |
| 주 사용자 | PM, 엔지니어, 디자이너 | UX 리서처, 서비스 디자이너 |

## 2. 3요소

**사용자**: 막연한 "고객"이 아니라 특정 세그먼트/페르소나. 해결하려는 문제, 기대, 불만·만족 요인을 함께 적는다. 같은 목표라도 신규와 재방문 사용자는 다르게 움직이므로 필요하면 나눈다.

**목표 (JTBD)**: 기능이 아니라 사용자의 의도로 쓴다.
> "[상황]일 때, 나는 [동기]하고 싶다. 그래서 [결과]할 수 있다."
> 예: "비밀번호를 잊어버렸을 때, 1분 안에 재설정하고 싶다. 그래서 짜증 없이 바로 일로 돌아갈 수 있다."
한 CUJ에는 JTBD 하나만. 여러 목표를 섞으면 누구의 문제도 풀지 못한다. "앱을 쓴다" 같은 모호한 목표는 금지 — 사용자에게 성공이 무엇인지로 쓴다.

**과업**: 목표 달성에 꼭 필요한 최소 행동만 (로그인, 검색, 폼 입력, 결제 확인 등). 목표를 직접 돕지 않는 과업은 넣지 않는다.

## 3. 3가지 유형과 선정 규칙

| 유형 | 무엇 | 찾는 법 | 언제 우선 |
|---|---|---|---|
| **High-Traffic** | 많은 사용자가 자주 거치는 흐름 (가입, 로그인, 탐색) | 분석 도구에서 가장 많이 완료되는 과업 | 초기·성장 단계, 도입·리텐션·접근성 개선이 목표일 때. 작은 마찰도 규모가 커지면 대량 이탈 |
| **High-Dollar** | 매출에 직결되는 흐름 (결제, 업그레이드, 예약 확정) | 매출 발생 흐름 추적, 고가치 사용자 경로 | 수익 모델이 분명할 때(SaaS, 커머스, 마켓플레이스), ROI 압박이 있을 때 |
| **OEC 기반** | 팀의 핵심 성공 지표(OEC, North Star)를 움직이는 흐름 | 핵심 지표를 먼저 정하고, 그 지표에 영향을 주는 여정을 역추적 | 성숙한 제품, OKR/KPI가 명확할 때, 부서 간 정렬이 필요할 때 |

**선정 규칙**
- 제품당 **3~5개**. 구글도 초기에 관리 불가능할 만큼 많은 CUJ 목록을 만들었다가 실패했다. 대부분의 사용자에겐 핵심 목표가 몇 개뿐이다.
- 가정이 아니라 데이터 기준(예: 전체 세션의 n% 이상, 매출의 n% 이상)으로 critical을 정한다. 데이터가 없으면 가설로 표시.
- 가장 몰입한 사용자(파워 유저)가 의존하는 여정을 참고한다.

**CUJ가 특히 필요한 때**: 성숙한 제품의 전환·참여가 떨어질 때 / 신규 제품·기능 출시 전 / 리디자인 때 / 팀 간 무엇이 중요한지 합의가 안 될 때.

## 4. 작성 7단계
1. **목표 정의**: 구체적이고 결과 중심으로. 성공의 모습을 한 문장으로.
2. **핵심 사용자 식별**: 이 목표를 실제로 시도하는 사람 (신규/재방문/특정 세그먼트).
3. **핵심 터치포인트 매핑**: 목표 달성에 직접 영향을 주는 상호작용만.
4. **사용자 인사이트 수집**: 분석 데이터·설문·고객 문의·인터뷰·사용성 테스트. 정량(무엇)과 정성(왜)을 섞는다. 예: 결제 페이지 이탈이 크다(정량) → 인터뷰로 결제 수단 부족 때문인지 UI 혼란 때문인지 확인(정성).
5. **MOT(Moment of Truth)와 주요 페인포인트 표시**: 성공/실패가 갈리는 결정적 상호작용. 예: 폼 제출 후 확인을 기다리는 순간, 결제 중 느린 로딩. 개선 효과가 가장 큰 곳이다.
6. **감정 레이어 추가**: 핵심 단계마다 감정을 기록. 과업을 끝냈더라도 헷갈리거나 답답했다면 개선할 곳이다. 이모지·감정 단어·색으로 칠한 감정 곡선 중 하나로 표시해 좌절·감동·혼란 구간이 한눈에 보이게 한다.
7. **이해관계자 검증**: PM·디자이너·개발자, 가능하면 영업·CS와 공유해 빠진 점을 찾는다.

## 5. 품질을 높이는 방법

**과업 → 감정 → 인사이트 3줄 기록**
```
과업: 카드 정보 입력 후 "결제하기" 클릭
감정: 불안 (-2) — "로딩이 너무 길다… 결제된 건가?"
인사이트: 로딩 중 피드백이 없어 중복 결제를 걱정함 → 진행 상태 표시 필요
```

**핵심만 남기는 질문**: "이 단계가 실패해도 사용자가 목표에 도달하는가?" → 도달한다면 critical이 아니다. 핵심 터치포인트는 **4~6개**. 예: 구매 CUJ라면 상품 상세(결정 지점), 장바구니 담기, 장바구니 확인, 결제 정보 입력, 주문 완료는 넣고 FAQ·블로그·계정 설정은 뺀다.

**터치포인트마다 지표 1개 이상**: 행동 지표(클릭률, 전환율, 이탈률, 완료율, 소요 시간)와 태도 지표(NPS, CES 고객 노력 점수, 만족도)를 섞는다.

**함께 만든다**: 디자이너·PM·엔지니어·CS가 각자 보는 사용자의 현실이 다르다. 1인 프로젝트라면 최소한 실제 사용자 2~3명에게 보여주고 확인한다.

## 6. 템플릿

```markdown
# CUJ: [이름]

## 개요
| 항목 | 내용 |
|---|---|
| 유형 | High-Traffic / High-Dollar / OEC 기반 |
| 선정 근거 | [데이터 또는 가설] |
| 핵심 사용자 | [세그먼트/페르소나] |
| OEC/핵심 지표 | [예: 첫 예약 완료율] |

## 목표 (JTBD)
> "[상황]일 때, 나는 [동기]하고 싶다. 그래서 [결과]할 수 있다."

## 핵심 터치포인트 (4~6개)
| # | 과업 | 화면 ID | 감정 (점수) | 생각 | 인사이트 | MOT | 지표 (행동/태도) | 목표치 |
|---|---|---|---|---|---|---|---|---|
| 1 | | | | | | | | |

## Moment of Truth
- [MOT 단계]: 왜 결정적인가, 실패하면 어떻게 되는가

## 제외한 터치포인트와 이유
- [단계]: 실패해도 목표 달성 가능

## 페인포인트 → 개선안
| 페인포인트 | 근거 | 개선안 | 기대 지표 변화 |
|---|---|---|---|

## 검증
- 검증 대상/방법: [이해관계자 리뷰, 사용성 테스트 n명]
- 다음 단계: 모드 C 여정 명세로 구체화 → `critical/[이름].md`
```

## 7. 사례
- **스포티파이 – 친구에게 곡 공유**: 곡을 듣고 마음에 드는 순간부터 공유 결정, 채널 선택, 받는 사람 반응까지 매핑. 공유 버튼을 찾기 어려워 중간에 포기하는 것을 발견하고 공유 옵션 노출과 미리보기로 개선. 작은 여정도 바이럴·성장을 좌우할 수 있다.
- **우버 – 호출 후 픽업 대기**: 과업과 함께 기대·초조함 같은 감정을 추적해, 기사가 늦거나 픽업 위치가 불명확할 때 불안이 커진다는 것을 발견. 실시간 위치·도착 예정 시간·소통 기능으로 체감 대기 스트레스를 줄였다. 시간이 걸리거나 불확실한 서비스일수록 감정을 꼭 기록한다.
- **여러 채널·부서에 걸친 여정 (텔러스, 디즈니, 에미레이트)**: 온라인·전화·매장처럼 접점이 여러 곳이면 CUJ로 그려야 채널마다 안내가 다르거나 사용자가 같은 말을 반복해야 하는 지점이 드러난다. 따로 일하는 팀 안에서는 보이지 않는 문제다. 디지털 화면 밖의 물리적 단계까지 범위를 넓히면 더 큰 개선(예: 출입·결제·예약을 하나로 묶은 디즈니의 웨어러블)으로 이어질 수 있다.
