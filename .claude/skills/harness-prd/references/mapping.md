# IA·사용자 여정 → PRD 변환 규칙

## 목차
1. 한눈에 보는 대응표
2. 사용자 여정 → PRD
3. IA → PRD
4. 충돌이 생길 때

---

## 1. 한눈에 보는 대응표

| 앞 단계 산출물 | PRD 위치 | 변환 방법 |
|---|---|---|
| 여정 페인포인트, 감정 최저점(-1, -2) | 2. 배경과 문제 | 가장 낮은 1~3개를 문제로. 근거 표시(직접 사용/데이터/가설) 유지 |
| 여정 As-Is 행동·불편 | 2. 배경, 5. 이전(What before) | 지금의 해결 방법과 불편 |
| 비교 대상(as_is_label) | 5. 대안(Alternatives) | 우리가 없으면 쓸 것, 그래도 우리를 고를 이유 |
| 페르소나 | 4. 핵심 사용자 | 인구통계를 빼고 문제·Job으로 다시 쓴다 |
| JTBD 목표 문장 | 5. 왜(Why), 6. 사용자 스토리 | Why에는 Job과 막는 문제, 스토리는 "(유형)인 나는 (목적)을 위해 (필요)를 원한다" |
| CUJ 유형·OEC | 3. 목표와 성공 지표 | OEC가 대표 KPI. High-Dollar면 매출 지표, High-Traffic이면 전환·완료율 |
| 터치포인트 지표 | 3. KPI(대표 1~3개) / 7. 수용 기준(나머지) | 대표만 KPI로, 나머지는 해당 FR의 수용 기준이나 측정 이벤트로 |
| CUJ 단계 + 화면 ID | 6. CUJ 시나리오 | 단계 순서 그대로, 화면 ID 붙임. CUJ ID(CUJ-01) 유지 |
| MOT | 6. MOT 표시, 7. Must 요구사항 | 모든 MOT는 Must 요구사항 1개 이상 + 그 MOT의 실패를 막는 수용 기준 |
| 기회(개선 아이디어) | 7. 요구사항 후보 | MoSCoW로 분류. 첫 버전 검증과 무관하면 Could/Won't |
| 인사이트 | 7. 요구사항의 근거, 8. 결정 | "왜 이 요구사항인가"의 한 줄 근거 |
| 여정 명세 성공 기준 | 7. 수용 기준 | "페이지 2초 이내" 같은 검증 가능한 문장 그대로 |
| 여정 명세 에러 시나리오·복구 경로 | 7. 요구사항(복구) 또는 수용 기준 | CUJ의 에러 복구는 Must에 포함. 해피 패스만 요구사항으로 만들지 않는다 |
| 근거가 "가설"인 감정·수치 | 8. 가정과 미결 질문 | 확인 방법·담당 한 줄씩 |
| 처리하지 않는 페인포인트 | 9. 이후 범위 / 하지 않을 것 | 이유와 함께 명시 |

## 2. 사용자 여정 → PRD

**어떤 여정 문서를 쓰나**
- 고객 여정 지도: 문제 발견용. 2번(배경)·4번(사용자)·5번(가치 제안)의 근거.
- CUJ: 범위 결정용. 6번과 7번의 뼈대. PRD의 CUJ는 1~3개로, 여정 스킬의 CUJ(3~5개) 중 이번 버전 KPI와 직접 연결되는 것만 고른다.
- 여정 명세: 수용 기준용. 7번의 세부 기준과 에러 복구.
- 여정 지도만 있고 CUJ가 없으면, 감정 최저점이나 MOT 구간을 CUJ 후보로 제안하고 사용자 확인 후 6번을 쓴다.

**페인포인트 처리 원칙**
여정의 페인포인트 하나하나는 PRD에서 셋 중 하나가 되어야 한다:
1. 요구사항(FR)이 해결한다 → FR의 `여정 출처` 열에 단계/CUJ를 적는다.
2. 이번엔 하지 않는다 → 9번 "하지 않을 것" 또는 "이후 범위"에 이유와 함께.
3. 원인이 불확실하다 → 8번 가정으로, 검증 방법과 함께.

**감정 점수는 우선순위의 힌트지 결정이 아니다.** 감정이 가장 낮은 곳이 매출·핵심 가치와 무관할 수 있다. 3번 KPI와 연결되는지로 최종 판단한다.

## 3. IA → PRD

- **유저 플로우 → CUJ**: 여정 문서가 없을 때만 IA 유저 플로우에서 CUJ를 고른다. 여정 문서가 있으면 그쪽이 우선이고, IA는 화면 ID 확인용.
- **화면 → 요구사항**: 화면 하나가 요구사항 하나가 아니다. 사용자가 할 수 있어야 하는 일 단위로 쓰고, 관련 화면 ID를 여러 개 붙일 수 있다.
- **우선순위 대응**: IA `MVP` 화면에는 Must/Should 요구사항이 최소 하나, `보류`·`삭제` 화면은 Won't에만.
- **개발 구분 `외부연동`** → 8번 종속성에 기록.
- **용어**: IA 용어 정의 표의 UI 표기를 그대로 쓴다.

## 4. 충돌이 생길 때

- 여정의 MOT 화면이 IA에서 `2차`·`보류` → 범위 충돌. IA 우선순위를 올릴지, 그 MOT를 이번 CUJ에서 뺄지 사용자에게 묻는다.
- 여정 화면 ID가 IA에 없음 → 여정 문서가 옛 IA 기준일 수 있다. 어느 쪽이 최신인지 확인.
- 여정과 IA의 용어가 다름 → IA 용어 정의를 기준으로 통일하고 여정 문서 수정을 제안.
고칠지 말지는 사용자가 정한다. 충돌을 PRD 안에서 조용히 덮지 않는다.
