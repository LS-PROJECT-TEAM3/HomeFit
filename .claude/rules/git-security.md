# Git·배포·보안·병렬 작업

## Git
- git이 없으면 `git init`과 `.gitignore`(`.env`, `node_modules/`, `_workspace/`, 운영체제 파일)를 제안한다.
- 브랜치는 `main` 하나로 쓴다. 크게 실험할 때만 브랜치를 제안한다.
- plan 단계가 끝날 때마다 커밋을 **제안**하고 승인 후 실행한다. 커밋 전에 시험을 돌리고, 통과한 상태로만 커밋한다.
- 메시지: `종류: 한국어 요약 (출처 ID)`. 종류는 `feat`, `fix`, `docs`, `refactor`, `test`만 쓴다. 예: `feat: 점검 도래 표 정렬 (spec 001 FR-004)`. 한 커밋에는 plan 단계 하나만 담는다.
- push, 강제 덮어쓰기, 이력 삭제는 사용자가 직접 말할 때만 한다.

## 배포
- 사용자가 "배포해줘"라고 직접 말할 때만 한다.
- 배포 전에 어디에, 누가 볼 수 있는지(공개/비공개), 비용을 보여 주고 승인을 받는다.

## 보안
- 비밀 키·토큰은 `.env`에만 두고, 코드·문서·대화에 값을 쓰지 않는다.
- 사용자가 입력한 글자를 화면에 그릴 때는 이스케이프한다.
- 실제 업무 데이터나 개인 정보는 시험 자료로 쓰지 않는다. 가짜 자료를 만든다.
- 외부 스킬·플러그인·패키지는 설치 전에 내용을 검토하고, 설치 스크립트를 그대로 실행하지 않는다.

## 서브에이전트와 병렬 작업
- 쓰는 때: 여러 파일·저장소를 넓게 훑어 결론만 필요한 조사, 웹 조사, 외부 스킬·코드 설치 전 검토, 서로 영향 없는 점검을 동시에 할 때.
- 쓰지 않는 때: 파일 하나 고치기, 위치를 아는 파일 읽기, 사용자 결정을 기다리는 일.
- 서로 독립된 조사·검토만 동시에 하고, 한 번에 5개 이하로 둔다.
- 코드 수정은 한 번에 하나. 같은 파일을 동시에 고치지 않는다.
- 서브에이전트 결과는 보고일 뿐이다. 파일·실행 결과로 확인한 뒤 사용자에게 전한다.
- 에이전트를 많이 띄우는 워크플로우나 별도 세션은 사용자가 요청할 때만 쓴다. 따로 갈 일이 보이면 제안만 한다.
